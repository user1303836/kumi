# Kumi の Logic Pro アダプター: M2, M3

- 元の Logic M2 リーダー用アプリ側アダプターです。`logic_read` でプロジェクト、トラック、リージョン、ノート、プラグイン、センド、マーカー、テンポを読み、FOCUS に Channel Strip、Piano Roll、Tracks、Routing を表示します。
- macOS の Logic Pro 12 が必要です。起動中の Logic に接続し、Logic 内へのインストールや再起動は不要です。ブリッジ、ビルド済みヘルパー、接続情報は `KUMI_HOME/bridges/logic/bridge/logic-kumi` に置きます。
- システム設定 → プライバシーとセキュリティ → アクセシビリティで、Kumi を実行するアプリを許可してください。セットアップは認証済みブリッジの権限状態を確認します。ダイアログや別デスクトップの状態は権限と区別します。
- 保存済みプロジェクトは、接続した Logic の Apple バンドル ID で開きます。プロジェクト、選択項目、録音状態を読み取ります。M3 では16種類の変更と3つのトランスポート操作、HISTORY と値を戻す取り消しに対応します。Logic に一括の取り消しブロックはなく、音量・パン・ミュート・ソロ・アーム・テンポ・バイパスは Logic 自身の取り消しに入りません。試聴、レンダリング、目標、スクリプト、変更の追跡は未対応です。ファイルからのライブラリ検索とマニュアル検索は利用できます。プリセットの読み込みとネイティブ Browser の操作は未対応です。
- リリースには `logic-kumi`、`kumi-logic-hands-*`、`version` を含めます。チェックアウトではネイティブブリッジとヘルパーを事前にビルドします。`KUMI_LOGIC_BRIDGE_SOURCE` で既存のリリース形式フォルダーを指定できます。セットアップはネイティブコードをビルドしません。
- 分離テストはローカルのフィクスチャとプロジェクトを開く処理の代役を使用し、実際の DAW や権限を必要としません。ネイティブの記録再生と実際の Logic／アプリでの確認は別の検証です。

実機の自動変更チェックは、使い捨てプロジェクトで `accept_logic --changes --scratch-confirmed` を使います。取り消しに失敗すると編集が残ります。記録の再生は新しい実機検証ではありません。

追加・削除したトラックと削除したマーカーは、Logic の取り消し履歴から手動で取り消します。Kumi はタイトルだけで特定した取り消しを実行しません。マーカーの追加・移動も、元の Text など必要な情報が不明だった場合は手動です。後で列を表示しても過去の値は復元できません。完全な行と一覧の情報がある場合だけ値で戻し、`discard` も不明な情報を無視しません。確認済みの手動取り消しが必要な変更は HISTORY に Kept として残り、標準の取り消しが以前の行を飛び越えて戻すことを防ぎます。不確かな変更は不確かなままです。マーカー・ノート・構造の変更を、タイトルだけから取り消し済みとは判定しません。
