# Kumi's Logic Pro adapter: M2, M3 and three M4 value previews

- The app adapter for the original Logic M2 reader. It reads project, track, region, note, plug-in, send, marker and tempo rows through `logic_read` and draws four FOCUS bodies: Channel Strip, Piano Roll, Tracks and Routing.
- Requires Logic Pro 12 on macOS. The bridge attaches to an open Logic; it installs nothing into Logic and requires no Logic restart. Its binary, built Accessibility helper and connection reference go in `KUMI_HOME/bridges/logic/bridge/logic-kumi`.
- Allow the app Kumi runs in under System Settings → Privacy & Security → Accessibility. Setup polls the authenticated bridge's permission status; dialogs and another desktop are reported separately.
- Saved projects open with the attached Logic's Apple bundle id. Kumi reports the saved project, the selected items and the recording state. M3 offers 16 change kinds and three transport actions, with HISTORY and by-value undo. Logic has no atomic undo block; its native undo skips volume, pan, mute, solo, arm, tempo and bypass. Listening, rendering, goals, scripts and catch-up remain disabled; offline library lookup and manual search are available; preset loading and native browser access remain unavailable.
- Release files carry `logic-kumi`, a `kumi-logic-hands-*` helper and `version`. A checkout builds the native bridge and helper explicitly. `KUMI_LOGIC_BRIDGE_SOURCE` may name an existing release-like folder; setup creates no native build.
- Isolated adapter/provider tests use local fixtures and stand-ins for project opening. They launch no real DAW and need no Accessibility grant. Recorded native replay and actual Logic/app acceptance are separate checks.

Native acceptance on a disposable project requires `accept_logic --changes --scratch-confirmed`; failed undo may leave edits. Recorded source evidence is not a current native acceptance result.

Added tracks, deleted tracks and deleted markers require manual Logic Undo History; Kumi never presses a native Undo step identified only by its title. Marker additions/moves also require manual undo if any captured original identity field (including Text) was unavailable; showing the field later cannot recover its old value. Complete known marker row/list identity permits value restores, and discard never overrides unknown identity. Confirmed manual-only changes stay Kept in HISTORY and block default Undo from skipping to an earlier change; uncertain deletions remain uncertain. Native marker, note and structural undo attribution is not inferred from titles alone.

The first M4 preview added `loop_range` (17 kinds before the Region value previews below): quarter-note start/end locators, 0/0 off while retaining them, 960 ticks per quarter note, with no silent rounding. Custom LCD and the complete Signature List must already be visible, with stopped nonrecording transport and a fresh complete N/4 timebase (N from 1 through 16, /16 division). That identity and both locator values fence apply/restore. Unknown or changed identity refuses even with discard; no native Undo is pressed and no entity is deleted. Missing original restore evidence is manual-only. Other than the two Region value previews below, other M4 kinds and project saving remain disabled; simulator timebase fixtures are explicit synthetic state, and current native acceptance remains pending.

Region Rename and Region Loop are the only two further M4 kinds (19 total). They require the target already selected alone, open Inspector/Mixer and complete version-one project/track/region/Inspector evidence. There is no selection, key, native Undo or pane operation. Unknown/replaced/ambiguous/changed evidence refuses even discard; name changes require fresh refs. The host retains full proof privately and publishes only controlled values plus validated restore capability. Missing proof is manual-only, uncertainty never resends. Other M4 writes/save and fresh native acceptance remain pending.
