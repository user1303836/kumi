# Logic Pro ブリッジ: M3 と Loop Range

- サンプルレートは任意情報です。バックグラウンドで `Alternatives/000/MetaData.plist` のサイズ制限付き XML だけを読みます。バイナリ形式、アクセス不可、シンボリックリンク、不確かなメタデータの場合は不明のままです。

- macOS の Logic Pro 12 向けの、実機の情報を読む実験的な基盤です。認証付き接続は6つの観測メソッドに加え、`change_preview`、`change_apply`、`change_restore`、`transport_stop`、`transport_play`、`cursor_set`、`undo_step_begin`、`undo_step_end` と、値の復帰で確認した `undone_in_daw` イベントに対応します。実機への読み取りが待機していても、キャッシュ済みの状態と FOCUS は応答します。
- 読み取り対象は project、track、region、note、plugin、send、marker、tempo の行です。本文は `tree`、`notes`、`timeline`、`routing` に対応します。M3 はトラックの5つの操作、名前変更・追加・削除、マーカーの追加・移動・削除、テンポ、ノートの追加・変更・削除、プラグインのバイパスに対応します。適用前にプレビュー時の値を照合し、適用後に読み直します。試聴とレンダリングは公開しません。実験的なアプリ統合は `kumi --daw logic` と `/daw logic` で選べます。記録の再生テストと実機での受け入れ確認は別です。
- `kumi-logic-hands` は別の子プロセスです。アクセシビリティ権限の不足は `busy` とは別に `permission: "accessibility"` として返します。最初の接続時に macOS がヘルパーの権限を求める場合があります。Logic 内には何もインストールせず、Logic の再起動も不要です。

リポジトリのルートで実行します。ビルドは同時に一つだけ実行してください。

```sh
python3 scripts/build-logic-hands.py
cargo build -p logic-kumi
sh scripts/test-isolated.sh --profile ci -p logic-kumi
```

ヘルパーのビルドには macOS と Xcode コマンドラインツールが必要です。ソースのダイジェストを名前に含むユニバーサルヘルパーを `target/logic-hands/` に作成します。分離された Rust テストは使い捨てのヘルパーを使うため、Logic もアクセシビリティ権限も不要です。

Logic を開いてから、開発用に直接実行する例:

```sh
target/debug/logic-kumi --kumi-home /absolute/path/to/disposable-kumi
cargo run -p logic-kumi --example logic_lab_client -- --kumi-home /absolute/path/to/disposable-kumi
```

- ビルド済みヘルパーは自動で見つかります。`--helper <path>` で指定もできます。直接実行したブリッジは Logic の終了、または SIGINT、SIGTERM、SIGHUP で終了します。標準入力の EOF では終了しません。
- ホストは `--hosted` を付けます。この場合は標準入力パイプを閉じても終了します。どちらの終了経路でも、検出ファイルを削除し、応答待ちの要求があってもヘルパーを停止して回収します。ブリッジは Logic を起動・終了しません。
- 通常の情報取得では仮想 MIDI ポートを開きません。`--mcu` を明示すると仮想 Mackie Control サーフェスを有効にします。Logic がそのコントロールサーフェス設定を保存する場合があります。ヘルパーの停止はポートを閉じますが、保存された設定は削除しません。自動復元は確認できていません。
- Logic を使わない任意のネイティブヘルパー確認: `python3 -m unittest discover -s daws/logic/logic-kumi/helper/tests -p test_protocol.py`。macOS ヘルパーをコンパイルして実行し、使い捨ての仮想 MIDI ポートを使います。

実機記録の再生には `d821e669` の元の M2 シーン4件と26要求のベクトルを使います。`tests/fixtures/sources.json` に元のパスと SHA-256 を記録し、テストは元のバイト列の一致と実際の読み取り結果を、期待値を書き換えずに確認します。この再生は、現在の Logic やアプリでの実機受け入れ確認を意味しません。読み取りのためにヘルパーが Logic のペインを移動する場合がありますが、トラックやリージョンの選択は変更しません。ノートは、対象のリージョンだけが選択されている場合に読み取れます。それ以外は、プロデューサーの選択を変更せずに拒否します。

- 値の復元は新しい書き込みです。追加したトラックは Logic 側で手動で取り消してください。ヘッダーと Mixer の情報では、再生位置から離れたオートメーション、閉じたプラグインのパラメーター、非表示のメタデータを確認できません。削除したトラックとマーカーも手動で取り消します。Edit メニューの名前は Kumi の特定の履歴を証明せず、元のマーカー名も設定できません。名前だけによるマーカー・ノート・構造変更の取り消し判定は非対応です。属性・トラック名・テンポは値の復帰を確認します。
- 追加・移動したマーカーの自動復元には、必要な過去の識別情報がすべて記録され、マーカーとリスト全体が一致する必要があります。取得できなかった Text は空文字ではなく不明です。過去の情報が不完全なら、`discard: true` や元の位置への見かけ上の復帰でも手動取り消しが必要です。後から Text を表示しても過去の値は復元できません。Text を取得できる派生記録では値の復元を検証します。
- M3 の20記録は `8d609d6a` からバイト単位で保持し、出所とハッシュは `tests/fixtures/change-sources.json` に記録します。14記録は、意図した識別・案内情報の追加と危険な構造変更の判定除外を明示して全要求を再生します。6記録は拒否する復元の境界まで進み、依存する後続要求を残します。未消費の要求数は `change-track-add` 0、`change-track-delete` 4、`change-marker-add` 1、`change-marker-move` 0、`change-marker-delete` 3、`change-carry` 4 です。拒否した復元と未消費の要求は、成功した再生範囲や現在の実機受け入れ確認には数えません。
- ノート編集は他のリージョンの選択を拒否し、Event List の対象が単独選択のままか確認します。観測では選択を書き換えません。参照の対応が曖昧な復元や、画面位置が不明なクリックは拒否します。

- プラグインのバイパスは、所有トラック・スロット番号・順序付きの全チェーン・各名前と種類・取得できる安定した AX role/subrole/id を照合します。適用と復元の直前に読み直し、不明・重複・不完全なら拒否します。元の値への復帰や `discard: true` でも省略しません。バイパス値や変動する UI 状態は識別情報に含めません。元の記録は保持し、追加の識別フィールドだけを記録済み Mixer 情報から明示的に導きます。
- Logic のスロットには永続的なプラグイン実体 ID やコンポーネントクラスがありません。同じ観測情報で削除・再作成する ABA 変化や、最終読み取りと AX 操作の間の変更は識別できません。これは実機受け入れ確認に残る制限です。現在の実機変更テストは行っていません。Undo の記帳では合成ショートカットを送信しません。


- M4 から追加した操作は `loop-range` だけです。あらかじめ Custom LCD に、値と書き込み可否を確認できる完全な2つの音楽位置ロケーターと `/16` 分割を表示し、完全な Signature List を選択してください。対応範囲は `1.1.1.1` にある既知の単一 N/4 拍子（N は1〜16）で、再生と録音は停止している必要があります。拍子や分割が不明・複数・非対応なら、プロジェクトを書き換える前に拒否します。この条件のために拍子イベントを変更することはありません。
- 入力は音楽上の1小節目からの `startBeats` と `endBeats` で、1/960拍の刻みに正確に一致する必要があります。`0, 0` は両ロケーターを保持して Cycle だけをオフにします。履歴には生の位置、読み直した保存済みプロジェクトの識別、対応する拍子マップ全体、分割を保存し、適用と値による復元で照合します。復元済みの判定や discard でも省略せず、過去の情報が不完全な履歴は手動復元を求めます。
- 書き込み可能な全操作と64ステップの上限を事前確認し、各操作の直前と直後に完全な状態を読みます。応答の消失・不正、プロジェクトや時間基準・無関係なロケーター状態の変化は結果不明として停止します。再試行、巻き戻し、表示の後片付けは送信しません。ペインを開く操作、LCD モードの変更、キー入力、MIDI、ネイティブ Undo は使いません。最後の読み取りから操作までの競合と、観測上同じプロジェクトの再読み込みはネイティブ API の制限として残ります。
- `tests/fixtures/cycle-source.json` は `6f8f6e9b` の Loop Range 記録の出所を示します。元の7要求は変更しません。記録済み情報だけの読み取り接頭部では LCD が Custom でないため最初のプレビューを拒否し、依存する後続6要求を明示的に未消費とします。完全な Signature List も元の記録にはありません。対応状態を明示した合成テストは別に扱い、実機受け入れ確認や元の全7要求の再生とは主張しません。
