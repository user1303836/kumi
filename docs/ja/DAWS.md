# Live、REAPER、Renoise で Kumi ができること

[English](../en/DAWS.md) · [简体中文](../zh-CN/DAWS.md) · 日本語

Kumi は Ableton Live、REAPER、Renoise で、それぞれの DAW の言葉で動きます。このページは、どの DAW で何ができるかをまとめたものです。つなぎ方は[ガイド](KUMI_GUIDE.md#reaper-や-renoise-につなぐ)、変更ツールの一覧は [Kumi が Set を変更するしくみ](KUMI_CHANGES.md)、Live のブリッジの詳細は[機能マトリクス](CAPABILITY_MATRIX.md)にあります。

## Live

- Kumi のブリッジは Remote Script で、Kumi の Live 拡張機能と Willington がそれを補います（[機能マトリクス](CAPABILITY_MATRIX.md)）。
- プラン全体は Live の取り消し一回で戻せます（Cmd-Z、Windows では Ctrl-Z）。
- スクリプトでできないことは Live 自身のメニューで行います。フリーズ、バウンス、ステム、オーディオから MIDI への変換などです（[Live 自身のコマンド](KUMI_GUIDE.md#live-自身のコマンド)）。
- **バリエーション**（`variations`）：Session の MIDI クリップの番号付きテイク V1、V2… を、同じトラックでその下の、ほかにクリップのないシーンに新しいクリップとして作ります（なければ最後にシーンを足します）。ノートのピッチ・ベロシティ・タイミングを動かすか、ノートを減らすか、Kumi が書きます。指定したノートはそのまま残します。各テイクがソースとも互いとも違い、それでいてキーを保つかを確かめます。Live は MIDI クリップをライブでしか鳴らさないので、テイクはスロットを再生して聴きます。残したテイクは「V3 · … · kept」と名前が変わります。

## REAPER

Kumi の拡張機能（`reaper_kumi`）を通じて動きます。macOS、Windows、Linux の REAPER 7 以降が必要です（[動作環境](SUPPORT_MATRIX.md#reaper-と-renoise)）。macOS の 7.82 で確認済みで、Windows と Linux ではまだ試していません。

### あなたのセットアップ

Kumi は見るたびに、あなたが REAPER をどう設定したかを読み、REAPER の初期設定ではなくそれに合わせて動きます。

- 新しいアイテムのフェード（またはなし）、新しいアイテムのループソース、新しいトラックのボリューム、プロジェクトのタイムベース。
- SWS、ReaPack、ReaImGui、js_ReaScriptAPI のどれが入っているか（入っているときだけ使います）。
- 使われているレンダー設定（ソース、範囲、フォーマット、サンプルレート、ファイル名のパターン）。変える前に伝えます。

Kumi が読み込むファイルは、あなたの読み込んだメディアがループするときだけソースをループし、あなた自身の読み込みと同じくフェードは付きません。

### Kumi が変更できるもの

変更はそれぞれ REAPER の取り消しの一ステップで、プラン全体も一ステップです。すべてのツールは [KUMI_CHANGES](KUMI_CHANGES.md#reaper-で-kumi-が変更できるもの) にあります。

- **トラック**（`track_add`、`track_move`、`track_delete` ほかの `track_…`）：追加（フォルダーとしても）、移動、削除、名前、色、表示と非表示、フォルダーの開閉、ロック。グループ、トラックテンプレート（`track_template_insert`）、固定レーンとコンピング（`lane_plays`、`lane_name`、`lane_comp`）、レイザー編集範囲（`razor_set`）。
- **ミキサー**（`track_volume`、`track_pan` など）：ボリューム、パンとパンモード、幅、ミュート、ソロ、極性、チャンネル数、親フォルダーやマスターへのセンド、FX チェーンのオンオフ。録音待機、録音入力、モニタリング。
- **ルーティング：** センドとレシーブ（`send_…`、`receive_add`）、3/4 チャンネルへのサイドチェーン、ハードウェア出力（`hw_out_…`）、ハードウェアへの MIDI 出力。
- **FX**（`fx_…`）：REAPER の FX ブラウザーに出る名前での追加、削除、移動、コピー、バイパス、オフライン。ウェット、ピン、プリセット、プラグインの状態全体、FX チェーンファイル。コンテナと並列 FX。パラメーター（一度に 256 個まで）、ReaEQ のバンド。パラメーターモジュレーション（LFO、オーディオコントロールシグナル、リンク、ラーン）。
- **エンベロープとオートメーション**（`envelope_…`、`automation_item_…`、`automation_override`）：表示とアーム、ポイント、オートメーションアイテム、オートメーションモード。
- **アイテムとテイク**（`item_…`、`items_glue`、`items_render`、`take_…`、`stretch_markers_…`）：追加、ファイルの読み込み、移動、分割、トリム、フェード、グループ、削除、複製。グルーとレンダリングは頼まれたときだけ。テイク、ストレッチマーカー、テイクマーカー。
- **MIDI**（`notes_…`、`midi_events_…`）：ノートの追加、変更、削除、クオンタイズ、ヒューマナイズ。CC、ピッチベンド、プログラム、プレッシャー、テキスト、SysEx。
- **マーカー、リージョン、ループ**（`marker_…`、`region_add`、`regions_add`、`region_render`、`ruler_lane`、`time_selection`、`loop_range`）：ルーラーレーン、リージョンのレンダーマトリクス、複数のリージョンを一つのステップで。
- **テンポとプロジェクト**（`tempo_set`、`tempo_marker_set`、`metronome_switch`、`project_…`）：テンポマーカー、拍子とランプ、メトロノーム、グリッド、タイムベース、メモ、タイトル、作者。
- **キットとゴール**（`drum_kit`、`scratch_keep`）。
- **スクリプト**（`run_lua`、`api_call`、`run_action`）。

ほかに、再生、停止、編集カーソルの移動、プロジェクト（または REAPER の次のバージョン）、トラックテンプレート、FX チェーンの保存もします。

### 聴き方

- パートをオフラインで（再生より速く）レンダリングして聴き、そのあと最大 1 分、音に出して聴かせます。トラック単体はプリフェーダーのステムです。
- REAPER の再生中は、マスター出力を再生しながら聴けます（既定は 8 秒）。レンダリングすると REAPER の再生は止まります。
- 判定する変更は、最後の ReaLimit で、なければ Kumi が加える JS: Volume Adjustment でレベルを保ちます。ゴールは候補をスクラッチコピー（「Kumi · try …」）で試し、最良のものが「Kumi · Goal best」に残ります。

### ワークフロー

- **納品**（`render_files`）：ゲームやクライアント向けのファイルを、音ごとに一つ。Kumi はアイテムをアセットにまとめ（重ねたレイヤーで一つの足音）、新しいものにプロジェクトのリージョンが従う命名規則で（または指定どおりに）名前を付け、次の音の前で止まるテールを足し、それぞれのリージョンを一つのステップで作ります（各リージョンはそのアセットのトラックをレンダリング）。次に、REAPER が書き出すファイルをその名前と照らし合わせ（何もレンダリングしません）、まさにそのファイルだけをレンダリングします。納品のリージョンだけを、それぞれのトラックをマスター経由で書き出し、言われない限りレンダーダイアログのノーマライズや第二フォーマットは使わず、既存のファイルにも上書きせず、レンダー設定は後で元に戻します。
- **ルーティング**（`routing`）：トラックが大きすぎる・鳴らない・打ち消し合う理由。Kumi は各トラックがマスターに届くすべての道（フォルダー、センド、ハードウェア出力）を読み、ありそうな間違いを名前で言います：合算するだけのバスで二度鳴るトラック、ループ、どこにも鳴らないトラック、トラックにないチャンネルへのサイドチェイン、位相が反転した重複。サイドチェイン（ReaComp でキックがベースをダッキング）、パラレルバス、ステムを REAPER の取り消し一ステップで作り、ルーティングを読み直して確かめます。
- **SFX バリエーション**（`variations`）：アイテムの番号付きテイク V1、V2… を作ります。それぞれトラック上のソースの後ろに置いたコピーで、ピッチ・レート・開始位置・長さ・フェード・音量が少しずつ違います（MIDI アイテムではノート・ベロシティ・タイミングを変えます）。Kumi は各テイクがソースとも互いとも違い、それでも同じ音のままか（アタックと指定したノートは保つ）を確かめ、レンダリングして聴き（ソースはクリップしないのにクリップするテイクは、ソースのピークまで下げます）、言われたとおりに残す・変える・捨てます。`render_files` で一つずつファイルにできます。
- **ステム**（`stems`）：トラックの区間を Kumi 自身のスプリッターでドラム（叩く音）、ベース（150 Hz より下で鳴り続ける音）、その他（残り。声も）に分けます。三つを足すと元のトラックになります。それぞれその下の新しいトラックに、区間を覆うアイテムとして置かれます。
- **オーディオから MIDI へ**（`audio_to_midi`）：トラックの音声を区間ごとに Kumi 自身の耳で聴きます。ドラム（ヒットごとに General MIDI のドラムキーのキック、スネア、ハット。叩いた強さのまま、ゴーストは弱く）、メロディー、ハーモニー（Basic Pitch）。ノートはその下の新しいトラックの MIDI アイテム一つに入ります。聴くには音源を足してください。
- **仕様どおりの納品**（`delivery_spec`）：ACX、ストリーミング（Spotify、Apple Music、YouTube…）、ポッドキャスト、放送（EBU R 128、ATSC A/85、Netflix）。Kumi はミックスをオフラインでレンダリングして、インテグレーテッドラウドネスとトゥルーピーク（ACX では RMS とノイズフロアも）を測ります。ピークが許すならマスターフェーダーを仕様に必要なゲインだけ動かし、もう一度測り、フェーダーでは直せないこと（リミッティング、ノイズ）はそう伝えます。
- **作業のスクリプト**（`scripts`）：繰り返す作業を、プロジェクトに合わせて Lua で書き、REAPER の取り消し一ステップとして一度実行します。あなたが承諾すると、Kumi は名前で再実行できるよう残し、アクションリスト（Scripts/Kumi）のアクションにもして、ショートカットやツールバーボタンに割り当てられるようにします。このプロジェクトの ID や Kumi の ref を名指しするものは残さず、位置で取るものはそう伝えます。
- **ドラムキット**をサウンドファイルから：パッドごとに ReaSamplOmatic5000 を置き、パッドトラックのフォルダーか一つのコンテナにまとめ、ハイハットはチョークし合います。
- **チュートリアルやリファレンスの音：** `watch_video` のあと、ReaEQ、ReaComp、ReaSynth やあなたのプラグインで作り、耳で判定します。
- **プリセット：** REAPER のリソースフォルダーにある FX チェーン、トラックテンプレートとプロジェクトテンプレート、JSFX、FX プリセットを探して読み込みます。

### 制限

- **REAPER の取り消しだけが** `run_lua`、`api_call`、`run_action` を戻せます。`run_action` は、名前が「…」で終わるアクション（ダイアログ）、終了、プロジェクトを開く・閉じる・保存する、レンダリング、REAPER での取り消しとやり直しのアクションは決して実行しません。
- **Kumi の取り消しだけが**、REAPER の取り消しが飛ばすものを戻せます。リピート（`loop_repeat`）、メトロノームのオンオフ（`metronome_switch`）、ReaEQ のバンドの種類とオンオフ（`fx_eq_band`）、オートメーションのオーバーライド（`automation_override`）、プロジェクトのメモ、タイトル、作者、グリッド、タイムベース（`project_notes`、`project_info`、`project_grid`、`project_timebase`）、何もオンになっていないパラメーターモジュレーションです。
- パラメーターモジュレーションを Kumi の取り消しで戻すと、スイッチはオフになりますが、REAPER が一度作ると残す設定はそのままです。HISTORY の行にそう書かれます。
- トラックがすべて一度に入れ替わったプロジェクトは別のプロジェクトとして読まれ、Kumi の参照は古くなって読み直します。
- `track_midi_out` には、REAPER の環境設定で MIDI 出力デバイスが必要です。
- ダイアログやレンダリングで REAPER の手がふさがっている間、変更はすぐに断られます。

## Renoise

Kumi のツール（`com.kumi.Bridge.xrnx`）を通じて動きます。macOS、Windows、Linux の Renoise 3.5 以降が必要です（[動作環境](SUPPORT_MATRIX.md#reaper-と-renoise)）。macOS の 3.5.4 で確認済みで、Windows と Linux ではまだ試していません。

### あなたのセットアップ

Kumi は見るたびにソングの設定を読み、それに従います。BPM（2 倍や 4 倍の慣習はそのまま）、LPB、TPL、Edit Step、ほとんどのパターンの長さ、グループとその色、入っているツール（Paketti も含む）です。

### Kumi が変更できるもの

変更はそれぞれ Renoise の取り消しの一ステップです。すべてのツールは [KUMI_CHANGES](KUMI_CHANGES.md#renoise-で-kumi-が変更できるもの) にあります。

- **ソング**（`song_bpm`、`song_lpb`、`song_tpl`、`song_groove` ほかの `song_…`、`metronome_switch`、`edit_settings`）：BPM、LPB、TPL、グルーヴ、メトロノーム、編集の設定（Follow Player、Edit Step、オクターブ、録音クオンタイズ）、名前、アーティスト、コメント、ヘッドルーム。
- **トラック**（`track_…`）：シーケンサートラック、センドトラック、グループトラックの追加、移動、グループ化、削除、名前、色、折りたたみ。ノート列とエフェクト列。ボリューム、パンニング、幅、ミュート、ソロ、出力ルーティング、ディレイ。
- **パターンシーケンスとマトリクス**（`slot_…`、`slots_drop`、`loop_range`、`loop_pattern`）：スロットの挿入、削除（複数を一つのステップで）、移動、クローン、ユニーク化、別のパターンやそのバリエーションへの差し替え。セクション、マトリクスのミュートと色。ループ。
- **パターンと行**（`notes_write`、`notes_clear`、`notes_transpose`、`notes_humanize`、`lines_copy`、`pattern_…`、`automation_write`）：ノート、インストゥルメント、ボリューム、パンニング、ディレイ、エフェクトの各列を Renoise の表記で。パターンの名前、長さ、エイリアス。オートメーション。
- **Track DSPs**（`device_…`、`doofer_…`、`splitter_set`、`notepad_write`、`meta_destination`）：ネイティブとプラグインのデバイス、パラメーター、プリセット、チェーンファイル（.xrnt）。Doofer とそのマクロ、Splitter、Notepad、メタデバイスの向け先。
- **インストゥルメントとサンプル**（`instrument_…`、`sample_…`、`keyzone_…`）：追加、複製、移動、読み込み（.xrni、.sfz、サンプル）、サンプルファイルからの作成。マクロ。サンプルの設定、スライス、キーゾーン、ドラムキットのレイアウト。サンプルの極性反転。
- **モジュレーションとサンプル FX**（`modset_…`、`moddevice_…`、`chain_…`、`chaindevice_…`）。
- **フレーズ**（`phrase_…`、`phrases_drop`）：追加（行ごと）、削除（複数を一つのステップで）、鍵盤への割り当て、再生のしかた、行。フレーズスクリプトを書いてレンダリング。.xrnz ファイル。
- **プラグインと MIDI**（`plugin_…`、`midi_set`）：プラグインインストゥルメント、そのパラメーターとプログラム。MIDI インストゥルメントの出力。
- **ゴールとスクリプト**（`scratch_keep`、`run_lua`）。

ほかに、再生、停止、ノートを鳴らして聴かせる、Renoise で何かを表示する、ソング、インストゥルメント、デバイスプリセットの保存もします。

### 聴き方

- パートをオフラインでレンダリングして聴き、そのあと最大 1 分、音に出して聴かせます。トラック単体は Renoise のトラックソロです。
- Renoise のスクリプトは鳴っている音を聴けず、レンダリングすると再生が止まります。再生中は、あなたが指定したパートだけをレンダリングします。
- 判定する変更は、最後の Maximizer で、なければ Kumi が加える Gainer でレベルを保ちます。
- Renoise のデモ版はレンダリングできないので、そこでは Kumi は聴けません。`kumi doctor` がそう伝えます。

### ワークフロー

- **バリエーション**（`variations`）：パターントラックの行（`0S`・`0R`・`0B` コマンドで書いたチョップなど）、フレーズ、またはインストゥルメントの新しいフレーズ（「フレーズを 9 つ作って」）を、番号付きのテイク V1、V2… として作ります。あなたが指定した行はその素材を決めるものとして残し、残りを変え（スライス、ロール、リバース、ゴーストノート、アクセント、音域）、各テイクが元とも他のテイクとも違い、それでいてアイデア・キー・グリッドを保つかを確かめ、テイクは先にレンダリングして聴きます（Renoise の再生中は除きます。ソースはクリップしないのにクリップするテイクは、ボリューム列でソースのピークまで下げます）。テイクはそれぞれフレーズになるか、シーケンス末尾の「Variations of …」セクションに自分のスロットを持ち、パターンの残りと一緒に鳴ります。「1、3、5 は残して、ほかは変えて」と言えばそれだけを一つずつ別の方向に変え、残りは一つのステップで消します。あなたが編集したテイクには手を付けません。残したテイクは「V3 · … · kept」と名前が変わり、Kumi を再起動してもテイクを覚えています。
- **フレーズ：** Renoise の表記で書くか、フレーズスクリプトを書いて行にレンダリングします。パターンの行をどのキーからでも弾けるフレーズにし（`variations` の extract）、フレーズの LPB は固定なので、速いコピーには `0Zxx` で切り替えます。
- **サンプルマップ**（`map_samples`）：サウンドのフォルダ、またはインストゥルメントのサンプルを、一つのステップで鍵盤に並べます。Kumi はファイル名の音名（「C3」「A#2」「C-4」「060」）、ベロシティ（「v3」「vel64」「ff」）、ラウンドロビン（「rr2」）を読み、各サンプルのピッチと音量を聴き、名前が中央の C を C3・C4・C5 のどれで書いているかを確かめます。ルートとゾーン、音量順のベロシティレイヤー、交互に鳴るラウンドロビン、アーティキュレーションごとのインストゥルメントを計画し、何を決めたかを伝え、判断できないことだけを尋ねます。整理では、どのノートも鳴らさないインストゥルメント、コピー、二つのインストゥルメントが持つ同じサンプルを見つけ、あなたが受け入れたものだけを変えます。
- **チョップ**（`chop`）：ブレイクを実際のヒットで切ります。各ヒットをフレーム単位で見つけ、キック・スネア・ハット・ゴースト・ロールのどれかを判断し、長さからブレイク自体のテンポを割り出します。一つのステップでスライスし（テンポが合うときは曲のグリッド上に）、ディレイ列も使って録音どおりに鳴るようスライスを並べます。結果をレンダリングし、ヒットがどれだけ近くに来るか、録音と比べてどれだけ打ち消し合うかを伝えます。軽い密度（ゴーストとロールなし、キックとスネアだけ）はバリエーションのテイクとして作られ、残すか捨てるかを選べます。
- **ジャムの整理**（`jam`）：キャッチアップのあと、録ったものを以前のものと突き合わせます。Kumi は何が新しいかを伝え、整理を提案します：空のパターンを鳴らすスロットの削除、以前と同じパターンはそちらを鳴らすこと、以前のパターンのトラックを繰り返すトラックのエイリアス化、フィールではなくミスに見えるノート（ダブルトリガー、近くのノートと違ってグリッドから大きく外れたノート、はぐれた音。どの拍にも共通するスウィングは残します）。受け入れたものを適用し、頼まれれば強さを指定してクオンタイズし、以前のものには触れません。
- **ブレイクのレイヤー**（`layers`）：メインのブレイクと各レイヤーを区間ごとに単独でレンダリングし、ヒットごとに比べます：各レイヤーがどれだけ早いか遅いか、極性がメインと打ち消し合っていないか、どのくらいの音量か。Kumi はトラックディレイでレイヤーをずらし、サンプルで極性を反転します（Renoise には極性スイッチがないため。ほかのトラックがそのサンプルを鳴らしていない場合のみ）。グルーは、まずコンプレッサーなしのグループを聴き、狙った量になるまで Bus Compressor のスレッショルドを動かします。バランスはあなたの耳で決めます。
- **ステム**（`stems`）：トラックの区間を Kumi 自身のスプリッターでドラム、ベース（150 Hz より下）、その他（声も）に分けます。三つを足すと元のトラックになります。それぞれ新しい音源として読み込まれ、その後ろの新しいトラックで区間の頭から鳴ります。
- **オーディオから MIDI へ**（`audio_to_midi`）：トラックの音声を区間ごとに Kumi 自身の耳で聴きます。ドラム（キック、スネア、ハット。叩いた強さのまま）、メロディー、ハーモニー（Basic Pitch）。ノートは新しいトラックに、そのスロットが鳴らすパターンの中で、行ごとにディレイ付きで書かれ、指定した音源で鳴ります。
- **仕様どおりの納品**（`delivery_spec`）：ACX、ストリーミング、ポッドキャスト、放送のラウドネス。Kumi はソングをオフラインでレンダリングして測り、ピークが許すならマスターのポスト FX フェーダーを必要なゲインだけ動かし、もう一度測ります。フェーダーの +3 dB を超えるときは、先に Gainer か Maximizer が要ると伝えます。
- **作業のスクリプト**（`scripts`）：繰り返す作業を、ソングに合わせて Lua で書き、Renoise の取り消し一ステップとして一度実行します。あなたが承諾すると、Kumi は名前で再実行できるよう残し、Tools > Kumi > その名前 のメニュー項目にもして、Renoise の Keys 設定でショートカットを割り当てられるようにします。Kumi の ref を名指しするものは残さず、位置で取るものはそう伝えます。
- **サンプルファイルからインストゥルメント：** ミュートグループ付きのドラムキット、またはベロシティレイヤー付きの鍵盤を一つのインストゥルメントに。
- **Doofer** をデバイスから作り、マクロに名前を付けます。
- **チュートリアルやリファレンスの音：** `watch_video` のあと、ネイティブデバイスやあなたのプラグインで作り、耳で判定します。

### 制限

- **Renoise の取り消しだけが** `run_lua` を戻せます。
- **Kumi の取り消しだけが**、Renoise の取り消しが飛ばすものを戻せます。ミュートとソロ（`track_mute`、`track_solo`）、ループとパターンループ（`loop_range`、`loop_pattern`）、メトロノームのオンオフ（`metronome_switch`）、編集の設定（`edit_settings`）です。
- 行の編集（`notes_write`、`lines_copy`、`phrase_write` など）を Renoise 自身の取り消しとやり直しにかけたあとは、Kumi の取り消しは断られます。Renoise のやり直しと、あなたが書いた同じ行を区別できないためです。Renoise の取り消しでは戻せます。
- AU インストゥルメントを読み込んだあと、ほかのアプリに切り替えるまで Renoise が取り消しの手順を開いたままにすることがあります。そのあとは 1 回の取り消しで読み込みとそれ以降の変更がまとめて戻ります。Kumi の取り消しは変更ごとに使えます。
- FOCUS の Mixer にはメーターがありません。Renoise の API にないためです。
- 密度の高いソングのレンダリングは、少しの間ビジーとして断られることがあります。もう一度頼んでください。
