Open Recent から読み、ライブラリーが次の実行のために保存しておきます：ブリッジが最近のプロジェクトの場所を知っているのは、開いているものと、Spotlight が `~/Music` の外で見つけるものについてだけなので（macOS はそのフォルダーをブリッジに見せません）、ほかのものは開かれるまで学習されません。REAPER と Renoise は Live ## 既知の制限

- Live の API では、Set の保存や書き出し、フリーズ、グループトラックの作成、アレンジメントのオートメーションの編集はできません。[Live の API が提供しないもの](CAPABILITY_MATRIX.md#live-の-api-が提供しないもの)を参照してください。
- 一部の変更は Kumi では取り消せず、Live 自身の取り消しでしか戻せません。[Live の安全性](LIVE_SAFETY.md)を参照してください。
- Windows では、Kumi の拡張機能は未テストで、1.6.0 以前からの `kumi update` は tar のエラーで失敗することがあります。[Windows](SUPPORT_MATRIX.md#windows) を参照してください。
- これまでの本物の Live でのテストは Live 12.4.15 beta で、ほとんどが Apple silicon の Mac です。Live 12.0〜12.3、Intel Mac、スクリーンリーダーは未テストです。
- Willington による編集は `/willington` でオンにするまではオフで、Willington のバインディングがある Live ビルドが必要です：macOS ARM64 の Live 12.4.15b4 と b5（ラックのチェーンのゾーンは b5 のみ）と、Windows x64 の Live 12.4.15b5。Windows では、バインディングは Live の中の Python を通じてテストされていますが、Kumi 自身の編集を通じたテストはまだです。[Willington](WILLINGTON_INTEGRATION.md)を参照してください。
- Kumi とブリッジには署名がありません。[リリースと配布](DISTRIBUTION_POLICY.md)を参照してください。
- Logic Pro は Stereo Out の後で聴かれます（プロセスタップは Logic の出力全体を聴きます）：トラックはソロにして単独で聴くので、Stereo Out のプラグインを通り、マスキングは、中立な Gain を除き、それらのどのプラグインを通しても読みません。各候補は、それぞれ専用のリアルタイムのパスです。Kumi はまだ、Logic でゴールのレンダリングのリグを開いたままにしておくことも、プラグインのノブを耳で追い込むこと（tune は Logic のノブを読みません）も、実行中に名前を変えられたトラックを追うこともできません。また、リージョンのオーディオファイルをファイルとして聴くこともできません。Logic はそれを名前でしか示さないからです（代わりに、そのトラックをリージョンの小節にわたって聴きます）。聴き取りは Logic のメトロノームをオフにしたりオンにしたりします（そのクリックでキャプチャのタイミングを測ります）。これは Logic がプロジェクトと一緒に保存する設定なので、聴き取りの後は、中身が何も変わっていなくてもプロジェクトが編集済みと表示されます。Kumi は聴いたときにそう伝えます。
- Logic Pro への対応では、マーカーに名前を付けることも名前を変えることもできません。マーカーの名前のセルはテキストフィールドではないからです。トラックの移動や色付けもできません。ヘッダーは外部からドラッグできず、Color palette の色見本は、どのヘッダーも読み戻さないただの位置だからです。プラグインの移動（Logic はドラッグで動かします）やセンドのモードの設定（Logic が自分で描く印で、外部からは何も読めません）もできません。ブリッジはそれぞれを、理由を添えて拒否します。Kumi は、ブリッジが本物の Logic の上で行う種類を、M4 の両方のスライスのものも M6 のものも宣言しています。Logic には取り消しのブロックがなく、フェーダー、パン、ミュート、ソロ、アーム、テンポ、バイパス、サイクルについても、プラグインのパラメータや設定（プラグインウィンドウ自身の取り消しのステップです）、Smart Control、センドのレベル、メトロノームについても取り消しのステップを残さないので、Kumi はそれらを値で元に戻します。削除したトラックやリージョン、分割、インポート、フラット化した Track Stack、読み込んだパッチは、そのステップが一番上にある間だけ Logic 自身の取り消しで戻ります（削除したプラグインはその設定とともに、作ったセンドは Logic がそのために作った AUX とともに）。読み込んだサンプルも同じ方法で、その Sampler トラックと両方のリージョンごと取り消され、そのファイルのコピーはプロジェクトのパッケージに残ります。キーコマンドで行ったことを戻せるのは、Logic 自身の取り消しだけです。サンプルを入れられるのは Logic の Sampler だけです：Quick Sampler は、そのウィンドウへのドラッグでサンプルを受け取ります。リージョンは時間の上でだけ、そのトラックに沿って動きます。その端、分割、インポートの位置は拍単位で、インポートは専用のトラックを作ります。テンポは整数の BPM です。保存はバージョンを残しません（それは REAPER のものです）。Logic Pro 11 と Intel Mac は対象外です。[Logic の契約](LOGIC_CONTRACT.md)を参照してください。
- Logic Pro には Kumi がプロジェクトの中に入れられる ID がないので、Kumi は Logic のプロジェクトをそのパスで見分けます（ブリッジの ID はパスのハッシュです）：移動したプロジェクトや別の名前で保存したプロジェクトは、離れていた間の変化に追いつくことにとっても記憶にとっても新しいプロジェクトです。離れていた間の変化に追いつくことと `watch_me` は、Kumi がブリッジを通じて読むスナップショットを比べます：トラックは名前と順番で照合し（同じ位置で同じ種類のまま名前が変わったトラックは、名前の変更として伝えます）、リージョンはトラックと開始位置で、プラグインはストリップ上の順番で、マーカーは位置で照合し、見分けられないものは不明と伝えます。ノートやプラグインの設定はまだ比べません。読んだときに Logic が Mixer のストリップを描いていなかったトラック（Mixer の表示より幅の広いプロジェクトで）は、そのプラグインとルーティングを、削除されたと伝える代わりに比較から外します。Stereo Out のプラグインはプロジェクトそのものの行になり（追加、削除、バイパス、オンへの復帰）、両方のスナップショットがそれを読んでいれば比べます。ブリッジが各種類のすべての行を一度に読む場合（`rows` を付けた `snapshot`）、スナップショットはプロジェクトを一度見たものになり、その Mixer と List Editors は一度だけ表示されます（M6 のブリッジの計測で、Scratch で 2.7 s。ページごとの読み取りでは 4.5 s）。古いブリッジのスナップショットは、これまでどおり 1 ページずつ読みます。Logic の Project Templates フォルダーにあるプロジェクトについては、離れていた間の変化に追いつくことは決してしません。
