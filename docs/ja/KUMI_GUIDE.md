# Kumi ガイド

[English](../en/KUMI_GUIDE.md) · [简体中文](../zh-CN/KUMI_GUIDE.md) · 日本語

Kumi は、開いている Ableton Live の Set のためのプロデューサーエージェントで、ターミナルで動きます。Set を読み、頼まれた変更を行い、その一つひとつを HISTORY に表示します。再生、録音、レンダリングを行い、オーディオを聴いてリファレンスと比べ、ビデオチュートリアルを見て、Max for Live デバイスを作り、ウェブで調べものをし、あなたの作業のしかたを覚えます。REAPER のプロジェクトや Renoise のソングでも動きます。このガイドはおもに Live について書いていて、そこで何が違うかは[REAPER や Renoise につなぐ](#reaper-や-renoise-につなぐ)にあります。

Kumi をインストールして Live につなぐには、[クイックスタート](../../README.ja.md#クイックスタート)に従ってください。このガイドでは、その後のすべてを説明します。キーと画面については[コマンド、キー、画面](KUMI_TUI.md)を、変更と取り消しのしくみについては[Kumi が Set を変更するしくみ](KUMI_CHANGES.md)を参照してください。

## サインインとモデルの選択

Kumi の中で `/login` を使うとサインインします（初回は Kumi のセットアップが先に尋ねます）。ChatGPT にはお使いのプランでサインインするか（ブラウザが開き、サインインの結果は `localhost:1455` に戻ってきます）、下の表のほかのプロバイダーには API キーでサインインします。キーは、ドットだけが表示される入力欄に貼り付けます。Kumi はキーを保存する前に、そのプロバイダーでキーを確認します。プロバイダーに接続できない場合は、キーを保存し、まだ確認していないことを伝えます。`/logout` でサインアウトします。

セットアップのサインインのステップでは：

- Kumi はまず ChatGPT のサインインに届くかを確かめます。届かないときは、その理由（DNS、TLS、プロキシ、時間内に応答がない、接続できない）と、経由したプロキシの設定を伝えます。設定がなければ、`HTTPS_PROXY` で設定できることを伝えます。
- **d** を押すと、ブラウザの代わりにコードで ChatGPT にサインインします。どの機器のブラウザでもそのコードを入力できます。SSH 経由では、`/login` でも `kumi login` でも、Kumi が自分でコードを使います。**b**（または `--browser`）でブラウザ用のリンクに戻れます。
- ブラウザ用のリンクは全体が表示され、**c** でコピーできます。
- Ollama か LM Studio が起動している間は、**On this computer** も選べます。

**プロバイダー。** 次のどれにも `/login` か `kumi login <id>` でサインインできます。`kumi auth` でサインイン状況がわかります。キーの環境変数も使えますが、`/login` で保存したキーが優先されます。

- モデル名にはプロバイダーの `/` がそのまま入ります（`openrouter/moonshotai/kimi-k3.1-pro`）。

- NVIDIA の無料トライアルキーはテストと評価のためだけのものです。一部のモデルは応答が遅れて届き、まだ Kumi では使えません。
- Hugging Face には、Inference Providers の権限を持つ fine-grained トークンが必要です。
- Google の Gemini API の規約は業務での利用向けで、EEA、スイス、英国では有料プランが必要です。
- `/model` には ChatGPT、Anthropic、OpenAI、OpenCode が常に、ほかのプロバイダーはサインインすると表示されます。その **More providers** で `/login` が開きます。
- 後から Kumi に加わったプロバイダーと同じ名前のカスタムサーバーは、その名前の ID のままです。Kumi はそのプロバイダーをあなたには表示せず、切り替え方は `kumi doctor` が伝えます。

`/login` で保存したキーが優先されます。保存したキーがなければ、Kumi は環境変数のキーを使います。この場合 Kumi からはサインアウトできないので、環境変数のほうを削除してください。API キーは Kumi のキー入力欄か `kumi login` のプロンプトにだけ貼り付け、メッセージには決して貼り付けないでください。Claude と Gemini のサブスクリプションによるサインインは提供していません。それぞれのプロバイダーが、サードパーティのツールでの使用を認めていないためです。OpenCode の Gemini モデルにはまだ対応していません。

`/model` は各プロバイダーのモデルを一覧表示します。一覧はプロバイダー自身から読み込むので、今日リリースされたモデルも Kumi を更新せずに使えます。文字を入力すると一覧を絞り込めます。モデルを選んでいない場合、Kumi はサインインしている最初のプロバイダー（表の順）の最初のモデルを使い、どれを使っているかを伝えます。`/effort` は、そのモデルが用意している段階（`none` から `max` まで）の中から、モデルがどれだけ深く考えるかを設定します。低いほど早く答えます。どちらも次のメッセージから適用され、次回も保持されます。モデルを変えても会話はそのまま続きますが、前のモデルの非公開の推論はそのモデルのものなので引き継がれません。

Kumi が各モデルについて知っていること（思考の段階、ツールを使えるか、言葉のほかに何を受け取るか）は、まずプロバイダーの一覧から、次に [models.dev](https://models.dev) のカタログから、最後にモデル名から得ます：

- 会話しないモデル（画像、埋め込み、音声）は一覧に出ません。
- **chat only**：そのモデルはツールを使えません。Kumi はそのモデルと Set について話せますが、何も変更できません。このコンピューター上のツールを使えないモデルと同じです。頼まれたときにツールを断ったモデルも、Kumi を再起動するまで同じように扱います。
- **unverified**：プロバイダーも models.dev もそのモデルを説明していないため、Kumi は名前から判断しています。
- **deprecated**：プロバイダーが提供を終えようとしています。

Kumi はカタログの写しを持っていて、新しいものを多くても一日に一度取得します。`settings.json` の `"modelCatalog": false` で取得を止められます。

サインインがない、または拒否されたために回答が失敗した場合、Kumi はサインインを提案し、その後あなたのメッセージを送り直します。選んだモデルをプロバイダーが提供していない場合は、別のモデルを選ぶよう提案します。保存したモデルがプロバイダー自身の一覧から消えた場合（プランのサインインで提供が終わったときなど）は、起動時にそのことを伝えて `/model` を開きます。回答が途中で途切れた場合（接続が切れたときなど）、Kumi は途切れたところから一度だけ続け、そのことをステータス行に表示します。もう一度途切れた場合は、メッセージを送り直すよう提案します。

### 上限、障害、フォールバックモデル

- **プランの上限**（ChatGPT の 5 時間枠や週の枠）：Kumi はリセットを待ち、同じ答えを続けます。NOW がいつ続けるかを表示し（「carrying on at 14:20」）、待つ時間は答えの 1 時間に数えず、コンピューターはスリープせず、Esc で止められます。リセットが 6 時間より先なら、答えを止めてリセットの時刻を伝え、フォールバック、別のモデル、別のサインインを提案します。
- **フォールバックモデル**は、待つ代わりに続けます：`/model` で ctrl+f を押すと、選んだモデルがフォールバックになります（もう一度押すと解除）。あなたのモデルのプランが上限に達したとき、クレジットを使い切ったとき、またはリトライの後もプロバイダーが落ちているときに、次のステップから引き継ぎます。答えている間はヘッダーにその名前が表示され、リセット後の最初のメッセージからあなたのモデルに戻ります。サインインしていないフォールバックは使わず、そのことを一度だけ伝えます。
- **混んでいる、または不調なプロバイダー：** プロバイダーが求めるだけ待ち（Retry-After。長さを問わず、秒数でも日時でも）、一つのステップを最大 3 回試します。
- **接続がないとき：** 答えを続けられる間は、少しずつ間隔を空けて（最大 30 秒）試し続けます。
- **プランの使用量：** 枠の 80% から、ヘッダーに「plan 84% · resets 14:20」と表示されます。

### このコンピューター上のモデル

- **Ollama** と **LM Studio** は、起動していればサインインなしで見つかります。`/model` はそれぞれを一つのプロバイダー（「Ollama · on this computer」）として、そのサーバーにあるモデルとともに表示します。インストール済みで閉じているものは、起動のしかたを示します。どこにもサインインしていなければ、Kumi はそれらのモデルのうち Set を変更できるもの（読み込み済みのものを優先）で始めます。
- **その他のサーバー**（llama.cpp の `llama-server`、vLLM、Jan、ゲートウェイなど）は、このコンピューター上でも別の場所でも `~/.kumi/settings.json` に書きます。名前がその ID になります（`llama.cpp` なら `llama-cpp/<model>`）。`format` で要求の書き方を指定します：`chat-completions`（OpenAI の Chat Completions。`format` がなければこれ）、`responses`（OpenAI の Responses）、`anthropic`（Anthropic の Messages）。そのモデルについて Kumi が知ることはサーバー自身の一覧から来るので、unverified と表示されます：

  ```json
  { "modelServers": [
    { "name": "llama.cpp", "baseURL": "http://127.0.0.1:8080/v1" },
    { "name": "Studio PC", "baseURL": "http://192.168.1.20:8000/v1", "apiKey": "…" },
    { "name": "Gateway", "baseURL": "https://llm.example.com/v1", "apiKey": "…", "format": "anthropic" }
  ] }
  ```

- **Kumi に必要な余裕。** Kumi の指示とツールだけで約 2.5 万〜3 万トークンになります。Kumi は Ollama に、それと会話と回答のための余裕（約 5.7 万トークン、モデルが読める上限まで）を求め、LM Studio には十分な余裕がないときにその余裕でモデルを読み込ませます。この余裕はメモリーを使い、モデル自体より多くなることもあります。
- **ツールを使えないモデル**でも Set について話せますが、変更はできません。Kumi はそのことを一度伝え、同じサーバーで使えるモデルを挙げます。見つかったサーバーは `kumi doctor` が一覧にします。

## Live につなぐ

Kumi はブリッジを通じて Live とやりとりします。ブリッジは、Live の中で動く Remote Script と、Kumi が起動するローカルの MCP サーバーからなります。初めて Kumi を開いたとき、また Kumi のブリッジが Live の中のものより新しいときはいつでも、Kumi のセットアップがアプリの中で、まだ済んでいないステップだけを進めます。

1. **Sign in**：Kumi がまだサインインしていなければ、サインインします。
2. **Connect to Live**：Kumi がブリッジを配置し、Live を開きます。
   - **Live が開いていないとき：** Kumi はまず Live 12 を探します。インストールされていない、または古い Live しかない場合はそう伝え、インストールしたら **Look again** で確かめ直します。Live 12 を一度も開いていない場合は、User Library を作らせるために Kumi が一度開きます。
   - **Live が開いているとき：** **Restart Live now**（Kumi が Live に終了を頼み、Live が先に作業の保存を求めます）か **I'll quit it**（自分で Live を終了するまで Kumi が待ちます）を選びます。Kumi が頼んでからしばらくしても Live が開いたままなら（保存を尋ねられて Cancel を選んだときなど）、Kumi はそう伝え、もう一度頼むかどうか尋ねます。
   - **Mac では、** 初回に macOS が、ターミナルに Live の操作を許可するか尋ねることがあります。OK を選んでください。許可しなかった場合は、Live を自分で終了するまで Kumi が待ち、許可する場所（システム設定 › プライバシーとセキュリティ › オートメーション）を伝えます。
   - Kumi が Live を閉じたあとは、ステップがどう終わっても Live はまた開きます。開いていた Set を Kumi が知っていれば、その Set ごと開きます（知らなければ、Set は File › Open Recent Set にあります）。
3. **Control Surface**：初回は Live で **Settings → Link, Tempo & MIDI** を開き、**AbletonMcpBridge** を Control Surface として選びます。Kumi は自分で気づき、Live はこの選択を覚えておきます。45 秒ほどたつと、Settings の場所（Mac では Live メニュー、Windows では Options）と、Live にダイアログが出ていれば先に答えることを書き添えます。

Live が動かない Linux では、セットアップはサインインだけを行います。

ステップで Esc を押すと、そのステップは後回しになります。ひとまず Live なしでチャットします。Sign in と Connect to Live は次回また提案されます。Connect to Live が済んでいれば、Live が応答したときに Kumi が自分で接続します。ブリッジの配置中に Kumi を終了すると、配置が終わってから終了します。`kumi bridge` は、Live を閉じた状態で同じことをシェルから行います：確認を求め（`--yes` で事前に確認済みにできます。ターミナルがないときは、`--yes` なしでは何も変えません）、Live の実行中は拒否し、Live を終了したり起動したりすることはありません。どちらも、ブリッジ自身のライフサイクルを通じて、チェック、レシート、ロールバック付きでブリッジをインストールまたは更新し、更新をまたいでブリッジの設定とシークレットを保持します。`kumi bridge` は Live が接続するまで最大 10 分待ち、接続したら知らせます。Live の中のブリッジが Kumi のものより古く、Live が閉じている場合は、`kumi update` が代わりに実行します（`--yes` を付け、待たずに）。それ以外のときは、`kumi update` と `kumi doctor` が `kumi` を実行するよう伝えます。`kumi` はブリッジを Live に入れ、Live の再起動も任せられます。

Kumi は User Library の中から Live の Remote Scripts フォルダーを見つけます。User Library を別の場所に移していても見つけます（そのために Live 自身の設定を読みます）。`KUMI_REMOTE_SCRIPTS_DIR` で上書きできます。

**Kumi の Live 拡張機能。** Live 12.4 以降では、`kumi bridge` は Kumi の拡張機能も Live の Extensions フォルダーに入れます（macOS では `~/Library/Application Support/Ableton/Extensions/kumi.kumi`。Windows では `%LOCALAPPDATA%\Ableton\Extensions` を使いますが、Windows ではまだ確認されていません）。Live は次に開いたときに拡張機能を起動します。拡張機能は、MIDI クリップをアレンジメントに直接書き込み、トラックの一区間をクリアし、トラックのクリップを再生せずにレンダリングし、Live の右クリックメニュー（**Extensions** の下）に **Ask Kumi about this** を加えます。これを選ぶと、クリックしたものが次のメッセージのために固定されます。Developer Mode がオン（Settings → Extensions）のときは Live が拡張機能を一切起動しないので、ブリッジが Kumi の拡張機能を自分で起動します。Kumi は拡張機能がなくても動作します。拡張機能があるか、動いているかは `kumi doctor` が知らせます。

ブリッジをインストールして Live で選べば、`kumi` がそれを見つけて接続します。設定することは何もありません。ブリッジがなくても Kumi は起動し、Live なしでチャットし（**No Live access**）、接続を提案します。`kumi --bridge-config <absolute path>` は自分で用意したブリッジ設定を使い、`kumi --inference-only` は Live なしでチャットします（会話が残るのは `-c` か `-r` で続けたときだけです）。

**Willington。** Willington のファイルを収めたリリースからは、Kumi のブリッジに Willington のネイティブバインディングが入ります。それまでは自分でインストールできます。どちらの場合も、`/willington` でオンにするまではオフです。オンにすると、Kumi はラックのマクロのマッピングとチェーンゾーンの設定もでき、セルフテストが合格していれば Follow Actions も編集できます。Willington のバインディングがある Live のバージョンは、macOS ARM64 の Live 12.4.15b4 と b5（チェーンのゾーンは b5 のみ）と、Windows x64 の Live 12.4.15b5 です。[Willington](WILLINGTON_INTEGRATION.md)を参照してください。

## REAPER や Renoise につなぐ

Kumi は REAPER 7 以降と Renoise 3.5 以降で、macOS、Windows、Linux のどれでも動きます。どちらにも Kumi 専用のブリッジがあります。REAPER が `UserPlugins` フォルダーから読み込む拡張機能（`reaper_kumi`）と、Renoise が設定フォルダーの `Scripts/Tools` から読み込むツール（`com.kumi.Bridge.xrnx`）です。Kumi はそこへ自分のホスト（`daw-mcp-server`。Kumi と同じ場所にインストールされます）を通じてつなぎます。やりとりはこのコンピューターの中だけです。ブリッジは 127.0.0.1 で待ち受け、`~/.kumi` にあるシークレットを使う Kumi にだけ応答します。Control Surface を選ぶ必要はありません。

**セットアップ。** `kumi` を実行し、REAPER か Renoise を開きます。Kumi より先でも後でもかまいません。Kumi は開いている DAW を使います。初回は、セットアップがサインインのあと、Linux でも **Connect to REAPER**（または **Connect to Renoise**）を進めます。Kumi が拡張機能（またはツール）を配置し、DAW を開きます。

- **DAW が開いているとき：** DAW が Kumi のブリッジを読み込むのは起動するときだけで、Kumi が DAW を終了させることはありません。**I'll quit it** を選び、自分で終了してください（先に保存を求められます）。Kumi がブリッジを入れ、DAW をまた開きます。保存したプロジェクトやソングは、DAW の最近使ったファイルの一覧にあります。
- **インストールされていないとき：** 入手先（reaper.fm、renoise.com）を伝えます。入れたら **Look again** で確かめ直します。古い REAPER や Renoise が開いている場合はそう伝え、開いたままにします。
- **一度も開いていないとき：** 自分のフォルダーを作らせるために Kumi が一度開きます。Kumi に頼まれたら終了してください。Kumi がブリッジ付きでまた開きます。
- **Esc** を押すと、Live のときと同じくそのステップは後回しになり、ひとまず DAW なしでチャットします。

`kumi --daw reaper bridge`（または `renoise`）は、同じことをシェルから行います。DAW のフォルダーに書き込む前に確認を求め（`--yes` で事前に確認済みにできます）、ブリッジを入れるか最新にし、DAW が開いていれば再起動するよう伝えます。

**どの DAW を使うか。** `kumi` は、ブリッジがまだ入っていなくても、開いている DAW を使います。複数開いているときは、ブリッジが入っているもの、なければ前回使ったもの、なければ Live を選び、ほかの DAW も開いていればそう伝えます（"Renoise is open too: Kumi works with REAPER. /daw renoise switches to Renoise."）。どれも開いていないときは、ブリッジが入っているもの（複数あれば前回使ったもの）を選び、どれかを開くよう伝えます。Kumi が自分の DAW につながっていない間（またはその DAW にまだ Kumi のブリッジがない間）にほかの DAW を開くと、Kumi はそちらに移ります。入力中や応答待ちでなければ、そう伝えてから閉じ、その DAW でまた開きます。`/daw` は Kumi がどの DAW を使っているかを伝え、`/daw <name>`（`live`、`reaper`、`renoise`）は Kumi を閉じてその DAW でまた開きます。`--daw` と `KUMI_DAW` は常にそれより優先され、そのときは Kumi はその DAW だけを使います。

**Kumi が探す場所。**

- **REAPER：** リソースフォルダー（Mac は `~/Library/Application Support/REAPER`、Windows は `%APPDATA%\REAPER`、Linux は `~/.config/REAPER` か `~/.reaper`）、いつものアプリフォルダーにあるポータブル版の REAPER（アプリの隣に `reaper.ini` があるもの）それぞれ、どこにあっても開いている REAPER、Kumi の拡張機能を入れた REAPER、または `KUMI_REAPER_RESOURCE_DIR` で指定したフォルダーだけ。ほかの場所（別のドライブなど）にあるポータブル版は、開いている間に見つかります。拡張機能は開いている REAPER に入ります。
- **Renoise：** 3.5 以降でいちばん新しい設定フォルダー（`~/Library/Preferences/Renoise`、`%APPDATA%\Renoise`、Linux では `~/.config/Renoise` か `~/.renoise` の中の `V3.5.4` など）、または `KUMI_RENOISE_PREFS_DIR` で指定したもの（`V<x.y.z>` フォルダーか、それを収めたフォルダー）。

**接続。** DAW がブリッジ付きで動いていれば Kumi は自分で接続し、DAW が戻ってきたときもまた接続します。DAW がダイアログやレンダリングで手が離せない間は、Kumi はそう伝え、応答するまで何も変更しません。

**そこでできること。** Kumi はプロジェクトやソングを読み、取り消し付きで変更します（何を変更できるか、取り消しがどう働くかは [REAPER と Renoise](KUMI_CHANGES.md#reaper-と-renoise) にあります）。FOCUS、NOW、HISTORY は DAW 自身のビューに沿って表示されます（[コマンド、キー、画面](KUMI_TUI.md#reaper-と-renoise)）。聴く、自分の変更を判定する、`/loop` と `/goal`、リファレンスに合わせる、インスタントフレーズ、閉じていた間の変化を伝える、手作業をレシピにする、ライブラリーやメモや会話を使う、のすべてを DAW の言葉で行います（DAW ごとの一覧は [Live、REAPER、Renoise で Kumi ができること](DAWS.md)）。REAPER ではアクション、API、Lua（ReaScript）も、Renoise では Lua も実行できます。Max for Live デバイス、Kumi Ears、Willington、Kumi の Live 拡張機能（**Ask Kumi about this**）、Live 自身のコマンド、Live のマニュアルは Live だけのものです。

**バージョン。** Kumi の各リリースには拡張機能とツールが付属し、`kumi update` がそれを最新にします（下の「更新、レポート、アンインストール」）。
Kumi 1.24.10〜1.24.32 には REAPER 拡張機能 0.1.7、1.24.0〜1.24.9 には 0.1.6、1.23.3 には 0.1.5、1.23.2 には 0.1.4、1.23.1 には 0.1.3、1.21.2〜1.23.0 には 0.1.2、1.21.0〜1.21.1 には 0.1.1、1.20.0 には 0.1.0。
Kumi 1.24.10〜1.24.32 には Renoise ツール 1.0.6、1.24.0〜1.24.9 には 1.0.5、1.23.3 には 1.0.4、1.23.2 には 1.0.3、1.23.1 には 1.0.2、1.21.0〜1.23.0 には 1.0.1、1.20.0 には 1.0.0。

## Kumi との作業

Kumi は全画面で動きます。左に会話、右に Live ペイン、下に入力欄があります。FOCUS は Live で触れたものを追い、NOW は Kumi がしていることを表示し、HISTORY はすべての変更をその取り消しとともに一覧表示します。幅が 100 桁未満になると、ペインは会話の下のドロワーになり、Kumi が変更を加えるたびにそこが開きます。Ctrl-\\ で開閉します。`KUMI_UI=plain` を使うか出力をパイプすると、代わりに 1 行ずつのプレーンな出力になり、スクリーンリーダーに向いています。詳しくは[コマンド、キー、画面](KUMI_TUI.md)を参照してください。

まずは「開いている Set を説明して：トラック、テンポ、トランスポート」と試し、続けて、あるトラックにどのデバイスが載っているかを聞いてみてください。「テンポを 124 にして、3-Audio の名前を Bass に変えて」のように変更を頼むと、それぞれの変更が HISTORY に現れ、横に **undo** が付きます。FOCUS でデバイスをクリックするか、Live で何かを右クリックして **Ask Kumi about this** を選ぶと、それを指し示せます。「この Saturator、きつすぎる」のように。

Kumi が作業している間、Enter で追加の指示を伝えられます（今のステップの後にメッセージが読まれます）。Tab は回答の後に送るメッセージ、`/btw` は作業を中断せずに別のことを聞きます。Esc で回答を止めます。終わったステップはそのまま残ります。`/stop` はいつでも Live（クリップ、トランスポート、録音）を止めます。

Kumi が選択を求めるとき（どのトラックか、どのバージョンか）、選択肢が入力ボックスの上に表示されます。番号を押して Enter で答えるか、そのまま自分の言葉で入力してください。

Kumi に何かを見せるには、ファイルをウインドウにドラッグするか、クリップボードの画像（シンセのスクリーンショットなど）を **Ctrl-V** で貼り付けます。「これを作って」のように。それぞれ入力欄の上に表示され、次のメッセージと一緒に送られます。× か、空の入力欄での Backspace で取り消せます。モデルが見られるのは PNG、JPEG、GIF、WebP の画像で、1 枚 3.75 MB まで、1 つのメッセージで合わせて 20 MB までです。参照用の音声、プリセット、Live Set などほかのファイルは、Kumi が使えるようにパスで送られます。画像はそのメッセージとだけ送られます。その後の会話には、保存したものも含めて各ファイルの名前とパスが残りますが、画像そのものは残りません。クリップボードの画像は `~/.kumi/attachments` に 1 週間保存されます。

## バックグラウンドジョブ

Set を変えない時間のかかる作業は、Kumi がバックグラウンドで進めるので、その間も Kumi と作業を続けられます：ウェブでの調べもの、チュートリアルビデオ、Live のマニュアル、あなたのライブラリーや以前の会話、Max for Live デバイスのファイル作りです。

- **始まるとき：** Kumi は何が動いているかを一行で伝え、すぐ次のメッセージを受けられます。頼むこともできます（「これをバックグラウンドで調べて」）し、Kumi に任せることもできます。
- **見る：** ヘッダーに動いているジョブの数（◐ 2 jobs）が出て、**JOBS** タブにそれぞれのしていること、時間、トークンが並びます。`/jobs` でも一覧できます。
- **終わったとき：** 会話にカードが入り、その最初の一行が表示されます（「✓ Job 2 · Burial vocal chops · 5 steps, 3 sources」）。Kumi は次のメッセージのときにそのレポートを読みます。あなたの依頼に必要なジョブ（「これを見て、ベースをあんな感じにして」）は、あなたが選択中、入力中、パネルを開いているとき以外に、ひとりでに続きを進めます。
- **Live は Kumi のもの：** ジョブは調べて書くだけで、Live を読んだり変えたりはしません。変更は Kumi 自身が行い、HISTORY に取り消し付きで残ります。ジョブが読んだものはデータであって、指示ではありません。
- **プラグインのプリセット：** ジョブは組み込みの VST3 ツールで対応するプリセットファイルを作成・編集でき、メインの会話と同じバージョン・書き込み検証が適用されます。ファイルのパスを返し、Kumi がメインの会話で読み込み、設定値の確認と試聴を行います。Live、REAPER、Renoise に対応します。
- **Ctrl-B** で、答えの中の Live を使わない時間のかかるステップ（ビデオ、ページ）をバックグラウンドに移し、答えはそのまま続きます。tmux では Ctrl-B を 2 回押します。
- **止める：** JOBS の行かジョブの詳細で `x`。Esc は答えを止め、ジョブは止めません。Kumi を終了するとジョブは中断され、次回 `/jobs` でもう一度実行できます。
- **離れているとき：** Kumi のウィンドウがほかのウィンドウの後ろにある間は、ジョブの終わりを通知と Live のステータスバーの一行で知らせ、ジョブが動いている間はコンピューターをスリープさせません。
- **設定：** `maxJobs`（同時に三つ）と `workerModel`（ジョブに使うモデル。`/model` の一覧から。指定しなければ会話と同じモデル）。各ジョブのトークンはその行に表示されます。

## Kumi に話しかける

**Ctrl-T** を押して話し、もう一度押します。話した内容が入力ボックスに入るので、Enter で送ります。

- **押している間だけ話す。** Ctrl-T を押したまま話し、離すと止まります。kitty キーボードプロトコルに対応したターミナル（kitty、Ghostty、WezTerm、iTerm2）はキーを離したことを伝えます。それ以外では、Kumi はキーのリピートをたどります。
- **聴いている間**、入力ボックスには点滅する点、時間、レベルメーターが表示されます。Enter で止めてすぐ送り、Esc で破棄します。話し終えてから 3 秒静かだと自動で止まります。一回は最大 2 分です。
- **`/voice`**：開始と停止、止めたら Enter なしですぐ送る設定、話す言語（英語、コンピューターの言語、または任意）、マイク。
- **プライベート。** ffmpeg がマイクを聴き、whisper.cpp が話した内容をあなたのコンピューター上で書き起こします。録音は書き起こしが終わるとすぐに削除されます。
- **必要なもの：** ffmpeg と whisper.cpp（Mac では `brew install ffmpeg whisper-cpp`。Windows と Linux では Kumi が取得します）、そして初めて話すときに Kumi が取得する音声モデル（約 190 MB、ビデオ視聴と共用）と、音楽やノイズが言葉にならないようにする小さな音声区間検出モデル。話す準備ができているかは `kumi doctor` が知らせます。
- **Mac で初めて使うとき**、macOS がターミナルにマイクの使用を許可するか尋ねます。Kumi が聞き取れないときは、その理由（許可がない、無音だけ、小さな音だけ、言葉が聞き取れない）を伝え、直し方を提案します：プライバシー設定か、別のマイクです。
- 話しかけられるのはフルスクリーンのアプリだけです。プレーン表示（`KUMI_UI=plain`）では入力のみです。

## 変更と取り消し

Kumi はリクエストを一つの変更のまとまりとして計画し、一度に実行します。すべての変更は、わかりやすい言葉のタイトル（"Tempo 120 → 124 BPM"）付きで HISTORY に入ります。横の **undo** をクリックするか、`/undo` で最新の変更を取り消すか、Kumi に頼みます。取り消しは、その変更が置き換えたものを正確に元に戻します。戻せない場合（対象がなくなった場合や、一部の設定で、その後に同じものをまた変更した場合）、その行には理由とともに **kept** と表示されます。プラン全体は Live 自身の取り消しでも一つのステップなので、Live で Cmd-Z（Windows では Ctrl-Z）を一回押せば元に戻ります。

Kumi が元に戻せない変更もあります（トラックの削除、クリップのクロップ、ラックチェーンの追加）。HISTORY ではこれらに **kept** と表示されますが、Live 自身の取り消しではやはり戻せます。Kumi が何かを削除するのは、あなたが頼んだとき、またはリクエストがそれを含んでいるとき（「最初からやり直して」「ドラムを差し替えて」）です。

**大きな変更の前にコピー。** プランが 3 番目のステップに達したとき、または何かを削除するステップに達したとき、Kumi は最後に保存された状態の Set をその隣にコピーし（`Song.backup-<date>.als`）、そのことを伝えます。コピーは保存されたバージョンごとに一回です。保存していない作業はファイルに入っていないのでコピーにも入らず、保存していない Set はコピーされません。

**Live の中の Python。** ほかのツールでは届かないところについては、Kumi は Live 自身の API を使って Live の中で Python を実行できます。スクリプトによる変更は Live の取り消しでは一つのステップになりますが、HISTORY には記録されません。Live の取り消しで元に戻せます。

**Live がスクリプトに許していないこと：** マクロやモジュレーターのパラメータへのマッピング（Willington ならどちらもマッピングできます：`/willington`）、アレンジメントのオートメーションレーンの編集。Kumi はそう伝え、回避策を提案します。保存、書き出し、フリーズ、バウンス、グループ化は [Live 自身のコマンド](#live-自身のコマンド)で行います。

Kumi が行えるすべての変更の一覧は[Kumi が Set を変更するしくみ](KUMI_CHANGES.md)にあります。

## 再生、録音、レンダリング

Kumi は、頼まれたとき、または作ったものの確認や披露に役立つときに、Set の再生と停止、クリップとシーンの起動、再生位置の移動、録音を行います。プランが途中で止まった場合（ステップが失敗した、または Esc を押した）、Kumi は自分が始めた再生と録音を止めます。Live が通常の停止を受け付けない場合、Kumi はブリッジの緊急停止を使います。

Live はスクリプトにバウンスの機能を提供していないので、Kumi はリサンプリングでバウンスします。ソーストラック（ミックス全体なら「Resampling」）から入力するオーディオトラックを追加し、必要な長さをアレンジメントに録音して、トラックのアームを解除します。録音はオーディオクリップとして Set に残ります。拡張機能があれば、オーディオトラック自体のクリップを、再生せずにファイルへレンダリングすることもできます（トラックのデバイスを通る前の音）。Live 自身の Bounce to New Track と Bounce Track in Place も、[Live 自身のコマンド](#live-自身のコマンド)を通して使えます。

## Live 自身のコマンド

Live のスクリプトにはまったくない機能もあります。それらについて、Kumi はあなたと同じように Live 自身のメニューを使います：トラックのグループ化と解除、フリーズ・フリーズ解除・フラット化、再生しないバウンス（Bounce to New Track、Bounce Track in Place）、統合（Consolidate）、オーディオから MIDI への変換（メロディー、ハーモニー、ドラム）、ステム分離、MIDI トラックへのスライス、Set の保存（Collect All and Save も）、オーディオや MIDI クリップの書き出し。

Kumi は Live の File メニューを通して Set のファイルも扱います。新しい Set を始めることに加え、Windows では指定された名前とフォルダーで Set を保存する（Save Live Set As）ことと、ファイルを指定して Set を開くこともできます。Mac では Kumi はまだ Live の保存・開くダイアログに入力できないので、この二つは Live であなたに行ってもらうよう頼みます。開いている Set に保存していない変更があると、Live が先に尋ねます。Kumi はあなたの指示どおりに保存するか破棄し、指示がなければあなたに尋ねます。保存先にすでにファイルがあると、Live は置き換える前に尋ねます。Kumi はその答えをあなたに任せます。Live は Set をプロジェクトフォルダーに保存します。プロジェクトではないフォルダーに新しい名前で保存すると、そこに「<名前> Project」を作り、Kumi は Set がどこに保存されたかを伝えます。Set を開く間 Live は Kumi との接続をいったん切りますが、それを頼んだリクエストは新しい Set で続きます。Kumi が `.als` ファイルを自分で書くことはありません。

- Kumi はコマンドの対象を選択し、コマンドを押し、何が変わったかを伝えます。Live がダイアログ（書き出しなど）を開いたときは、チェックボックスも含めてそれを読んで答えます。
- ステム分離では、Kumi は Live のダイアログで頼まれたステム（ボーカル、ドラム、ベース、その他。指定がなければ 4 つすべて）にチェックを入れ、頼まれれば 2 つか 3 つを 1 つのトラックにまとめ、指定があれば High Quality か High Speed を選びます（指定がなければ前回使ったほう）。Separate を押し、Live の処理が終わるまで待ちます。曲全体なら 1 分以上かかります。
- トラックは、Live 12 がスクリーンリーダー向けに提供するアクセシビリティを通して名前で選択されます。Live はそのままの場所にあり、前面に出るものはなく、コマンドは 1 秒もかかりません（バウンスやフリーズは Live がレンダリングするぶんの時間）。
- すでにフリーズされたトラックを再びフリーズすることはありません。Live のコマンドだとそれが取り消されてしまうので、Kumi は先に確認します。
- クリップのコマンドは、セッションのクリップか、Live であなたが選択したクリップに対して働きます。アレンジメントのクリップを Kumi が選択することはまだできません。
- HISTORY に各コマンドが並び、Live 自身の取り消し（Cmd-Z）で元に戻せます。
- **Mac では**アクセシビリティを使います。最初に macOS が尋ねるので、システム設定 › プライバシーとセキュリティ › アクセシビリティで、Kumi を動かしているアプリ（ターミナル）をオンにしてください。オンかどうかは `kumi doctor` が知らせます。**Windows では** Live のメニューバーとダイアログを Windows 自体を通して読み（トラックの選択は UI オートメーション）、設定は不要です。Live のメニューを読めるかどうかは `kumi doctor` が確かめます。Windows の Live の確認ダイアログは、Mac の Save と Don't Save の代わりに Yes、No、Cancel と言いますが、Kumi はどちらでも受け付けます。

## 聴く

Kumi はオーディオファイルと Set のオーディオクリップを聴きます。リファレンストラック、サンプル、バウンス、録音などです。測定するのは次のとおりです。

- ラウドネス：インテグレーテッド LUFS、トゥルーピーク、ラウドネスレンジ
- サブからエアまでの 10 バンドのトーンバランスと、各バンドのステレオ幅
- ダイナミクス、テンポ、キー
- 単音の場合は、そのピッチ、倍音、エンベロープ、動き（テンポに対する LFO のレート）
- ノートのあるパートの場合は、ノートそのもの（最初の 1 分から）。MIDI クリップとして書き込めます

リファレンスがあれば、ラウドネスを揃えてから、いちばん大きな違いを伝えます。会話には、聴いた内容が小さなスペクトルとして、比較結果がリファレンスより何 dB 上か下かとして表示されます。Kumi は WAV と AIFF を自分で読み、MP3、M4A、FLAC などは macOS の `afconvert`、それ以外では `ffmpeg`（Windows では初めて必要になったときに Kumi が取得します）を通して読みます。解析はあなたのコンピューター上で行われ、モデルに送られるのは数値だけで、オーディオが送られることはありません。

**Set を聴く。** トラックやミックスについて尋ねると（「ベースはこもっている？」「キックとぶつかっているのは？」）、Kumi は準備なしに Live の中で直接聴きます：

- **Live が再生中なら**、再生中の音を数秒聴き、トランスポートには触れません。曲全体を聴くときは、再生中でも頭から再生して聴き、Live を止めたままにします。
- **Live が停止中なら**、ループ（またはプレイヘッドから数小節、あなたが指定した部分、あるいは最後のクリップまでの曲全体）を再生して聴きます。聴く時間は、聴く音楽の長さと同じです。
- **Kumi が聴く音は、あなたにも聞こえます。** 聴いている間、Kumi は Main を下げたり、作業中のトラックをミュートしたりしないので、一緒に聴きながら方向を伝えられます。聴くたびに、どの小節を何のために再生するか（「300 Hz をカットしたあと」）を伝えます。
- **複数のトラックを同時に：** それぞれの音と、二つのトラックが同じ帯域に同じくらいのレベルで重なっている箇所。
- **しくみ：** Kumi が持ってくる小さな Max for Live デバイス Kumi Ears です（`kumi bridge` が User Library の Kumi フォルダーに入れます）。Kumi は聴く必要があるときにトラックのチェーンの最後に置き、終わったら取り除きます。音は（下で述べる、止めておく候補を除いて）そのまま通り、Set には何も録音されません。
- オーディションとサウンドマッチの探索も、候補を同じ方法で聴きます。スクラッチトラックもアームも不要です。オーディションであなたに聞こえるのは最初の候補で、ほかの候補は Kumi が録音する間、Kumi Ears が止めておきます。探索ではすべての候補を止めておき、一時停止または終了したときに最良のものを「Kumi · Goal best」に置きます。Max for Live がなければ、Kumi は代わりに録音して聴き、候補はいっしょに鳴ります。

**REAPER のプロジェクトや Renoise のソングを聴く。** Kumi はその部分をオフラインでレンダリングし（再生より速く、前に 1 小節を付けて）、それを聴いてから、あなたにも聞こえるように再生します（最長 1 分）。トラック単体はそれだけでレンダリングします。REAPER ではプリフェーダーのステム、Renoise ではトラックのソロです。

- **REAPER の再生中は**、再生中のマスター出力をそのまま聴けます（既定で 8 秒）。トラック単体はレンダリングします。
- **Renoise の再生中は**、レンダリングすると再生が止まり、Renoise のスクリプトは再生中の音を聴けないので、Kumi はあなたが指定した部分だけをレンダリングします。
- **変更を判定するとき**は、REAPER では最後の ReaLimit（なければ Kumi が加える JS: Volume Adjustment）、Renoise では最後の Maximizer（なければ Gainer）でレベルを合わせます。ゴールとサウンドマッチの探索は、トラックのスクラッチコピー（「Kumi · try …」）で候補を試し、終わったら取り除きます。最良のものは「Kumi · Goal best」に残ります。
- Renoise のデモ版はレンダリングできないので、そこでは Kumi は聴けません。`kumi doctor` がそう伝えます。

## 変更の判定とループ

測れる作業（ラウドネスに合わせたマスタリング、耳に痛いレゾナンスを抑える、ボーカルを前に出す）では、Kumi は自分の変更を信じ込まず、判定します：

- **ゴールはチェックリストになります：** ラウドネスと上限、バランス、リファレンスのプロファイル、あるいは前に出すべき要素を、それぞれ許容範囲付きで。Kumi はまず区間全体を聴き、問題点を挙げます：耳に痛い、またはレゾナンスのある周波数、広がりすぎた低域、ランブル、DC、大きすぎるベースノート、オーバーとクリップ、そしてあなたが指定した要素をマスキングしているもの。
- **マスキングは Main のチェーンの前で測ります：** Kumi は指定した要素を Main のチェーンの前で聴きます。Max for Live があれば、Main のチェーンに入るところのミックスも聴くので（Main の先頭に置く二つ目の Kumi Ears で、聴くたびに外します）、Main に何があってもマスキングを公平に測れます：そこにあるリミッターや EQ は結果を動かしません。Max for Live がなければ Main のチェーンの後のミックスしか聴けないので、マスキングがチェックリストに載るのは、Main のデバイスがオフ、メーター（Spectrum、Tuner）、またはレベルだけを変える Utility（要素もそのレベルで聴きます）のときだけです。それ以外が Main にあると載せず、ランがそう伝えます：要素を前に出す作業は Main のデバイスをオフにして判定し、マスターのラウドネスとピークはそのあと別に判定してください。
- **一度に一つの変更：** 変更のたびに、Kumi はレベルをあるべき所（目標のラウドネス、またはもとのレベル）へ、トラックの最後の Live の Limiter、なければ Kumi が加える Utility で戻すので、前後は同じラウドネスで判定されます。狙った項目が良くなり、ほかに耳で分かるほど悪くなったものがない場合だけ変更を残します（無音などで測れなくなった項目は悪化とみなします）。そのレベルでピークが戻ったりクリップしたりすれば、その変更も戻します。残さない変更は、Kumi の取り消しで元に戻します。
- **数値はコードが選びます。** 変更を選ぶのは Kumi で、その値はコードができるだけ少ない試聴で見つけます：測った内容から計算する EQ（レゾナンスを抑える最小のカット、またはリファレンスの形に近づけるバンド）、一つのノブを追い込む（ラウドネスが合うまでリミッターのゲインを、ディエッサーのスレッショルドを）、一つのノブをその範囲全体でプローブする（7 つの設定をトラックの一時的なコピーで並べて一度に聴き、その反応が目標に届く所に合わせる）、あるいは互いに影響する数個のノブを小さな世代で探索し、各世代を同じように聴きます。プローブと探索には、一つのトラックで判定する実行（`judge` に `track`）が必要で、ミックスでは使えません。ノブがあるトラックで何をしたかは一か月覚えていて、次にそこで追い込むときはそこから始めます。追加するデバイスや動かす量は、それに見合う効果がなければなりません。
- **ラウンドの記録**は、各ラウンドを会話に表示します：狙い、変更、前 → 後の数値、残したか戻したかとその理由、次にやること、それまでの試聴回数。二回続けて変更が効かなかった項目は後回しにし、次の項目に取りかかります。
- **リスニングモデル**があれば、それも前後をモノラルで聴きます（広がりや高域の空気感については尋ねません）。歪んだ、ポンピングした、クリップしたと聞こえ、しかもどちらの順で聴いても前のほうを選んだ変更を退けられます。それ以外の判断はメーターが行います。Gemini の API キー（`GEMINI_API_KEY`）があれば Gemini 自身の一覧から選んだ最新の Flash モデルを使い、なければ OpenAI の API キーで OpenAI の最新のオーディオモデルを使います。`KUMI_LISTENER` で別のもの（`<base URL>#<model>`、たとえばあなたのコンピューター上のモデルサーバー）を指定でき、`KUMI_LISTENER=off`（またはモデルのアドレスではない値）ならメーターだけで判定します。どのモデルが聴くかは、実行の最初のラウンドが伝えます。
- **モデルスロット。** `/slots` で、聴く仕事ごとにどのモデルが担当しているかを表示します：ステム（Live 自身のステム分離）、採譜（Live の変換）、リスニング（上の探し方）、埋め込み（Kumi 自身のもの：スタイルには LAION-CLAP の音楽モデル、エフェクトには AFx-Rep）。`/slots listening gemini`、`/slots listening off`（実行中でもすぐに効きます）、`/slots listening http://127.0.0.1:8080/v1#<model>` のように、ふつうの言葉で入れ替えられます。新しいリスニングモデルはまず既知のクリップで試し、正しく聴き分けたときだけ切り替えます。`/slots back <job>` で入れ替えを戻します。埋め込みは Kumi 自身のモデルランタイムで動きます：`/slots embeddings ~/models/clap.onnx`（スペースを含むパスは引用符で囲みます）や、どのホストでもよい `.onnx` ファイルへの https のリンク（最大 4 GB、Esc でダウンロードを止められます）は、二つの既知の音を聴き分けられたときだけ使います。それはスタイルモデルの代わりになり、エフェクトモデルは Kumi 自身のままです。あとでファイルがなくなると Kumi 自身のものに代わり、そのことを一度だけ伝えます。`/slots embeddings off` で止めます。ステムと採譜はまだモデルファイルを受け付けません。Kumi が読めない `slots.json` があると、リスニングはオフになります。`KUMI_LISTENER` を設定している間は、それがリスニングのスロットより優先されますが、`/slots listening off` なら止められます。
- **モデルが聴くスタイルとエフェクト。** リファレンスがあると、Kumi のスタイルモデル（LAION-CLAP）がそれと実行中の各リスニングを聴き、音をリファレンスのスタイルから遠ざける変更は戻します。音のゴールでは、エフェクトモデル（AFx-Rep）が音のエフェクトについて同じことをします。初めて必要になったときに一度だけ、ディスクに空きがあれば Kumi のフォルダーの `models`（`~/.kumi/models`、または `KUMI_HOME` の下）に取得します（ONNX Runtime 約 10 MB、Windows では 80 MB、モデル約 245 MB。それぞれチェックサムで確認します）。

**リファレンス**も目標になります。ファイル、その入ったフォルダー、YouTube の動画や再生リスト、Spotify のリンク、あるいは言葉（「Burial みたいに」「ダブテクノ」「Kid A」）を渡すと、Kumi は例になるトラック（アーティストの代表曲、アルバムの曲、ジャンルの主なアーティスト）を見つけて一曲ずつ測り（無音や −45 LUFS 未満の静かなトラックと、フォルダーや検索では 30 秒未満のスケッチは除きます）、トラックが収まる範囲を持つプロファイルとして保存します。「そのスタイルの中」とはその範囲の内側のことです。言葉が複数の意味に取れるとき（同じ名前のアーティストが二組いる、アルバムとアーティストが同じ名前など）は、どれのことかを一度だけ尋ね、その答えで決まります。各リファレンスは一度だけ測られ、`~/.kumi/references` に保存されます。ファイルやフォルダーは、中のファイルが変わると測り直します。リファレンスの一つの要素（ベースやドラム）については、トラックを Set に入れ、Live のステム分離でステムに分け（Kumi がトラックのクリップのクリックを頼むことがあります）、そのステムを測れます。

**パートのノリ**は、聴かずにノートで判定します：小節のどこで鳴るか（Drum Rack のパートは五つのレーン：キック、スネア、ハット、シンバル、パーカッション）、各ステップがどれだけ前か後ろか（プッシュとスウィング）、アクセント、シンコペーション、フィルを、リファレンスの MIDI と比べます。レコードのドラムなら、Kumi はまずステムに分け（Kumi が頼んだらトラックのクリップをクリックしてください）、ドラムのステムを Live の Drums to MIDI で MIDI に変換し、各ヒットをステムの実際のオンセットに合わせます。Live の外にある音程のあるパート（オーディオファイルのベースラインなど、その最初の 2 分）は、Basic Pitch でノートにし、そのノートに合わせたグリッド（テンポと最初のダウンビート）に置きます。オーディオからは、タイミングとスウィングを比べ、アクセントは比べません。フィルには 8 小節以上が必要です。Kumi はあなたのノートをステップごとにリファレンスへ近づけることもでき、ほかが離れずに近づいた変更だけを残します。

**曲の構成**は小節ごとに聴きます：エネルギーの推移（ラウドネス、密度、明るさ、低域）、各セクションの役割と繰り返し、セクション間のつなぎとドロップの準備、イントロ・アウトロ・最初のフック、どのトラックがどこで鳴るか（64 トラックまで）。うまくいっていない点も挙げます：対比のないセクション、エネルギーの停滞、半端なフレーズの長さ、準備なしに来るドロップ、32 小節以上変わらないループ。リファレンス曲があれば、構成の違いを示します。

**音そのもの**も、ほかのトラックと並べて一度に聴いて測ります：アタック、拍に対する減衰、明るさ、808 やキックのピッチの下がり幅、うねりの速さ（何拍で一周するか）、温かさ（2 次・3 次倍音）、広がり、高域の伸び、ノイズフロア、テールの残り方、クラックル。ノートの頭のクリック、DC、飛び出すノートも指摘します。キットはひとまとまりで判定します：ノイズフロアや高域、ざらつきが浮いているピース、重なり合うピースや隙間、次のヒットまで鳴り続ける減衰。キックに対しては、各パートがどれだけダッキングしてどれだけ早く戻るか、ヒットが噛み合うかぶつかるかを示し、キーを伝えればベースラインのノートがキーからどれだけ外れているかを示します。エフェクトも聴いたものから読み取ります：リバーブの減衰時間とテールが暗く・広くなる度合い、ディレイのエコーの音価・リピート回数・1 回ごとの減衰、レベルの揺れの深さ、フィルターが動く幅、拍に対するポンピング、小節ごとのテールの割合。途切れたテール、テンポに合わないエコー、消えないリピート、ドライのヒットを埋もれさせるテールも指摘します。リファレンスの音やエフェクトに近づけるよう頼めば、測った差をラウンドごとに縮め、近づいた変更だけを残します。

`/loop` に到達したい目標を付けると、達成するまでラウンドで作業します：一つの変更を判定し、次の目標へ。止めるのはモデルではなく Kumi です：すべての項目が許容範囲に入ったとき、変更が効かなくなったとき、または 16 ラウンドか 45 分が過ぎたとき。チェックリストは最初に決めたまま変わらず、モデルが判定を終えるのは Kumi が求めたときだけです：区間全体をもう一度聴き、何が変わったかを伝えます。モデルが自分で変更を判定すると、Kumi は同じループを自分から始めます（測るだけでは始まりません）。Esc か `/loop stop` で止まり、あなたのメッセージも、それに答えたあとでループを止めます。残した変更はそのままです。

`/goal` に到達したい目標を付けると、達成するまでターンをまたいで一つのゴールを続けます。ターンのたびに Kumi が確認します：判定で測ったときはその数値で、そうでなければモデル自身の確認で。その確認は、完了、ブロック（とあなたが先にすべきこと）、継続（と次の一歩）のどれかを答えなければなりません。12 ターン、1 時間、または近づかないターンが 3 回続くと止まり（判定の数値では 1 ステップ以上、それ以外では Set の変更が前進です）、どこまで来たかを伝えます。あなたが直すべきエラー（サインイン、請求、モデル、設定、Live、6 時間より先にリセットされるプランの上限）ではブロックとして止まり、何をすればよいかを伝えます。もっと近い上限は待つか、フォールバックが続けます。ターンが Kumi のおすすめの選択肢付きの質問で終わり、誰も答えないときは、1 分後（`answerAfter`）に Kumi がそれを選び、ゴールは続きます（`/goal answer: <words>` で同じことを手で行えます）。実行中にあなたがメッセージを送ると、それに答えてからゴールはあなたを待ちます。GOAL タブには、ゴール、予算に対するターン数と時間、最後の確認、次にやることが表示されます。`/goal` だけで表示し、`/goal edit <words>` で変更、`/goal resume` で（使い切ったぶんだけ新しい予算で）再開、`/goal pause` か Esc で一時停止、`/goal clear` で終了します（終わっていないゴールがなければ、一時停止中のサウンドマッチの探索を終えます）。終わっていないゴールがあるときに別の `/goal` を送ると、まず確認します：もう一度送るか `/goal new: <words>` で置き換えます。ゴールは Set ごとに保存され、再起動後も残ります。未保存の Set のゴールは、その Set が開いている間（Kumi の再起動や新しい会話をまたいでも）Live の Set の識別で保存され、Set を最初に保存したときに一緒に移ります。

## リファレンスに合わせる

何かをリファレンスのような音にするよう頼むと（「ベースをこれみたいな音にして：~/refs/bass.wav」）、Kumi はそれを当て推量ではなく探索として扱います。リファレンスを聴き、2〜4 通りの異なるバージョンをそれぞれ別のトラックに作り、まとめてレンダリングして、それぞれをリファレンスと比べて採点します（0〜100、最も大きな違いとともに）。あなたに聞こえるのは最初のバージョンで、残りは Kumi だけが聴きます。続けていちばん良いものを磨き、どのノブでも埋まらない差があれば構造を変え、目標に届いたとき、新しいアイデアが効かなくなったとき、または 12 ラウンドか 45 分が過ぎたときに止めます。最後に、前後のスコアと、まだ違う点を伝えます。

`/loop` に合わせたい音を付けると、さらに先まで進みます。Kumi は、主に自前の高速なノブ探索で、数世代ごとにモデルの大きなアイデアも交えながら、スコアが 95 に達するか、あなたが止めるか、4 時間が過ぎるまで探索を続けます。進み具合は GOAL タブに表示されます。Max for Live があれば、Kumi は試している候補を止めておくので、候補を除いた Set が聞こえます。最良のものは、探索を一時停止または終了したときに「Kumi · Goal best」に置かれます。Esc で探索を一時停止し、`/loop` だけを入力すると（再起動後でも）再開し、`/loop stop` で終了します。

各マッチングから Kumi が学んだことは、次回のためにレッスン（✦）として保存されます。`/memory` で一覧表示できます。

## アレンジメント

ループを一曲にするよう Kumi に頼めます：「これをアレンジして」「このシーンから 3 分のアレンジメントを作って」、あるいはファイルを添えて「このリファレンスのようにアレンジして」。

- **素材。** セッションのシーン（セクションはシーンのクリップか、トラックごとに選んだクリップを再生します）、またはアレンジメントにすでにある小節（その MIDI クリップ）。
- **構成。** 名前と小節数を持つセクション。指定がなければ、Kumi はジャンルとテンポに合う構成を選びます。リファレンスがあれば、その構成（セクション、各セクションのエネルギー、どれが繰り返されるか）を聴いて写します。
- **変化。** トラックはセクションごとに入ったり抜けたりします。つなぎは、ドロップ前の空白、セクション終わりのトラックのフィル、次のセクションの頭で終わるライザーやクラッシュ（エフェクトトラックのクリップか、あなたのサンプル）です。頼まれない限り、Kumi が新しいパートを書くことはありません。
- **Live では。** クリップはアレンジメントの既存の内容の後ろ（または指定した場所）にコピーされ、各セクションにロケーターが付き、プレイヘッドが先頭に移ります。
- **取り消し。** アレンジメント全体が HISTORY の 1 行で、取り消しも一回、Live でも Cmd-Z 一回です。
- **制限。** Live のスクリプトはアレンジメントにオートメーションを描けないので、フィルターのスイープや音量の変化はあなたが描きます。アレンジメントにすでにあるオーディオクリップはそこではコピーできないので、先にセッションのスロットにドラッグしてください。Live の再生中は、ロケーターは待ちます。

[アレンジのしくみ](KUMI_CHANGES.md#アレンジメント)を参照してください。

## プラグイン

- **組み込みの VST3 プリセット。** プリセットの作成や編集を頼むと、Kumi は外部を調べる前にローカルの形式カタログを確認します。対応するプリセットは履歴と取り消し付きで読み込めます。Serum 2、Ozone 12 と各モジュール、Valhalla、Minimal Audio、Pulsar Modular などの対応バージョンと制限は[形式一覧](../../plugin-formats/README.md)を参照してください。
- **インストール済みの処理を優先。** マスタリングやリファレンスとの比較では、まず Ozone 12、次に適切な VST3、最後に DAW 標準のデバイスを確認します。変更の前後で測定・試聴し、リファレンスは音量をそろえて比較します。
- **ネイティブファイルの制限。** Softube と一部の Zynaptiq は内容の確認、テンプレートの複製、プリセット名の変更に対応し、未検証の数値パラメータは読み取り専用です。未検証の製品の VST3 状態読み込みは保証しません。Live ではブラウザーから新しいインスタンスを読み込み、既存のインスタンスは公開されたパラメータで変更します。
- **検証済みの書き込み。** インストール済みのバージョンが検証済みライターと一致する必要があります。数値の編集には検証済みの範囲が必要です。文字列と真偽値の編集には検証済みの意味または明示的な許可リストが必要で、リソースのパスは読み取り専用です。新しいファイルは Kumi のプリセットフォルダーに保存します。Live の User Library にもコピーを保存し、読み込んだデバイスを取り消してもそのファイルは残ります。

Serum 2、Vital、Ozone 12、Pro-Q 4、Pro-L 2、Saturn 2、Decapitator、OTT、Supermassive、Pigments には詳しいガイドもあります。作業の前にそのプラグインのガイドを読みます：何をするものか、各セクション、よくある音のレシピ、そしてプラグインが Live に見せている実際のパラメータとの照合です。

- **プラグイン自身の単位で値を指定：** 「800 Hz」「-6 dB」「35 %」、またはメニューの項目名（「Saw」）。プラグイン自身の表示に合わせて設定されます。
- **Live が見せるパラメータ。** Live では、プラグインの設定済みのパラメータだけを Kumi が動かせます。ガイドはどれがそうか、そして追加のしかたを伝えます：プラグインのタイトルバーの **Configure** をクリックし、ウィンドウでノブを一度動かします。プラグインのウィンドウは Kumi が開けます。
- **役割でノブを指定。** Kumi がプラグインを調整するとき、ノブを役割で指定できます：ガイドにある役割（Ozone 12 の ceiling）や、どのデバイスにもある仕事（リミッターのゲイン、その上限、EQ バンドのゲイン、コンプレッサーのスレッショルド）。プラグインが Live に見せている名前の中からノブを探し、設定済みのときだけ動かします。設定されていなければ、どのノブを設定すればよいかを伝え、その間は同じトラックの別のデバイスにその仕事をさせます：まず Ozone 12、次に Kumi が知っているほかのプラグイン、最後に Live 自身のデバイス。EQ Eight の EQ バンドは、変更が狙う周波数から約 1 オクターブ以内にある、オンになっているバンド（ゲインならベルかシェルフ）のうちいちばん近いものです。なければ Kumi がどのバンドかを尋ねます。トラックにどれもなければ、Live 標準のデバイスの前に適切なインストール済み VST3 を確認します：リミッターは最後、EQ やコンプレッサーは最後のリミッターの前。
- **公開されていないパラメータ。** まず組み込みのプリセット形式で設定できるか確認します。形式の範囲外の操作や Ozone の Master Assistant のような対話機能はプラグインのウィンドウで行います。場所はガイドが示します。
- **ウェーブテーブル。** Kumi は波形と倍音から、または音から切り出して、Serum、Vital などのウェーブテーブルシンセ用のウェーブテーブルを作り、プラグインのフォルダーに入れます。オシレーターにドロップして使います。

ほかのプラグインも、パラメータ名で扱えます。

## ビデオチュートリアルを見る

Kumi にビデオを渡し、その内容を作るよう頼みます。ビデオは YouTube のチュートリアル（または [yt-dlp](https://github.com/yt-dlp/yt-dlp) が読めるほかのサイト）か、コンピューター上のビデオファイルです。

> これを見て、ベースを新しいトラックに作って：https://www.youtube.com/watch?v=…

Kumi はビデオのタイトル、チャプター、言葉を読みます。言葉は字幕から、字幕がない場合は音声から取り出し、あなたのコンピューター上で文字起こしします。続いて、ナレーションがデバイス、設定、値に触れている場面のフレームを見ます。値を読む必要があるときはアップで見ます。そして、ビデオが何を作っているかを数行で伝え、あなたの Set の中でそれを作ります。ビデオがあなたの Set にないもの（プラグイン、サンプル）を使っている場合は、そう伝えて、いちばん近い Live のデバイスを使います。

1 回の回答の中で、Kumi がすでに 3 回見た場面はもう見せません。1 本のビデオで見る画像は最大 240 枚です。「使っている設定を全部」のような長い依頼でも、同じフレームを見直し続けず、読み取れたことと読み取れなかったことを伝えて答えます。

必要なもの：

- **yt-dlp**：初回に Kumi が `~/.kumi/tools` に取得します（約 35 MB、リリースのチェックサムで確認）。その後も毎月取得し直します。 JavaScript の処理が必要な動画では、Kumi は旧インストーラーから残した Node を優先し、次に PATH 上の `node` を探して yt-dlp に渡します。新規のネイティブインストールにはこの任意のランタイムは付属しません。一部の YouTube 動画で必要です。
- **ffmpeg**：フレームと音声に使います。Mac では `brew install ffmpeg`、Windows では初回に Kumi が取得します（約 170 MB、確認付き）。ない場合、Kumi はビデオの言葉だけを読みます。YouTube には ffmpeg 8.1 以降を使ってください。YouTube の求めるとおり、ストリームを少しずつ要求します。古い ffmpeg では、YouTube が転送をごく遅くしたり、拒否したりすることがあります。
- **whisper.cpp**：字幕のないビデオにだけ使います。Mac では `brew install whisper-cpp`、Windows では Kumi が取得します。その音声モデル（約 190 MB）は初回に取得します。

ffmpeg と whisper.cpp があるかどうかは `kumi doctor` が知らせます。ビデオを丸ごとダウンロードすることはありません。フレームと音声は、Kumi が見る時点のぶんだけビデオのストリームから取り出します。最近の 24 本のビデオは `~/.kumi/videos` に保存されるので、同じビデオをもう一度見るときはすぐに済みます。ビデオの言葉や映像は Kumi にとって情報であり、Kumi への指示として扱われることはありません。

## Max for Live デバイスを作る

Live にないデバイスを自分の言葉で頼めば、Kumi が作ってトラックに載せます。

> 各コードのいちばん低いノートだけを残す MIDI エフェクトを作って、Keys トラックに載せて

> Erbe-Verb みたいな音のオーディオエフェクトを作って

Kumi は、あなたがわざわざ指定しないような細部を決め、何を選んだかを伝えます。既存のデバイスのように動くべき場合は、まず元のデバイスがどう動くかを調べます。デバイスは User Library の Kumi フォルダー内、種類ごとの Audio Effects、MIDI Effects、Instruments に入り、Live のブラウザにほかのデバイスと同じように表示されます。ノブは必要なだけ付きます（最大 3 行）。ノブは通常の Live のパラメータなので、オートメーションやマッピングができます。デバイスの読み込みは、取り消し付きの変更として HISTORY に入ります。

MIDI エフェクトは JavaScript で書かれます。作る前に、Kumi はそのコードをあなたのコンピューター上で、自分で書いたテストと独自のチェック（エラーがない、すべてのノートが解放される、何も動いたまま残らない）に対して実行し、失敗したら修正します。オーディオエフェクトとインストゥルメントは、Max の gen~ の言語である GenExpr で書かれます。エフェクトには Mix と Output のノブが付き、インストゥルメントは同時に 8 音、または最大 32 音まで鳴らせます。どちらも最後に Kumi の出力段を通り、出力を安全に保ちます（NaN、デノーマル、DC なし、+6 dBFS 未満に抑制）。Kumi は作ったものを聴き、聴こえた問題を修正します。

ノブ以外の見た目（パネル、文字、色）は Max が描くので、Kumi には見えません。ユーザーライブラリのデバイスが読み込まれると、Kumi はその見た目を読み、パネルが何を隠しているか（ほかより先に並んだ背景がそれらを覆うこと）を知らされます。だから、あなたに見えないデザインを説明することはありません。

Kumi は、すでにあるデバイスも変えられます。Kumi が作ったもの、あなたが作ったもの、ダウンロードしたもののどれでも構いません。

> Echo に同期スイッチを付けて

Kumi はデバイスを読み、その変更だけを加え、結果を新しいデバイスとして Kumi フォルダーに保存します（名前を指定しなければ「Echo 2」）。元のファイルには一切書き込まないので、それを使っているどの Set もそのままです。変更が触れない部分は Max が保存したとおりに残り、フリーズされたデバイスは中のファイルをそのまま持ち、新しいデバイスにはどのデバイスから作ったかが記録されます（User Library 内の場所か、ファイル名だけ。あなたのコンピューターのフォルダーは記録しません）。Live 自身の Max for Live デバイス（LFO、Shaper など）はロックされているので、Kumi は開けません。元のデバイスの代わりに使うよう頼めば、Kumi は新しいデバイスを元のデバイスの隣に読み込み、共通のノブを同じ値にそろえ、元のデバイスをオフにします。元のデバイスのオートメーションとマッピングは新しいデバイスに移らないので、元のデバイスを取り除くのはあなたが指示したときだけです。

Max for Live（Live Suite、またはアドオンを追加した Standard）が必要です。

## 調べる

ハードウェア、プラグイン、エフェクトのアルゴリズム、アーティストのテクニックなど、Kumi が十分に知らないものの名前を挙げると、Kumi はウェブを検索し、見つけたものを読みます。

- **検索**には、キー不要の無料検索サービス（Exa、Parallel、Keenable、Firecrawl を順番に使い、どれも応答しないときは DuckDuckGo）を使い、コードには GitHub を使います。20 分以内の同じ検索は繰り返しません。
- **読み込み**は、ページ、PDF、テキストやコードのファイル、GitHub リポジトリ、Max パッチ、Max for Live デバイス、そして画像（モデルが見ます）に対応しています。
- Live に触れない**検索や読み込み**（ウェブ、サウンド、プリセット、あなたの Set、Live のマニュアル、以前の会話）は、最大 4 つまで同時に実行します。Live への変更は、これまでどおり 1 つずつ実行します。

Kumi が調べたものは、回答の上に 1 行ずつ表示されます。読むのは公開されているアドレスだけで、あなたのコンピューターやネットワークを読むことはありません。ページに書かれていることは情報として扱い、指示として扱うことはありません。

## あなたのライブラリー

Kumi はあなたの持っているものを知っているので、「このリファレンスのような埃っぽいスネア」「いつものボーカルチェーン」「Night Drive の Set のベース」と頼めます。

- **探す場所。** Live の User Library と Places、Live がインストールしたパック、Core Library、Splice のフォルダー、そして `settings.json` に書いたフォルダー（`"libraryFolders": ["~/Samples"]`）。リクエストで名前を挙げたフォルダーは次に学習されます。Set は Live が最後に開いた場所とその近くから見つかります。
- **学習するもの。** 音ごとに：長さ、ワンショットかループか、ループのテンポ、キーや音程、ラウドネス、明るさ、エンベロープ、何の音か（キック、スネア、パッド、ボーカル、FX など）、似た音を見つけるための指紋。プリセットごとに：デバイスと種類。Set ごとに：テンポ、キー、トラック、チェーン、プラグイン、リターン、クリップ、使っているサンプル。
- **邪魔をしない。** 学習は Kumi の起動数秒後に、最低の優先度の別プロセスで自動的に始まり、Live の再生中は止まります。初回以降は新しいファイルと変わったファイルだけを学習し、途中で止まっても何も失いません。
- **見つけ方。** 言葉、種類、テンポ、キー、長さ、またはファイル・クリップ・レンダリングしたトラックにどれだけ近い音か。プリセットはデバイスと種類で、Set はテンポとキーで。「Live で…するには？」には、Ableton の Live 12 マニュアルから該当セクションを示して答えます。
- **あなたの Set から。** Kumi はあなたの作業のしかたを学びます：テンポとキー、トラックの種類ごとの楽器といつものチェーン、よく使うプラグイン、リターンとメインのチェーン、トラックの名前と色の付け方。`/memory` の「From your Sets」に並び、忘れさせた行は忘れたままです。
- **進み具合。** `/status`、ウェルカム画面、`kumi doctor`、`kumi library` が知らせます。`kumi library --rebuild` ですべてを学習し直します。`~/.kumi/library` に、あなただけが読めるように保存されます。

## あなたの音楽

Kumi はあなた自身の音楽からあなたの好みを、あなたのコンピューター上で学べます。スタイルを指定しないリクエスト（「ビートを作って」「何か暗いもの」）では、その好みを頼りにします。リファレンス、音、値を指定したときは、そちらに従います。

- **尋ねるのは一度だけ。** スタイルを指定しないリクエストが初めてあったとき、Kumi は見つけた曲の数（ミュージックのフォルダー、iTunes のフォルダー、または `~/Music`。Windows ではミュージックフォルダー）を伝え、そこから好みを学ぶかどうかを尋ねることがあります。断ればもう尋ねません。`/music add <folder>` でいつでも始められます。
- **学習するもの。** 曲ごとのタグ（アーティスト、アルバム、タイトル、ジャンル、年）、タグがなければフォルダーから取った名前。それからバックグラウンドで、どう聞こえるか：ラウドネス、明るさ、低域、ダイナミクス、響き、そしてスタイルの指紋。まずアーティストをまたいだ曲の見本を通して聴き（約 1 時間）、次にすべての曲を 1 分ずつ新しい順に、最後に 1 曲ずつ通して聴きます。
- **邪魔をしない。** Kumi のライブラリー学習プロセスの中で最低の優先度で動き、DAW の再生中（Kumi が聴いている間も含む）と、コンピューターがバッテリーで動いている間は待ち、止まったところから続けます。30 秒未満の曲とほとんど無音の曲は飛ばし、Apple の保護された購入曲は名前だけを知り、聴きません。
- **あなたの音楽のように。** あなた自身のスタイルで（「自分の曲みたいに」）と頼むと、Kumi はあなたの曲のうち近いもの（5〜10 曲、通して聴いたもの）をリファレンスとして保存し、ほかのリファレンスと同じようにそれに近づけていきます。
- **言葉で。** スタイルを言葉で伝える（「メランコリックなダブテクノ」）と、Kumi はあなたの音楽からそのように聞こえる曲を見つけます。使うのはスタイルモデルの言葉の側で、初めて使うときに取得します（約 127 MB）。あなたのスタイルにも同じように、約 200 のジャンルとムードの言葉から名前を付けます。`/slots` でほかの埋め込みモデルを使っているときは、言葉は曲のジャンルタグと照らし合わせ、Kumi はそう伝えます。
- **モデルに届くもの。** あなたが頼んだものに近い曲の名前（アーティスト、タイトル、アルバム）と、それらに共通することを述べた 1 文。ファイルや指紋は届きません。Kumi があなたの好みを使うとき、曲名とアーティスト名がモデルに届きます。
- **保存場所。** `~/.kumi/music` に、あなただけが読めるように保存されます。`/music` でフォルダー、聴いた曲の数、進み具合を表示し、フォルダーの追加と削除、一時停止と再開ができます。`/music forget` ですべてを削除します。
- **地図で。** `/map` はあなたの曲をスタイルごとに、ライブラリーのサウンドを種類ごとに、似て聞こえるものどうしを近くに並べて描きます。矢印キーで動き、Space で、またはマウスを点の上に動かして点を聴けます（[キー](KUMI_TUI.md)）。そこでサウンドを拾い（ボックスのドラッグか `x`）、Enter でパレットに入れられます。パレットはセッションをまたいで残ります（`/palette`）。Kumi は依頼のたびにパレットを読むので、「パレットからもっと暗いキックを」のように頼めます。
- **ブラウザーで。** `/map open` で同じ地図をブラウザーに表示します。点にポインターを合わせると名前が出て、ホイールでズーム、Shift を押しながらドラッグ（または Lasso）で点を選び、絞り込み、クリックで聴けます。アクションは Kumi の入力欄に言葉を入れ、Add to palette は拾った点をパレットに入れます。ページはあなたのコンピューターだけから（127.0.0.1、ランダムな鍵の付いたリンクで）届き、点はファイルのパスではなく地図上の位置で再生します。`/map close` で閉じ、Kumi を終了しても閉じます。SSH 越しでは、つなぎ方を Kumi が伝えます。

## Kumi が覚えること

Kumi が保存するものはすべて、その場で表示されます。会話の中の 1 行と、HISTORY タブの先頭にある **forget** 付きの行です。`/memory` ですべてを一覧表示し、項目を選ぶとそれを忘れさせられます。メモを選べば、言葉を変えたりピン留めしたりもできます。

- **メモ**（✎）：Live では表示できない、あなたが Kumi に伝えたこと。たとえば、トラックの用途、目指している方向、あなたの癖や好みなど。あなたについてのメモは `~/.kumi/memory.json` に、保存済みの Set についてのメモは `~/.kumi/projects` の中のその Set のフォルダーに入ります。それぞれの場所に最大 24 件、1 件 1 文で、いっぱいになるとピン留めしていないうち最も古いものが消えます。Kumi は、Set を見ればわかること、自分がしたこと、指示のように読めるものやキーのように見えるものは保存しないので、Set の中のテキストが常設の命令になることはありません。
- **テクニック**（◆）：Kumi が作ったものの背後にある考え方。のちに同じ種類の音に応用するために保存します。作ったものが再利用に値するとき、Kumi は答えのあとで保存するかどうかを尋ねます。1 で保存し、2、Enter、Esc、または答えずに先へ進んだ場合は保存しません（次のメッセージで「テクニックを残して」と言えば保存できます）。Kumi の取り消しでその作業を取り消すと、質問も取り下げられます。尋ねるのはあなたが頼んだ作業についてだけで、`/goal` や `/loop` に向けた作業や、Kumi 自身が直前に質問したときには尋ねず、答え 3 回につき多くても 1 回です。あなたが示したチュートリアル、リファレンス、手順が常に優先されます。Kumi がテクニックを使うのは、やり方をあなたが指定しなかったときだけで、使うときはそう伝えます。最大 40 件、`~/.kumi/techniques.json` に入ります。テクニックは DAW ごとには分かれていません。Live で学んだテクニックは、REAPER や Renoise では応用するためのアイデアとして提案されます。
- **レシピ**（↻）：どの Set でも再実行できる作業のしかた。たとえばボーカルチェーンやリサンプリングのループなど。今やったことを残すよう Kumi に頼むか、手順を説明するか、「見てて」と言って Live で手作業し、終わったら伝えます。Kumi は変わったことを、毎回異なる部分を空欄にしたレシピにします。レシピは名前で頼むと実行され、`/recipes` も使えます。`~/.kumi/recipes` に 1 件 1 ファイルで保存されます。REAPER と Renoise のレシピは別に保存され（`~/.kumi/recipes/reaper`、`~/.kumi/recipes/renoise`）、その DAW の変更でできていて、その DAW でだけ提案・実行されます。
- **レッスン**（✦）：Kumi が音のマッチングで学んだこと。次のマッチングで使います。最大 60 件、`~/.kumi/playbook.json` に入ります。

Kumi のツールや Live のスクリプト機能にないものがリクエストに必要な場合、Kumi はそう伝え、回避策を提案し、足りない機能を Kumi の開発者向けに `~/.kumi/gaps.jsonl` に記録します。この記録が会話に読み戻されることはありません。`kumi report` を送ると決めたときに、そのレポートに含まれます。

Kumi は、各回答の時間の内訳（モデル、ツール、Live へのリクエスト、送信したバイト数、モデルに尋ねる前に Set を見た時間）も `~/.kumi/timings.jsonl` に最新のおよそ 1000 件を記録します。ギャップの記録と同じく、あなたのコンピューターに残り、外に出るのは `kumi report` を送るときだけです。

## 会話と、離れていた間の変化

Kumi は各 Set の会話を `~/.kumi/projects` に保存します。回答のたびに保存し、それぞれ約 256 KB まで（古いやりとりから消えます）。それぞれの会話の横には、その中で起きたことの記録も保存されます（最大 32 MB。言葉の中のキーは取り除かれます）。保存済みの Set で Kumi を開くと、その最新の会話の続きになり、HISTORY には直近 100 件の変更が（取り消しなしで）表示されます。`/new` で新しく始めると、直前の会話は残ります。保存していない Set の会話は、初めて保存したときにその Set 自身のフォルダーに移ります。

- **戻る：** `/resume`（または `/conversations`）でこの Set の会話を一覧表示し、Tab ですべての Set の会話を表示します。入力で絞り込み、Enter でその会話に戻り、ctrl+f で名前の変更、ピン留め、削除、ID のコピーができます。
- **シェルから：** `kumi -c` は、どの Set のものでも、最後に使った会話の続きから始めます。`kumi -r <ID または名前>` はその会話の続きから始めます（ID は先頭だけでも足ります）。`kumi -r` だけなら一覧から選べます。どちらも `--inference-only` と一緒に使えます。
- **ID：** すべての会話に `mv66me0m3fa91c` のような ID があります。`/status` で表示され、その会話を使ったときは、Kumi が閉じるときに「Continue this conversation: kumi -r mv66me0m3fa91c」と伝えます。
- **名前とコピー：** `/rename <name>` でこの会話に名前を付け、`/new <name>` で名前を付けて新しく始め、`/fork` でコピーに続けます（元の会話は残ります）。
- **別の Set の会話：** Kumi はまず尋ねます。その Set を Live で開く（Live が開いている Set について尋ねることがあります）、ここでコピーとして続ける（別の Set から Kumi が読んだ内容は除きます）、またはキャンセル。Live が閉じているときはそのまま続け、Live が別の Set を開いたときに尋ねます。
- **二つの Kumi ウインドウ：** 一方で開いている会話は、もう一方ではコピーとして続きます。
- **モデル：** 戻っても今使っているモデルのままです。会話が別のモデルで行われていたときは、Kumi が一度だけ伝えます。
- **残す期間：** 各 Set は最新の 20 件、過去 90 日以内に使った会話（`conversations.keepDays`。`0` ですべて残す）、ピン留めした会話を残します。設定から `keepDays` を外すと、90 日と最後に設定した値のうち長いほうで残します（`0` ならすべて残したまま）。ロールバックした後の Kumi 1.16 以前は、各 Set の最新 20 件だけを残します。アップデート前から開いている Kumi のウィンドウも、閉じるまでは同じです。
- **共有：** `/export` はこの会話を Markdown としてコピーするか、Markdown、Web ページ、Kumi 用のファイルとして保存します（`/export copy`、`md`、`html`、`json` でそのひとつをすぐに行います）。`/share` は Web ページを保存し、それを開く、Finder（エクスプローラー）で表示する、パスをコピーする、のいずれかを選べます。ファイルは Kumi を起動したフォルダーに会話の名前で保存され、ほかのファイルを上書きすることはありません。macOS と Linux では、あなただけが読めます。
- **書き出す内容：** あなたと Kumi の言葉、各ステップの名前、HISTORY の変更（Web ページでは図付き）。キー、トークン、ホームフォルダー、アカウント名は取り除かれます。Live の詳細、あなたのメモ、Kumi からモデルへのメモ、モデルの推論は書き出されません。Web ページはインターネットから何も読み込みません。
- **シェルから：** `kumi export [ID または名前]` は Markdown（`--md`、既定）、`--html`、`--json` で保存します。ID を省くか `--last` を付けると、最新の会話です。`--full` で各ステップの入力と結果も加わり、`-o <パス>` で保存先を選べ、`--raw` はキーやパスを残します（そう伝えます）。`kumi import <ファイル>` は `--json` で保存したファイルを取り込みます。`kumi -r <ID>` でコピーとして続けられ、Kumi はモデルに、ファイルから来た会話だと伝えます。

以前のこと（「先週のボーカルのリバーブチェーン」）に触れると、Kumi はすべての Set について保存した会話と、テクニックやレシピを、その言葉で探します。検索はあなたのコンピューターの中で行われ、見つかったものはほかの読み取りと同じようにモデルに送られます。

Kumi は、保存済みの各 Set を最後に見たときの状態も覚えています。次回、ウェルカム画面にその間に変わったことが表示され（"Since you were last here · 3 days ago: Tempo 120 → 124 BPM; Added track “Pad”"）、Kumi はそれを踏まえて作業します。Kumi は Set の中に保存した ID で Set を見分けるので、移動した Set や、同じ Live Project フォルダーに別の名前で保存した Set はそのまま続きます。別の場所に保存したコピーは新しく始まります。

**REAPER と Renoise では**、保存済みの各プロジェクトやソングについても同じです。

- 会話、メモ、離れていた間の変化はそれぞれのものです。保存していないものは、初めて保存するまで DAW の未保存用の場所に置かれ、保存すると保存したものの場所で続きます。
- Kumi は保存済みの REAPER プロジェクトに ID を書き込みます（次に保存したときに REAPER がプロジェクトに残します）。そのため、移動したプロジェクトや、同じフォルダーに別名で保存したプロジェクトはそのまま続きます。元のファイルが残ったまま別のフォルダーに保存したコピーは新しく始まります。
- 別のプロジェクトの会話：Kumi はそのプロジェクトを自分で開くよう伝えます（Kumi からは開けません）。開くと会話が続きます。
- 離れていた間の変化には、REAPER や Renoise が閉じていた間や再起動した間の変化も、DAW の言葉で含まれます。REAPER のトラック、FX、アイテム、マーカーとリージョン、テンポと拍子。Renoise のトラック、デバイス、パターン、インストゥルメント、テンポ、LPB（Lines per beat）、パターンシーケンス。
- 比べる元の状態は `~/.kumi/bridges/reaper/snapshots`（または `renoise`）にあり、あなただけが読めます。削除しても、次回の比較が最初からになるだけです。

## Live がいなくなったとき

Kumi は Live が閉じたりクラッシュしたりすると 1 秒以内に気づき、そう伝えて、会話はそのまま保ちます。2 秒ごとに Live を探し、Live が戻ると自動で再接続します。実行中だったリクエストは入力欄に戻ってくるので、Enter 一回でもう一度送れます。30 秒経っても Live が戻らない場合は、Live が開いていて AbletonMcpBridge が Control Surface として選ばれているかを尋ねます。`/reconnect` はすぐに接続を試みます。

Live がただ忙しいだけのこともあります。大きな Set や重いデバイスを読み込んでいると、しばらく応答しないことがあります。Kumi は AbletonMcpBridge がまだ待ち受けているかどうかで、この二つを見分けます。Live が忙しいときは、Kumi はそう伝えて待ちます。リクエストは取り消されず、Live が応答すると、必要なものを読み直してから続きます。それまでの変更は Kumi の取り消しで引き続き戻せます。Live が別の Set を開いた状態で戻ってきた場合は、自分で Set を開いたときと同じく、リクエストはそこで止まります。

Kumi の取り消しは、Live との接続が続いている間だけ有効です。Live の再起動、再接続、Kumi の再起動の後は、それ以前の変更は **no undo** と表示され、Live 自身の取り消しでしか戻せません。`/new` は接続を保つので、取り消しは引き続き使えます。

**REAPER や Renoise** がいなくなったときも同じように伝えます。Kumi は DAW なしでチャットし、DAW が応答すると自分で接続し直します（"REAPER answered, so Kumi is connected to it now."）。そこでの Kumi の取り消しは最新 400 件の変更を、Kumi と DAW のつながりが続く間だけ保ちます。`/reconnect` や Kumi の再起動の後は、それ以前の変更は **no undo** と表示され、DAW 自身の取り消しでまだ戻せるかどうかがそれぞれに書かれます。

## 更新、レポート、アンインストール

```sh
kumi update                    # 最新の Kumi と、古ければ Live の中のブリッジも
kumi update --check            # 新しい Kumi があるかどうかを伝えるだけ
kumi update --rollback         # 前回の更新より前の Kumi に戻す
kumi update --version 1.15.0   # そのリリースを入れる（新しくても古くても）。--rollback で戻る
kumi doctor                    # インストール、サインイン、ブリッジ、Live、ターミナルを確認
kumi doctor --json             # 同じチェックを JSON で。キーとホームフォルダーは含まない
kumi report                    # 問題が起きたときに送るファイル
kumi uninstall --dry-run       # uninstall が削除するものを伝えるだけ
kumi uninstall                 # Kumi を削除。--all を付けると Kumi に残したものも削除
```

`update` は最新のリリースを取得し、チェックサムで確認し、配置する前に一度起動して動くことを確かめます。一つ前のものは `--rollback` のために残します。

- 約 250 MB の空きが必要で、足りなければダウンロードの前に伝えます。
- 最後まで終えられないときは、理由（接続の原因、GitHub の代わりに Wi-Fi のサインインページが応答した、ディスクがいっぱい）と、何も変更していないことを伝えます。
- `~/.kumi` が別のアカウントのもの（`sudo` で実行したインストール）なら、取り戻すための `sudo chown` の行を示します。
- 最後にバージョン（`1.15.0 → 1.16.0`）と新機能を数行伝えます。残りは Kumi の中の `/changelog` にあります。すでに開いている Kumi のウィンドウについては、ある場合だけ伝えます。
- `--version x.y.z` はそのリリース（1.7.6 以降）を、新しくても古くても入れます。それまでの Kumi は残るので、`--rollback` で戻れます。古い版に戻しても Live の中の新しいブリッジはそのまま残り、前の Kumi でも動きます。

Live の中のブリッジのほうが古く、Live が閉じていれば、続けて `kumi bridge --yes` を実行します。Live が開いていれば、`kumi` を実行するよう伝えます。`kumi` は Live の再起動も任せられます。リポジトリのコピーでは、`update` は代わりにチェックアウトを進め（`git merge --ff-only`。ローカルの変更があれば拒否します）、Cargo でワークスペースをビルドします。Kumi の中の `/update` は、まず確認してから Kumi を閉じ、更新して、同じ会話で開き直します。

`--rollback` は一つ前の Kumi に戻し、Live が閉じていればそのブリッジも戻します。ターミナルでは、Live を終了するのを待つか尋ねます（Kumi が Live を終了することはありません）。それ以外の場合は新しいブリッジがそのまま残り、前の Kumi でも動きます。ブリッジも戻すには、Live を終了して `kumi update --rollback` を2回実行します。

**REAPER の拡張機能と Renoise のツール**は、Kumi のブリッジが入っていれば Kumi に合わせて動きます。

- `kumi update` は新しい Kumi に付属するものを入れ、DAW が開いていれば再起動するよう伝えます（"Kumi's extension 0.1.1 is in REAPER now: restart REAPER if it's open."）。どちらも Kumi が入れた場所へ入れ、新しい Renoise が自分のバージョンフォルダーに作ったツールのコピーも一緒に最新にします。あなたが取り除いたものは入れ直さず（"Kumi's tool isn't in Renoise any more"）、REAPER のフォルダーがなくなった拡張機能をほかの REAPER に移すこともありません。入れるには `kumi --daw reaper bridge` を使います。
- `--rollback` は前の Kumi に付属していたものに戻します。REAPER と Renoise を知らない Kumi（1.19.3 以前）はそれらをそのまま残して使わず、取り除くために削除するファイルやフォルダーを Kumi が伝えます。その Kumi は、`KUMI_DAW` が `reaper` か `renoise` のままだと起動しません。使うときは外してください。
- Kumi が入れた後に DAW のフォルダーで変わっていたものは、まず `~/.kumi/bridges/reaper/changed`（または `renoise`）に保存し、その場所を伝えます。
- どちらも Live や DAW を閉じる必要はありません。動いている DAW は、再起動したときに新しいものを読み込みます。

現在の 1.7.5 インストーラー版（付属の Node 24）からは、Live を閉じて `kumi update` を実行し、いつもどおり Kumi を開きます。最初のネイティブ起動時に、ブリッジが同じ 1.0.74 でも移行します。設定、サインイン、会話、ライブラリーは `~/.kumi`、または指定済みの `KUMI_HOME` に残り、再ログインもデータの移動も不要です。

前のアプリと Node はロールバック用に残ります。Windows では、ネイティブ版の初回起動で古いランチャーが置き換わり、以降の起動は Node を経由しません。通常の更新に追加の操作は不要です。`kumi update --rollback` は JavaScript 版とそのブリッジの設定・シークレットを一緒に戻します。Live を閉じ、ブリッジの前の世代が残っている必要があります。もう一度ロールバックするとネイティブ版に戻ります。Kumi が Live を終了することはありません。

古い Node 22 付きインストーラーで更新が Node のバージョンを理由に拒否される場合は、同じ `KUMI_HOME` のまま[インストーラー](../../README.ja.md#クイックスタート)を再実行してください。データを保持してネイティブ版を入れます。npm 利用者は従来のコマンドを使えます。Cargo があれば現在のチェックアウトをビルドし、なければ対応する公開済みネイティブ版に移行します。

Kumi は起動時に、1 日に最大 1 回、新しいバージョンを確認します。新しいバージョンがないとき、またはネットワークがないときは何も言いません。`~/.kumi/settings.json` の `"updateCheck": false`、または `KUMI_NO_UPDATE_CHECK=1` で確認を無効にできます。

`doctor` はまずインストールを確認します。

- Kumi のバージョンとフォルダー、`--rollback` で戻る先。
- シェルが見つける `kumi` がこの Kumi かどうか。
- 新しい Kumi が出ているか（1 日 1 回の確認の結果から。ネットワークには問い合わせません）。
- 空き容量、インストールされている Live、Live のユーザーライブラリー、ブリッジのポート（9765 と 9766）、Live の Developer Mode。

問題ごとに次にすることを一つ伝えます。直すべきことがあれば `doctor` は 1 で終了します。お知らせ（このコンピューターに Live がない、新しい Kumi がある）は数えません。

REAPER や Renoise を使ったことがあれば、`doctor` はそれも DAW の言葉で確認します（`kumi --daw reaper doctor` はその DAW について伝えます）。

- DAW、そのバージョンと場所、開いたことがあるかどうか。
- その中の Kumi のブリッジ：バージョンとチェックサム、Kumi が入れた後に変わったか消えたか、この Kumi のものより古いか、リファレンスファイルとシークレット、macOS が付けるダウンロードの印、拡張機能のアーキテクチャ。
- DAW が動いていてブリッジが応答するか（開いているプロジェクトやソングも）、古いブリッジのまま動いている DAW（再起動が必要）、そのポート（REAPER は 9770〜9779、Renoise は 9780〜9789）を使うほかのプログラム。
- Renoise では、デモ版かどうか（レンダリングできないので、Kumi はオフラインで聴けません）、OSC サーバー（オンだとネットワークからのコマンドをパスワードなしで受け付けます）、Tools › Tool Browser で Kumi のツールがオフになっていないか。

`--json` は共有のために同じチェックを JSON で出力します。レポートと同じく、キー、トークン、ホームフォルダー、アカウント名は取り除かれます。文言はバージョンによって変わることがあるので、スクリプトで照合するためのものではありません。

- `kumi`：バージョン。`fixes`：直すべきチェックの数。
- `sections`：それぞれ `title` と `checks` を持ち、各チェックには `status`（`ok`、`note`、`fix`）、`text`、そして次にすることがあれば `next` があります。
- 終了コードは `--json` なしのときと同じです。

`report` は `~/kumi-report-<date and time>.txt` を書き出します。Kumi とブリッジのバージョン、doctor のチェック結果、設定、直近の会話で Kumi がしたこと、ギャップのログ、Live 自身のログにあるブリッジの行（REAPER と Renoise では、`~/.kumi/bridges/<daw>/logs` にある Kumi のブリッジのログの最後の行）が入ります。キーとトークンは取り除かれ、ホームフォルダーは `~`、アカウント名は `<user>` と表示されます。送る前に目を通してください。

`uninstall` は Kumi、`--rollback` のために残した版、更新が残したもの、残っている旧版の Node、ランチャー、Kumi が追加した PATH のエントリー、Kumi が取得したもの（プログラム、モデル、見たビデオ。必要になればまた取得します）を削除し、空いた容量を伝えます。ブリッジと拡張機能を Live から取り除くか（Live が閉じている間だけ）、Kumi の拡張機能を REAPER から、ツールを Renoise から取り除くかを尋ねます。REAPER と Renoise の離れていた間の変化を比べる状態も `--all` を付けない限り残り、あなたが変えたブリッジの版（`~/.kumi/bridges/<daw>/changed`）は常に残ります。会話、メモ、レシピ、サインイン、ライブラリー、リファレンスは、`--all` を付けない限り残ります。`--dry-run` は削除するものを伝えるだけで、何も削除しません。

- Kumi のフォルダー（`KUMI_HOME`）がホームフォルダー、ディスクのルート、相対パス、または Kumi のランチャーとアプリがないフォルダーのときは何も削除せず、手で取り除く Kumi のものを伝えます。インストーラーもそこにはインストールしません。`sudo` で実行しても、あなたのホームフォルダーと、root のものではないフォルダーには手を付けません。
- `bin`、`downloads`、Kumi が取得したもののフォルダーからは、Kumi 自身のファイルだけを削除します。ほかのものは残し、その名前を伝えます。フォルダーも残ります。
- `--all` が会話などまで削除するのは、インストーラーが付ける名前 `.kumi` のフォルダーからだけです。フォルダー自体は空になったときに削除します。あなたが自分で入れたものは残ります。ほかのフォルダー（たとえば `KUMI_HOME=~/.local`）からは Kumi 自身だけを削除し、会話などはそこに残して、手で削除できるよう名前を伝えます。
- 削除できない部分があれば、どれをなぜ削除できなかったかを伝え、`kumi uninstall` をもう一度実行できるように Kumi を残します。
- 取り除けない PATH の行（書き込めないファイルにある、`if`、`for`、関数の中にある、または `&&`、`||`、`|`、`\` で前後のコードとつながっている）は、手で取り除けるよう、その行を示します。

## 制限

| 項目 | 制限 |
| --- | --- |
| 送信するメッセージ | 256 KB |
| 1 回の回答 | モデルのステップ 200 回。進捗がないまま 10 分、または合計 60 分で停止（マッチングとゴールではもっと長い。プランの上限を待つ時間は数えない） |
| 再試行 | 混んでいる、または不調なプロバイダーに対して最大 3 回。そのステップの出力がまだ表示されていない場合に限り、プロバイダーが求めるだけ待つ。プランの上限は 6 時間まで待つ。接続がないときは答えを続けられる間 |
| ブリッジへのリクエスト | 65 秒 |
| 1 回の回答での変更 | 5,000（パッドやパラメータのまとめた変更は 1 回と数える） |
| プラン内の `wait` ステップ | 30 分 |
| バックグラウンドジョブ | 同時に 3 つ（`maxJobs`、8 まで）。それぞれモデルのステップ 40 回と 20 分。Ctrl-B で移したステップは答えの 60 分のまま |
| 会話のサイズ | 約 160 KB を超えると以前の Live の読み取り結果が縮小され、約 400 KB を超えると古いやりとりから消える |
| 聴くオーディオ | ファイルの最初の 12 分（求められれば 1 時間まで）。曲全体なら 1 時間まで |
| ビデオの文字起こし | 一度に 90 分 |
| 事前に確認する空きディスク容量 | 録音に 100 MB（Set のあるディスク。保存していない Set ではホームフォルダーのディスク）、デバイスの作成に 100 MB（User Library のあるディスク）、Kumi 自身のモデルの取得にそのサイズの 2 倍と 200 MB、スロットのリンクにはそのサイズと 200 MB（Kumi のフォルダー） |

**聴く機能**が聴くのは、ファイル、録音、そして Set のトラックとミックスです（Set は Kumi Ears を通して聴くので、Max for Live が必要です。REAPER のプロジェクトや Renoise のソングはレンダリングして聴きます）。測定と比較をし、ゴールに対して変更を判定します。好みはあなたのものです。

**Live 自身のコマンド**には、Mac ではターミナルのアクセシビリティが必要です。クリップのコマンドは、セッションのクリップか、あなたが選択したクリップに対して働きます。

**このコンピューター上のモデル：** サーバーが起動していない、モデルがない、空きメモリーに対してモデルが大きすぎる、Kumi の指示とツールに対してウィンドウが小さすぎる、といった場合はそれぞれ対処法（`ollama serve`、`ollama pull <model>`、小さいモデル、大きいコンテキスト）とともに伝え、メッセージの再送か別のモデルの選択を提案します。Kumi のツールからの画像は、ローカルモデルには言葉としてだけ届きます。

**ビデオの視聴**は、各サイトの現状に左右されます。非公開、メンバー限定、一部の年齢制限付きのビデオは読めず、自動字幕は名前を聞き間違えることがあります。画像を扱えないモデルには、ビデオの言葉だけが渡されます。

**ブリッジのバージョン。** Kumi は接続時にブリッジのバージョンを読み、そのバージョンが対応しているツールだけを提供します。どのツールにどのバージョンが必要かは[ブリッジのバージョン](KUMI_CHANGES.md#ブリッジのバージョン)にあります。

## プライバシー：コンピューターの外に出るもの

- **モデルのプロバイダー**には、メッセージ、会話、Kumi が Set から読んだもの、見たビデオのフレーム、読んだ画像、メッセージに添えた画像、バックグラウンドジョブに渡したものとジョブが読んだもの（`workerModel` を設定していればそのプロバイダー）が送られます。このコンピューター上のモデルなら、それらはこのコンピューターから出ません（`settings.json` に書いたサーバーには、それがどこで動いていても送られます）。
- **ウェブ検索と読み込み**は上記の検索サービスに送られ、Kumi が読むページにはそのリクエストが届きます。Kumi はキーやトークンを含むアドレスは読みません。
- **ダウンロード**は、GitHub（Kumi のリリースと更新確認、yt-dlp、ffmpeg、whisper.cpp、ONNX Runtime と Kumi 自身のモデル）、Hugging Face（音声モデル）、スロットのモデルにあなたが指定した https のアドレス、あなたが指定したビデオサイトから行います。
- **リファレンス**を言葉で指定すると、名前で MusicBrainz と ListenBrainz を調べ、Spotify のリンクは Spotify の公開ページ（アーティストのリンクは MusicBrainz）から読み、音声は YouTube の検索で取得して、測り終えたら削除します。
- **オーディオ**はあなたのコンピューター上で解析され、モデルに送られるのは数値だけです。リスニングモデルがあれば、判定する変更の短い抜粋（それぞれ最長 10 秒、モノラル）が送られます：Gemini の API キーなら Gemini へ、OpenAI の API キーなら OpenAI へ、または `KUMI_LISTENER` かリスニングのスロット（`/slots`）のモデルへ（`KUMI_LISTENER_KEY` を設定していればそれも一緒に）。`KUMI_LISTENER=off` か `/slots listening off` で止められます。新しいリスニングモデルを試すときに送るのは、既知のテスト用の音だけです。
- **あなたの声**はあなたのコンピューター上で書き起こされ、録音はすぐに削除されます。外に出るのは、送ったときの言葉だけです。
- **あなたのライブラリー**はあなたのコンピューター上で学習されます。ウェブから来るのはマニュアルのページだけです。
- **あなたの音楽**はあなたのコンピューター上で学習されます。Kumi があなたの好みを使うときは、選んだ曲の名前（アーティスト、タイトル、アルバム）と、それらがどう聞こえるかを述べた 1 文がモデルのプロバイダーに届きます。ファイルそのものは届きません。
- **models.dev のモデルのカタログ**は多くても一日に一度取得します。その要求にあなたのものは何も含まれません。`"modelCatalog": false` で止められます。

トラック、クリップ、デバイスの名前、ツールの結果、ウェブページは Kumi にとってデータであり、指示ではありません。そこに画面に表示されない文字で隠された言葉は、モデルには `[hidden text removed]` として届きます。Kumi はファイルを `~/.kumi` に保存し、あなただけが読めるようにしています。サインイン情報は `~/.kumi/auth.json` にあります。ターミナルのスクロールバックと、プロバイダー自身のデータ保持は、これとは別です。

## プロキシと学校や職場のネットワーク

- **プロキシ：** Kumi は `HTTPS_PROXY`、`HTTP_PROXY`、`ALL_PROXY`（`http://…` または `socks5://…`）を経由します。`NO_PROXY` のアドレスは経由しません。これらがなければ、macOS または Windows の設定にあるプロキシを、その例外とともに使います。プロキシ自動設定（PAC）ファイルは読みません。代わりに `HTTPS_PROXY` にプロキシのアドレスを設定してください。
- **パスワードが必要なプロキシ：** `HTTPS_PROXY=http://user:pass@host:port` と設定してください。システムのプロキシが Kumi にはできないサインイン（NTLM、Kerberos）を求めるとき、応答しないとき、またはこのコンピュータが信頼していない証明書を示すときは、代わりに直接つなぎます。`NO_PROXY=*` なら常に直接つなぎます。
- **プロキシを経由しないもの：** このコンピューター上のモデル（Ollama、LM Studio）と Live のブリッジ。自分で指定したモデルサーバー（`modelServers`、`KUMI_LISTENER`）は、環境変数のプロキシだけを使い、システムのプロキシは経由しません。システムの設定を使うときは、自分のネットワーク上のアドレスも直接つなぎます。
- **安全な接続を検査するネットワーク**（学校や職場によくあります）：Kumi はこのコンピューターが信頼する証明書を信頼します。ブラウザーと同じく、ネットワークの証明書がインストールされていれば動きます。`SSL_CERT_FILE` で、Kumi が信頼する証明書のファイルを追加できます。OpenSSL と同じく、Linux とウェブ検索・読み込みでは、このコンピューター自身の一覧の代わりになります。
- **ウェブ検索と読み込み**はプロキシを経由せず、直接つなぎます。Kumi は各アドレスが公開のアドレスかを確かめてからつなぎますが、プロキシを通すとプロキシが名前を引き直すため、その確認が効かないからです。プロキシ経由でしか外に出られないネットワークでは、ページを読めません。

## ファイルと設定

Kumi はすべてを `~/.kumi` に保存します。`~/.kumi/settings.json` には次の項目があります。

| キー | 意味 |
| --- | --- |
| `model` | 選んだモデル。`<provider>/<model>`（`/model`、`kumi model`） |
| `effort` | `none`、`minimal`、`low`、`medium`、`high`、`xhigh`、`max`。ない場合はモデルのデフォルト（`/effort`） |
| `fast` | `true` で、プロバイダーが一覧に載せている場合にモデルの速い層を使う（`/fast`） |
| `fallbackModel` | あなたのモデルがプランの上限に達したとき、またはプロバイダーが落ちているときに続けるモデル。`<provider>/<model>`（`/model` で ctrl+f） |
| `panelTab` | 最後に開いていた Live ペインのタブ |
| `mapHover` | `false`：`/map` で、マウスが点に来ても再生しない。地図の `h` でオンとオフを切り替え、Kumi はここに覚えておく |
| `updateCheck` | `false` で起動時の新バージョン確認を無効にする |
| `whatsNew` | `false` で、アップデート後の最初の起動時に What's new を表示しない |
| `notifications` | `"off"`：Kumi のウィンドウがほかのウィンドウの後ろにある間、デスクトップ通知（やベル）を出さない。それ以外は `"auto"` |
| `liveStatusBar` | `false`：Kumi が終えたときやあなたが必要なときに、Live（または Renoise）のステータスバーに一行を出さない |
| `keepAwake` | `false`：Kumi が作業している間もコンピューターはスリープできる |
| `answerAfter` | 誰もいないときに Kumi がおすすめの答えを選ぶまでの秒数（60）。`0` は選ばない |
| `theme` | `system`（既定。ターミナルの背景に合わせて明るい配色か暗い配色になり、ターミナルが配色の変化を知らせればそれに合わせて切り替わる）、`dark`（Kumi 本来の配色）、`light`（明るいターミナルのための配色）、`colorblind`（赤緑の色覚の違いでも見分けやすい色にした dark） |
| `instantPhrases` | `false` で、決まったフレーズ（"tempo 124"、"mute drums"）もほかのメッセージと同じくモデルに送る（[即時フレーズ](KUMI_TUI.md#即時フレーズ)） |
| `contextMeter` | ヘッダーの、モデルのコンテキストがどれだけ埋まったかのメーター：`"auto"`（既定）は半分を超えてから、`"always"` は常に、`"off"` は表示しない |
| `modelServers` | 名前を付けたモデルサーバー：`[{ "name", "baseURL", "apiKey", "format" }]`（[このコンピューター上のモデル](#このコンピューター上のモデル)） |
| `libraryFolders` | Kumi がサウンド、プリセット、Set を学習する追加のフォルダー |
| `musicFolders` | Kumi があなたの好みを学ぶ、あなた自身の音楽のフォルダー（`/music add`）。同意するまではありません |
| `musicOffered` | あなたの音楽を学ぶかどうかを Kumi が尋ねたら `true`。尋ねるのは一度だけです |
| `voice` | 話しかける設定：`send`（止めたら送る）、`language`、`microphone`（`/voice`） |
| `maxJobs` | 同時に動くバックグラウンドジョブの数：1〜8、デフォルトは 3 |
| `workerModel` | バックグラウンドジョブが使うモデル。`/model` の一覧にある `<provider>/<model>`。ない場合は会話と同じモデル |
| `conversations` | `keepDays`：会話を最後に使ってから残しておく日数。各 Set の最新 20 件はこれとは別に残る（90。外すと 90 日と最後に設定した値のうち長いほう）。`0` ですべて残す |
| `modelCatalog` | `false`：models.dev のモデルのカタログを取得せず、手元の写しを使い続ける（[モデルの選択](#サインインとモデルの選択)） |
| `copyOnSelect` | `false`：Kumi のウィンドウでドラッグしたテキストは、離したときにはコピーされず、Ctrl-C か右クリックでコピーするまで選択されたまま |
| `mouse` | `"off"`：マウスをターミナル（または tmux）に任せ、ターミナル自身の選択とコピーを使う。Page Up と Page Down でスクロールする |
| `transcriptOnQuit` | `false`：終了するときに会話をターミナルのスクロールバックに出力しない |
| `fullRepaint` | `true`：何かが変わるたびに、Kumi がウィンドウのすべてのセルを書き直す。変わった部分だけの描画が乱れるターミナル向け。Windows Terminal では既定でオンで、`false` でオフになる |

`~/.kumi/slots.json` には、入れ替えたモデルスロットが保存されます（`/slots`）。`~/.kumi/probes` には、各ノブが何をしたかがデバイスとトラックごとに、`~/.kumi/models` にはモデルランタイムと Kumi 自身のモデルが、`~/.kumi/cache/models-catalog.json` には models.dev のカタログの最新の写しが保存されます。四つとも `KUMI_HOME` に従います。

`~/.kumi/bridges/reaper` と `~/.kumi/bridges/renoise` には、各 DAW のブリッジのために Kumi が保存するものが入ります。シークレット（`bridge.secret`）、動いているブリッジが自分の居場所を知らせるファイル（`discovery`）、ログ（`logs`）、インストールのレシート（`install-receipt.json`）、ロールバック用に残した版（`generations`）、あなたが変えた版（`changed`）、離れていた間の変化を比べる状態（`snapshots`）です。`~/.kumi/last-daw` は前回使った DAW です。

| `GEMINI_API_KEY`、`GOOGLE_API_KEY` | リスニングモデル用の Gemini API キー（Gemini 自身の一覧から選んだ最新の Flash モデル） |
| `KUMI_FAST=0` | デバイスのパラメータを、ブリッジのプレビューと適用という遅いほうの道で設定する（[変更の流れ](KUMI_CHANGES.md#変更の流れ)） |
| `KUMI_YTDLP`、`KUMI_FFMPEG`、`KUMI_WHISPER`、`KUMI_WHISPER_MODEL` | 自分で用意した yt-dlp、ffmpeg、whisper.cpp（`whisper-cli`）、音声モデル（`ggml-*.bin`）のパス |
| `KUMI_DAW` | `reaper` か `renoise` でその DAW を使う（Live は `ableton`）。`--daw` と同じ |
| `KUMI_REAPER_RESOURCE_DIR` | 既定の場所にないときの、REAPER のリソースフォルダー。指定すると Kumi はそこだけを使う |
| `KUMI_RENOISE_PREFS_DIR` | Renoise の設定：`V<x.y.z>` フォルダー、またはそれを収めたフォルダー |
| `KUMI_REMOTE_SCRIPTS_DIR` | Kumi が見つけられないときの、Live の Remote Scripts フォルダー |
| `KUMI_LIVE_EXTENSIONS_DIR` | Kumi が Live の Extensions フォルダーを見つけられないときに、`kumi bridge` が Kumi の拡張機能を入れ、`kumi doctor` がそれを探す場所 |
| `KUMI_BRIDGE_WAIT_SECONDS` | `kumi bridge` が Live の接続を待つ時間。`0` で待たない |
| `KUMI_NO_UPDATE_CHECK` | 任意の値で起動時の新バージョン確認を無効にする |
| `HTTPS_PROXY`、`HTTP_PROXY`、`ALL_PROXY`、`NO_PROXY` | Kumi が経由するプロキシと、経由しないアドレス（[プロキシ](#プロキシと学校や職場のネットワーク)） |
| `SSL_CERT_FILE` | このコンピューターの証明書に加えて Kumi が信頼する証明書のファイル |
| `KUMI_UI=plain` | 全画面アプリの代わりに 1 行ずつのプレーンな出力。`kumi bridge`、`kumi update` などのコマンドも、処理中にスピナーを表示しません |
| `KUMI_COLOR` | 検出が間違っているときの `truecolor`、`256`、`16`、`none`。`NO_COLOR` にも従う |
| `KUMI_ICONS` | ターミナルの記号が正しく表示されないときの `glyphs` または `badges`（2 文字のアイコン） |
| `KUMI_PROBE=off` | 起動時にターミナルの種類を問い合わせない。画像、通知、色は環境変数だけで決まる |
| `KUMI_TRACE=1` | ブリッジ呼び出しごとにその名前を表示（引数や結果は表示しない） |

インストーラーが読む設定：

- `KUMI_HOME`：`~/.kumi` 以外の場所にインストールする。後からではなくインストール時に設定します。
- `KUMI_VERSION`：指定したリリース（`1.16.0` など、または `latest`）をインストールする。1.7.6 より前のリリースはそのリリース自身のスクリプトでインストールします。そのコマンドはインストーラーが示します。
- `KUMI_RELEASES`：ダウンロード元。`KUMI_VERSION` より優先します。
- `KUMI_NO_MODIFY_PATH=1`：PATH を変更しない。
- `KUMI_ALLOW_ROOT=1`：sudo で実行したときに root 用にインストールする。指定がなければ、Kumi があなたではなく root のホームフォルダーに入ってしまうため、インストーラーはそこで止まります。

もう一度実行すると Kumi を修復し、`kumi update --rollback` で戻る先の Kumi は残します。新しい Kumi が入る前に Ctrl-C で止めれば、何も変わりません。うまくいかないときは理由を示します：リリースがない、接続できない（DNS、TLS、プロキシ、タイムアウト）、GitHub の代わりに Wi-Fi のサインインページが応答した、など。
