# Kumi のコマンド、キー、画面

[English](../en/KUMI_TUI.md) · [简体中文](../zh-CN/KUMI_TUI.md) · 日本語

Kumi のターミナルアプリのリファレンスです。画面に表示されるもの、すべてのコマンドとキー、プレーンモードを説明します。Kumi が何をするかは[ガイド](KUMI_GUIDE.md)で説明しています。

## 画面

Kumi はターミナルウィンドウ全体を使い、Kumi が閉じたとき、クラッシュしたとき、止められたときには、元の状態に戻して返します。

- **ヘッダー：** Kumi、Set の名前、モデルとその effort（どれだけ深く考えるか）、Live との接続。Live の再生中は、テンポの横で黄色いライトが拍に合わせて点滅します（小節の最初の拍で最も明るくなります）。
- **会話**（左）：あなたのメッセージ、Kumi の答えとそのステップを、普段の言葉で（"looked at your Set"）、それぞれの所要時間とともに表示します。作業中のステップは種類ごとにアニメーションします（検索、読み込み、デバイスの作成、変更、試聴、再生）。同じステップを何度も行うと一行にまとまります（"read a page ×3"）。Kumi が聴いたものは小さなスペクトラムとして、Kumi が保存したものは専用の行として表示されます：✎ メモ、◆ テクニック、↻ レシピ、✦ マッチングから得た教訓。
- **FOCUS**（右上）：Live でいまいる場所を、選択の変化に合わせて表示します。ラックのチェーンを含むトラックのデバイスツリー、小さなピアノロールで表したクリップのノート、またはセッションやアレンジメントの帯です。指し示したデバイス（クリックするか、Live で **Ask Kumi about this** を使う）は、次からのメッセージのためにピン留めされます。
- **NOW**（右中央）：Kumi がしていることを、その場で描きます。値の変更前と変更後、新しいクリップのノート、色見本、チェーンに収まるデバイス、"▶ Playing from the start marker" などです。
- **タブ**（右下）：**HISTORY** には、Kumi が最近保存した三つのもの（それぞれに **forget**）、続いてすべての変更が新しい順に並び、それぞれに **undo**、取り消せないものには **kept** / **no undo** / **check Live** が付きます。**GOAL** は `/goal` を表示します（設定されるまでは "No goal yet"）：目標、最高スコアとその推移、首位の候補、経過時間です。
- **入力欄**（左下）：送信待ちのメッセージはその上に、ピン留めしたデバイスはチップとして表示されます。空のときは「ctrl+t to talk」と表示します。Kumi が聴いている間は、下の行に点滅するミントの `●`、時間、レベルメーターと、右側に使えるキーが表示されます。赤は使いません。Live では赤は録音を意味するからです。

ウェルカム画面には、前回から Set で変わったこと、新しい Kumi が出ていればそのこと、そして初回には Kumi がライブラリーをバックグラウンドで学習していることが表示されます。

幅が 100 列未満になると、Live のペインは入力欄の上の 2 行の帯にたたまれます（いまいる場所と Kumi がしていること、次に最後の変更とその undo）。24×8 より小さいと、Kumi はウィンドウを大きくするよう求めます。

## ターミナルでのコマンド

これらは `kumi <command>` として実行します。リポジトリのコピーからは `npm run kumi -- <command>` として実行します。

| コマンド | 内容 |
| --- | --- |
| `kumi` | Live で開いている Set で Kumi を開く |
| `kumi --inference-only` | Live なしでチャットする |
| `kumi --bridge-config <absolute path>` | 自分のブリッジ設定を使う |
| `kumi login` | サインイン：ChatGPT か API キーかを尋ねる |
| `kumi login <provider>` | `openai-codex`（ChatGPT。ブラウザなしなら `--device`）に、または API キーで `anthropic`、`openai`、`opencode`、`opencode-go` にサインインする |
| `kumi logout <provider>` | そのプロバイダーへの Kumi のサインインを削除する |
| `kumi model [<provider>/<model>]` | モデルを表示または選択する。このコンピューター上のモデルも（`ollama/<model>`） |
| `kumi auth` | 使えるプロバイダー、モデル、サインインファイル（秘密情報は表示しない） |
| `kumi bridge [--yes] [--allow-dirty]` | Live を閉じた状態で：ブリッジを Live に入れる、または最新にする。`--yes` は Live が閉じていることを確認済みとする。`--allow-dirty` は、コミットされていない変更があるチェックアウトでもそのブリッジをインストールできるようにする |
| `kumi doctor` | Node、サインイン、このコンピューター上のモデルサーバー、ブリッジ、Live、拡張機能、ライブラリー、ビデオ用プログラム、話しかける機能、Live のメニュー、ターミナルを確認し、実行すべきことを伝える |
| `kumi library [--rebuild]` | Kumi があなたのサウンド、プリセット、Set をどこまで学習したか。`--rebuild` ですべて学習し直す |
| `kumi update [--check \| --rollback]` | 最新の Kumi を取得する（ブリッジが古ければブリッジも）。`--check` は確認だけ、`--rollback` は一つ前に戻す（インストールした Kumi のみ） |
| `kumi report` | 問題が起きたときに送る `~/kumi-report-<date and time>.txt` を書き出す |
| `kumi uninstall [--all] [--yes]` | インストールした Kumi を削除する。`--all` は会話、メモ、レシピ、サインインも削除する。`--yes` は最初の質問を省く |
| `kumi --version`（または `-v`）、`kumi --help` | バージョン、ヘルプ |

## Kumi の中のコマンド

`/` を入力するとこれらのメニューが出ます：↑↓ で選び、Tab で補完、Enter で実行、Esc で閉じます。パスで始まるメッセージ（ターミナルにドラッグしたファイル）は、コマンドではなくメッセージとして扱われます。

| コマンド | 内容 |
| --- | --- |
| `/new` | 新しい会話を始める。それまでの表示は線で区切られて画面に残り、前の会話は保存され、HISTORY の undo も引き続き使える |
| `/btw <question>` | 横からちょっと尋ねる。Kumi の作業中でもいつでも使える。それまでの会話をもとに、ツールを使わずにパネルで答え、会話には加えない。`/btw` だけなら最後の答えをもう一度表示する |
| `/conversations` | この Set で保存された会話（最新の 20 件）。一つ選ぶとその続きから再開する |
| `/reconnect` | 新しいブリッジで Live に接続し直す。会話はそのまま（それ以前の変更は Kumi の undo を失う） |
| `/undo` | Kumi の最新の変更を取り消す |
| `/stop` | Live を止める：クリップ、トランスポート、録音。Kumi の答えも止める |
| `/refresh` | モデルに尋ねずに Set を読み直す |
| `/copy` | Kumi の最後の答えをクリップボードにコピーする |
| `/model`, `/effort` | モデル（各プロバイダー自身の一覧から、続いてこのコンピューター上のモデルサーバー：Ollama、LM Studio、settings.json に書いたもの。入力して絞り込める）と、どれだけ深く考えるかを選ぶ。次のメッセージから反映される |
| `/login`, `/logout` | サインイン（ブラウザで ChatGPT、またはドットでだけ表示される API キー）またはサインアウト |
| `/goal <what to reach>` | Kumi がたどり着くまで、ある音を追い求める。`/goal` だけなら一時停止した目標を再開し、`/goal stop`（または `/goal end`）で終える |
| `/memory` | Kumi が保存しているすべて：あなたとこの Set についてのメモ、あなたの Set から学んだこと、テクニック、レシピ、教訓。一つ選ぶと忘れさせられる（レシピは実行するか忘れさせる） |
| `/recipes` | あなたのレシピ：実行する（Kumi がメッセージ `Run my recipe "<name>" on ` を書き始めるので、続きを入力する）か、忘れさせる |
| `/status` | Kumi の接続先、モデル、ライブラリーの学習の進み具合、API キーの場合はこのセッションで使ったトークン数 |
| `/voice` | 話しかける機能：開始と停止、「止めたら送る」、話す言語、マイク |
| `/update` | 最新の Kumi を取得する：確認してから閉じ、更新し、同じ会話で再び開く |
| `/help` | キーとコマンドを、会話の中のメモとして表示する |
| `/quit` | Kumi を閉じる |

`/new`、`/reconnect`、`/refresh`、`/undo` は Kumi が答えていないときだけ使えます。答えの途中では、Kumi はそう伝え、何も変えません。

## キー

**入力と送信**

| キー | 動作 |
| --- | --- |
| Enter | 送信。Kumi の作業中は、進行中のステップの後にメッセージを読む |
| Tab（Kumi の作業中） | 答えが終わった後に送る。メッセージは入力欄の上で待つ |
| Alt-↑ | 最後の待機中のメッセージを入力欄に戻す |
| Ctrl-J, Alt-Enter, Shift-Enter | 改行（Shift-Enter は、それを報告するターミナルで） |
| ↑ と ↓ | 入力欄の行を移動し、その先は以前に送ったものをたどる（`/new` や再起動をまたいで保持。秘密情報は除く） |
| Ctrl-A / Ctrl-E, Home / End | 行の先頭 / 末尾 |
| Alt-← / Alt-→, Ctrl-← / Ctrl-→, Alt-B / Alt-F | 一単語左 / 右 |
| Ctrl-W, Alt-Backspace, Ctrl-Backspace | カーソルの前の単語を削除 |
| Ctrl-K / Ctrl-U | 行の末尾 / 先頭まで削除 |
| Ctrl-T | 入力の代わりに話す：もう一度押すと止まり、押したまま話すこともできる。話した内容はカーソル位置に入る。Enter で止めてすぐ送り、Esc で破棄する |

**停止と移動**

| キー | 動作 |
| --- | --- |
| Esc | `/` メニューを閉じる。メニューがなければ Kumi の答えを止める（終わったステップは残り、待機中のメッセージは入力欄に戻る）。それもなければ、ピン留めしたデバイスを外す |
| Ctrl-C | Kumi の答えを止める。Kumi が何もしていないときは入力欄を空にし、入力欄が空なら終了する |
| Ctrl-D | Kumi が何もしておらず入力欄が空のときに終了する |
| Page Up / Page Down、マウスホイール | 会話をスクロールする（タブの上ではホイールでタブをスクロール）。新しいテキストが届いても位置はそのまま |
| Ctrl-Home / Ctrl-End | 会話の先頭へ / 最新に戻る |
| Ctrl-L | 画面を再描画する |

**Live のペイン**

| キー | 動作 |
| --- | --- |
| Tab（Kumi が何もしていないとき） | FOCUS のデバイスツリーに、Live の選択位置から入る：↑↓ で移動、Enter でその行を指し示す、Esc か Tab で入力に戻る |
| Shift-Tab | タブに入る（もう一度押すと次のタブ）：↑↓ と Page Up/Down で移動、Enter でその行の **undo** または **forget**、Esc か Tab で戻る |
| マウス | 行末の **undo** や **forget**、タブの名前をクリックする。ツリーのデバイスをクリックすると、それを指し示す。ピンをクリックするとピン留めを外す。テキストを選択するには Shift を押しながらドラッグする（iTerm2 では Option） |

**パネル**（`/model`、`/effort`、`/login`、`/memory` など）：↑↓ で移動、Enter で選択、Esc で閉じます。`/model`、`/memory`、`/conversations`、`/recipes` では、入力すると一覧を絞り込めます。キーの入力欄ではキーを貼り付けて Enter を押します。Kumi はプロバイダーでキーを確認し、プロバイダーに接続できないときは確認せずに保存します。ChatGPT のサインインパネルでは `c` でリンクをコピーします。`/btw` パネルでは ↑↓ と Page Up/Down でスクロール、←→ で以前の答えをたどり、`c` でコピー、Esc、Enter、Space で閉じます。

## プレーンモード

`KUMI_UI=plain`、またはパイプを通した入力や出力では、代わりに一行ずつのプレーンなインターフェースになり、スクリーンリーダーやログに向いています。使えるのは `/help`、`/status`、`/undo`、`/stop`、`/refresh`、`/reconnect`、`/new`、`/conversations [n]`、`/model [provider/model]`、`/effort [level|default]`、`/logout <provider>`、`/memory`、`/forget <id>`、`/recipes`、`/update`、`/quit` で、`/btw`、`/goal`、`/copy` はありません。サインインはシェルから `kumi login` で行います。Ctrl-C は答えを止め、Kumi が何もしていないときは終了します。

## ターミナル

Kumi はターミナルが表示できる色数を検出します。`KUMI_COLOR`（`truecolor`、`256`、`16`、`none`）で上書きでき、`NO_COLOR` にも従います。ターミナルの記号が表示されないおそれのある環境（古い Windows コンソール、Linux コンソール）では、Kumi はアイコンの代わりに 2 文字のバッジを使います。`KUMI_ICONS=glyphs` または `badges` で選べます。Windows では Windows Terminal をおすすめします。kitty キーボードプロトコルに対応していないターミナルでは、改行に Ctrl-J か Alt-Enter を使います。対応しているターミナルは、押していた Ctrl-T を離したことを伝えます。それ以外では、キーのリピートが止まったところで Kumi は聴くのをやめます。

## 設計メモ

アプリを開発する人向けです（`crates/kumi/src/tui/`）。

**原則。** Kumi はウィンドウ全体を受け持ち、すべてのセルを自分で描くので、ペインはそれぞれ独立にスクロールし、位置がずれません。枠線は使わず、領域は背景の濃淡で分けます。色には必ず意味があります。記号より言葉を優先し、ステップはツール名ではなく音楽の言葉として読めるようにします（"looked at Bass and Drums"）。動きは、何かが起きている、または変わっていることを示すためだけに使います。ペインはビューです：ランタイムが描くものをデータとして記述するので、別のフロントエンドでも同じものを描けます。

**パレット**（`style.rs`）。グレーは `#0e0f12`（地）から `#f4f6f8`（最も明るい色）まで、アクセントは一つでミント `#86e3b5`、そして Live 自身のトラックカラー（とても暗いものは表示用に明るくします）。警告 `#e7b45f`、エラー `#ee8479`、拍のライト `#ffe14d`。Kumi が保存するものは種類ごとに色があります：メモ `#8cc8ff`、テクニック `#c7a6ff`、レシピ `#f2a6c4`、教訓 `#e7c88f`。

**基盤**。UI フレームワークを使わず、ターミナルの基本機能から組み立てています：

1. ターミナル I/O（`tty.rs`）：raw モード、代替スクリーン、bracketed paste、SGR マウス、フォーカスイベント、使える場合は kitty キーボードプロトコル。終了時、クラッシュ時、シグナル受信時にはターミナルを元に戻します。
2. 入力（`keys.rs`）：修飾キー付きのキー（xterm と CSI u）、貼り付け、マウス、複数回の読み取りに分かれて届くシーケンス、そして短いタイムアウトで判定する単独の Esc。kitty プロトコルでは、押し続けているキーのリピートと、キーを離したことがそれぞれイベントになります。
3. スクリーンとレンダラー（`screen.rs`、`render.rs`）：セルのグリッドです。各フレームを前のフレームと比較し、変わったセルだけを同期更新の中で書き込みます。色は 24 ビットから 256 色、16 色、色なしへと段階的にフォールバックします。
4. テキスト（`width.rs`、`wrap.rs`）：書記素の幅（全角の CJK 文字と絵文字は 2 セル）、折り返し、切り詰め。
5. フレーム（`scheduler.rs`）：再描画はまとめて行い、アニメーションのクロックは何かが動いているときだけ動きます。

`app.rs` がレイアウトを描いて入力を処理し、`editor.rs` が入力欄、`transcript.rs` が会話、`tree.rs` がデバイスツリー、`tabs.rs` がタブを担当します。テストはレンダラーの出力を小さなターミナルインタープリターで再生し、意図したフレームを正確に再現できなければなりません。

**まだできていないこと：** ロケーターと新しいトラックを NOW で図にすること。ルーティングのファンイン図やサイドチェイン図。とても長いクリップの概観の帯。多くのトラックにまたがる変更を、展開できる一つの HISTORY 項目にすること。ある変更に依存する変更の取り消しを提案すること。項目に "undone in Live" と印を付けること。macOS のアクセシビリティ機能を通した FOCUS（正確なコントロール、クリップのタブ、Browser の項目）。
