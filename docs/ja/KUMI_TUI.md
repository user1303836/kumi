# Kumi のコマンド、キー、画面

[English](../en/KUMI_TUI.md) · [简体中文](../zh-CN/KUMI_TUI.md) · 日本語

Kumi のターミナルアプリのリファレンスです。画面に表示されるもの、すべてのコマンドとキー、プレーンモードを説明します。Kumi が何をするかは[ガイド](KUMI_GUIDE.md)で説明しています。

## 画面

Kumi はターミナルウィンドウ全体を使い、Kumi が閉じたとき、クラッシュしたとき、止められたときには、元の状態に戻して返します。

- **ヘッダー：** Kumi、Set の名前、モデルとその effort（どれだけ深く考えるか）、動いているバックグラウンドジョブの数（◐ 2 jobs）、Live との接続。Live の再生中は、テンポの横で黄色いライトが拍に合わせて点滅します（小節の最初の拍で最も明るくなります）。フォールバックモデルが答えている間は、そのモデルが「· fallback」付きで表示されます。プランの上限が近いとき（枠の 80% を使ったとき）は、モデルの横に「plan 84% · resets 14:20」と表示されます。モデルのコンテキストが半分を超えると、モデルの横のメーターがどれだけ埋まったかを示します（「context ▰▰▰▰▰▰▱▱▱▱ 62%」、80% からは警告の色）。settings.json の `"contextMeter": "always"` で最初から表示し、`"off"` で表示しません。
- **会話**（左）：あなたのメッセージ、Kumi の答えとそのステップを、普段の言葉で（"looked at your Set"）、それぞれの所要時間とともに表示します。作業中のステップは種類ごとにアニメーションします（検索、読み込み、デバイスの作成、変更、試聴、再生）。同じステップを何度も行うと一行にまとまります（"read a page ×3"）。Kumi が聴いたものは小さなスペクトラムとして、Kumi が保存したものは専用の行として表示されます：✎ メモ、◆ テクニック、↻ レシピ、✦ マッチングから得た教訓。モデルがステップの合間に考えている間は、その推論の見出しが作業中のステップと同じように専用の行に表示されます。終わった答えには、目立たない一行が付きます：かかった時間、変更の数、そして API キーならトークン数、サブスクリプションならプランのうち使った割合（「6.2s · 2 changes · 18.4k in · 1.2k out」）。
- **FOCUS**（右上）：Live でいまいる場所を、選択の変化に合わせて表示します。ラックのチェーンを含むトラックのデバイスツリー、小さなピアノロールで表したクリップのノート、またはセッションやアレンジメントの帯です。指し示したデバイス（クリックするか、Live で **Ask Kumi about this** を使う）は、次からのメッセージのためにピン留めされます。
- **NOW**（右中央）：Kumi がしていることを、その場で描きます。値の変更前と変更後、EQ やコンプレッサーのカーブ、オートメーションのレーン、新しいクリップのノート、色見本、チェーンに収まるデバイス、"▶ Playing from the start marker" などです。Kumi がモデルを待っている間は、その理由といつまで待つかを表示します：「retrying in 5s · ChatGPT is busy」「carrying on at 14:20 (in 2h 13m) · ChatGPT's plan limit」「offline · trying again in 20s」（どれも Esc で止められます）。モデルが考えている間は、NOW がその長さ（「thinking · 31s」）と推論の見出しを表示します。一行だけで、推論そのものは表示されず、答えにも `/copy` にも入りません。
- **タブ**（右下）：**HISTORY** には、Kumi が最近保存した三つのもの（それぞれに **forget**）、続いてすべての変更が新しい順に並び、それぞれに **undo**、取り消せないものには **kept** / **no undo** / **check Live** が付きます。変更を開くと、その図が表示されます：EQ のカーブ、コンプレッサーのカーブ、ノート（新しいものは色付き、消えたものは薄く）、オートメーションのレーン、または各値の変更前と変更後。Live が頼んだ値と違う値を設定したときは、頼んだ値も添えます（"asked -2 dB"）。**GOAL** は `/goal` を表示します（設定されるまでは "No goal yet"）：ゴール、予算に対する済んだターン数と時間（ステータス行は進行中のターンを数えます）、最後の確認、次にやること。音を合わせる `/loop` では、最高スコアとその推移、首位の候補、経過時間です。最初のバックグラウンドジョブとともに **JOBS** が加わります：それぞれの進み具合、時間、トークンが新しい順に並び、**stop** が付きます。Enter でそのステップとレポートを開きます。
- **入力欄**（左下）：送信待ちのメッセージはその上に、ピン留めしたデバイスはチップとして、次のメッセージと一緒に送るファイルは名前、種類、サイズと × で表示されます。空のときは「ctrl+t to talk」と表示します。Kumi が聴いている間は、下の行に点滅するミントの `●`、時間、レベルメーターと、右側に使えるキーが表示されます。赤は使いません。Live では赤は録音を意味するからです。

ウェルカム画面には、前回から Set で変わったこと、新しい Kumi が出ていればそのこと、そして初回には Kumi がライブラリーをバックグラウンドで学習していることが表示されます。

アップデート後に初めて Kumi を開くと、会話の最初に **What's new**（新機能）が表示されます。Kumi の変更履歴から新しい順に最大 5 件で、残りは `/changelog` で見られます。前回から続く会話がある場合は、その下に表示されます。新規インストールでは表示されず、モデルに送られることもありません。`~/.kumi/settings.json` に `"whatsNew": false` を書くと表示しなくなります。

続けた会話は、終えたときのままに戻ります。最後の 30 件の依頼が、ステップ、図、試聴のラウンドとともに表示され、その上に表示されていないそれより前のメッセージの件数が出ます。HISTORY にはその会話の変更が出ますが、再起動後は Kumi から取り消せません（DAW 自体の取り消しは使えます）。古い Kumi が保存した会話は、これまでどおり言葉だけで戻ります。

**セットアップ**は、まだ済んでいないステップがあるときに最初に表示されます：サインイン、Live の中の Kumi のブリッジ（ないとき、または Kumi のものより古いとき）、そして Control Surface です。3 つのステップを並べ、済んだものは選んだ内容とともにミントで示し、いまのステップに必要なことを尋ねます。ワードマークの下のミントの波形は、Kumi が待っている間（ブラウザ、インストール、Live）だけ動きます。↑↓ と Enter で選び、Esc でそのステップを後回しにします。続くセッションは同じウィンドウに表示されます。ChatGPT のサインインを待っている間は、**c** でリンク（またはコード）をコピーでき、**d** でブラウザの代わりにコードを、**b** でまたブラウザを使えます。Linux では、セットアップはサインインだけを行います。セットアップ済みの Kumi は、すぐにセッションから始まります。

幅が 100 列未満（DAW の横に置いたウィンドウ）になると、ペインは会話の下の**ドロワー**になります：タブの列（NOW、FOCUS、HISTORY など）と、その下に表示中のタブ。高さはウィンドウに合わせて 6〜10 行です。

- Kumi が変更を加えると NOW が開きます：Kumi がしていること、変更とその undo、そしてその図。ゴールでは、たたまれたドロワーが GOAL で開きます。Kumi が開いたドロワーは、10 秒間新しいことがなければタブの列にたたまれます。
- タブをクリックするとそのタブで開き、表示中のタブをクリックすると閉じます。Shift-Tab と Tab は、タブや FOCUS のツリーに入るときにドロワーをそこで開きます。自分で開いたドロワーは、選んだタブのまま、閉じるまで開いたままです。入力欄からキーボードを奪うことはありません。
- Ctrl-\\ で開閉します。一度閉じると、もう一度開くまで Kumi は閉じたままにします。

24 行未満では、代わりにペインは入力欄の上の 2 行の帯になります（いまいる場所と Kumi がしていること、次に最後の変更とその undo）。24×8 より小さいと、Kumi はウィンドウを大きくするよう求めます。

## REAPER と Renoise

REAPER と Renoise でも画面は同じで（[つなぎ方](KUMI_GUIDE.md#reaper-や-renoise-につなぐ)）、DAW 自身の言葉とビューに沿って表示されます。

- **ヘッダー：** プロジェクトやソングの名前と、DAW との接続（"● REAPER"。ダイアログやレンダリングで手が離せない間は "REAPER busy"）。ビートのライトは DAW 自身の時間に沿って点滅し、テンポの横に拍子を表示します。REAPER ではテンポマップを通じた拍子（"7/8"）、Renoise では LPB（"LPB 4"）です。
- **REAPER の FOCUS** は、REAPER でフォーカスのあるものを追います。
  - **アレンジビュー**：REAPER でスクロールやズームしたとおりの範囲（"bars 9–16 of 64"）と、選んだトラックの前後のトラックを、フォルダーの階層ごとに字下げして表示します（完全にたたんだフォルダーの中のトラックは隠れます）。アイテムは帯で表示し、固定レーンはレーンごとに 1 行（再生されないレーンは薄く）表示します。マーカー、始まりから終わりまでのリージョンとその名前、ループ、再生位置も表示します。
  - **MIDI エディター**：テイクのノートを小さなピアノロールで表示し、その下に最大 3 つのレーン（CC、ピッチ、プログラム、チャンネルプレッシャー、ポリフォニックアフタータッチ）と「and n more lanes」を表示します。
  - **FX チェーン**：チェーンをツリーで表示します。入力 FX は独立した枝、コンテナは中の FX ごと開き、バイパス、オフライン、並列の FX には印が付きます。テイクの FX にフォーカスがあるときはテイクのチェーンです（"Kick · take “kick.wav”"）。
  - トラックの**ルーティング**ウィンドウ：センド、レシーブ、ハードウェア出力とそのレベル、MIDI のハードウェア出力。
  - **ミキサー**ウィンドウ（ドッキングしていないもの。ドッキングしたミキサーは見分けられません）：マスターと、選んだトラックの前後のトラックのボリューム、パン、ミュート、ソロ、アーム、ピークメーター。
- **Renoise の FOCUS** は、中央のフレームとパネルを追います（Renoise はどこにキーボードのフォーカスがあるかを教えないので、変化したものに従います）。
  - **Pattern Editor**：カーソル（再生中で Follow Player がオンなら再生位置）の前後の行。各トラックのノート、インストゥルメント、ボリューム、パンニング、ディレイ、エフェクトの各列を Renoise の表記で、トラック名はその色で表示します。
  - **Pattern Matrix**（表示しているとき）：シーケンスの各スロットのパターン、セクション、ミュートしたトラック、現在のスロット。
  - **Phrase Editor**：同じグリッドに、フレーズの LPB、キートラッキング、ループを添えて表示します。
  - **インストゥルメント**（Instrument Editor または Sample Editor）：キーゾーンを鍵盤のマップで表示し、各サンプルのミュートグループとスライス、マクロ、フレーズ、モジュレーションセット、FX チェーンも表示します。
  - **Track DSPs**（パネルを開いているとき）：チェーンをツリーで表示します。Doofer は中のデバイスごと、Splitter はレーンごとの枝（Frequency Low と High、Mid と Side、Parallel Lane 1 と 2）で表示し、バイパスしたデバイスには印が付きます。
  - **Mixer**：各トラックのポスト FX のボリューム、パンニング、ミュート、ソロ（メーターはありません。Renoise の API にないためです）。
- **指し示す：** FX と DSP のツリーでも、Live のデバイスツリーと同じく Tab とクリックが使えます。
- **図：** NOW と HISTORY には、変更の種類ごとに一つの図が出ます。パターンやフレーズの行の前後、エンベロープやオートメーションのポイント、動いたパラメーター（名前とバー）、ルートの値（センド、レシーブ、ハードウェア出力）、キーゾーン、トラック上のアイテム、設定の前後、チェーンを読み込んだあとのトラックのデバイスです。キーゾーンとアイテムは絵で（ターミナルが表示できれば画像で）、行とルートは言葉で表示します。
- **セットアップ**は、Linux でも、サインインと Connect to REAPER（または Renoise）の 2 ステップです。Control Surface はありません。
- **コマンド**は DAW の言葉で話します。`/refresh` は REAPER のプロジェクトを読み直し、`/stop` は REAPER のトランスポートと録音、そして Kumi が鳴らしているものを止めます。`/willington` は Live だけのものです。
- **Kumi から離れているとき：** Kumi の一行は Renoise のステータスバーに出ます。REAPER には Kumi が書き込めるステータスバーがないので、通知で知らせます。どちらになるかは `/status` が伝えます。

## ターミナルでのコマンド

これらは `kumi <command>` として実行します。リポジトリのコピーからは `npm run kumi -- <command>` として実行します。

| コマンド | 内容 |
| --- | --- |
| `kumi` | DAW（Live、REAPER、Renoise。Kumi の前でも後でも開いてよい）で開いているもので Kumi を開く。初回はサインインし、Kumi のブリッジをその DAW に入れる（Live の再起動も任せられる）。Kumi がつながっていない間にほかの DAW を開くと、Kumi はそちらに移る |
| `kumi --daw live`、`kumi --daw reaper`、`kumi --daw renoise` | どの DAW が開いていても、その DAW だけを使う。初回はサインインし、Kumi のブリッジを入れる。`KUMI_DAW` でも同じ。`kumi --daw reaper doctor`（または `report`）はその DAW について伝える |
| `kumi --daw reaper bridge [--yes]`（または `renoise`） | Kumi の拡張機能を REAPER に、ツールを Renoise に入れる、または最新にする。`--yes` で確認に前もって答える |
| `kumi -c`（`--continue` でも可） | どのプロジェクトのものでも、最後に使った会話の続きから始める |
| `kumi -r [ID または名前]`（`--resume` でも可） | 保存された会話を ID（または先頭部分）か名前で選んで続ける。引数なしなら一覧から選ぶ。どちらも `--inference-only` と使える |
| `kumi export [ID または名前 \| --last] [--md \| --html \| --json] [--full] [--raw] [-o パス]` | 保存された会話を Markdown（既定）、Web ページ、Kumi 用ファイルとして保存。ID を省くか `--last` で最新の会話。`--full` で各ステップの入力と結果も加え、`--raw` でキーやパスを残す |
| `kumi import <ファイル>` | `kumi export --json` で保存した会話を取り込み、`kumi -r` で続けられるようにする |
| `kumi --inference-only` | DAW なしでチャットする |
| `kumi -p "<依頼>" [--json]`（`--print` でも可） | 依頼を 1 つ実行し、答えを出力して終わる（スクリプト向け）。うまくいかなかったことは stderr に出し、終了コードで結果を示す：0 答えた、1 失敗、3 1 回の答えのステップ上限で止まった、130 ctrl+c で止めた。`--json` では代わりに Kumi が送るイベントを 1 行ずつ JSON で出す。決まったフレーズ（「tempo 124」）はモデルを使わずすぐ DAW を変える。DAW があれば、`kumi` と同じく開いているプロジェクトの会話に入る。`--inference-only`、`--daw`、`-c`、`-r <ID または名前>` と使える |
| `kumi --bridge-config <absolute path>` | 自分のブリッジ設定を使う |
| `kumi login` | サインイン：ChatGPT か API キーかを尋ねる |
| `kumi login <provider>` | `openai-codex`（ChatGPT。ブラウザなしなら `--device`。SSH 経由ではこれが既定。ブラウザなら `--browser`）に、または API キーで `anthropic`、`openai`、`opencode`、`opencode-go` にサインインする |
| `kumi logout <provider>` | そのプロバイダーへの Kumi のサインインを削除する |
| `kumi model [<provider>/<model>]` | モデルを表示または選択する。このコンピューター上のモデルも（`ollama/<model>`） |
| `kumi auth` | 使えるプロバイダー、モデル、サインインファイル（秘密情報は表示しない） |
| `kumi bridge [--yes] [--allow-dirty]` | Live を閉じた状態で：ブリッジを Live に入れる、または最新にする。`--yes` は Live が閉じていることを確認済みとする（ターミナルがないときは、これがないと何も変えない）。`--allow-dirty` は、コミットされていない変更があるチェックアウトでもそのブリッジをインストールできるようにする |
| `kumi doctor [--json]` | インストール（バージョン、ロールバック、PATH、更新、空き容量、Live、ユーザーライブラリー、ブリッジのポート、Developer Mode）、サインイン、このコンピューター上のモデルサーバー、ブリッジ、Live、拡張機能、ライブラリー、ビデオ用プログラム、話しかける機能、Live のメニュー、ターミナル、使っていれば REAPER と Renoise を確認し、実行すべきことを伝える。`--json` はキーとホームフォルダーを除いて出力する |
| `kumi library [--rebuild]` | Kumi があなたのサウンド、プリセット、Set をどこまで学習したか。`--rebuild` ですべて学習し直す |
| `kumi update [--check \| --rollback \| --version <x.y.z>]` | 最新の Kumi を取得する（ブリッジが古ければブリッジも、REAPER の拡張機能と Renoise のツールは付属するものに）。`--check` は確認だけ、`--rollback` は一つ前に戻す（Live が閉じていればそのブリッジも）、`--version` はそのリリースを新しくても古くても入れる（インストールした Kumi のみ） |
| `kumi report` | 問題が起きたときに送る `~/kumi-report-<date and time>.txt` を書き出す |
| `kumi uninstall [--all] [--yes] [--dry-run]` | インストールした Kumi と、Kumi が取得したものを削除する。`--all` は会話、メモ、レシピ、サインイン、ライブラリー、リファレンスも削除する。`--yes` は最初の質問を省く。`--dry-run` は削除するものを伝えるだけ |
| `kumi --version`（または `-v`）、`kumi --help`（または `-h`、`help`） | バージョン、ヘルプ |

## Kumi の中のコマンド

`/` を入力するとこれらのメニューが出ます：↑↓ で選び、Tab で補完、Enter で実行、Esc で閉じます。コマンドとスペースを入力すると、メニューはそのコマンドが取る言葉を出します：`/palette use` ならパレット、`/resume` なら保存された会話、`/slots listening` ならそのスロットに使えるモデル、`/model` なら使えるモデル、`/export` なら形式。Tab で選んだものを入れます。Enter は名前を入力したものだけを実行するので、途中まで入力した言葉はまず入力欄に入ります。パスで始まるメッセージ（ターミナルにドラッグしたファイル）は、コマンドではなくメッセージとして扱われます。

| コマンド | 内容 |
| --- | --- |
| `/new [name]` | 新しい会話を始める（名前を付けられる）。それまでの表示は線で区切られて画面に残り、前の会話は保存され、HISTORY の undo も引き続き使える |
| `/btw <question>` | 横からちょっと尋ねる。Kumi の作業中でもいつでも使える。それまでの会話をもとに、ツールを使わずにパネルで答え、会話には加えない。`/btw` だけなら最後の答えをもう一度表示する |
| `/resume [ID または名前]` | 保存された会話：この Set のもの、Tab ですべての Set のもの。一つ選ぶとその続きから再開する。ID（または先頭部分）か名前を付けるとその会話。`/conversations` も同じ |
| `/rename [name]` | この会話に名前を付ける。名前なしなら今の名前が入力欄に入り、変えられる |
| `/fork [name]` | この会話のコピーに新しい ID で続ける。元の会話は残る |
| `/export [copy \| md \| html \| json]` | この会話をファイルに：Markdown としてコピー、または Markdown、Web ページ、Kumi 用ファイル（`kumi import`）として保存。省くと選べます。64 KB を超えるとコピーの代わりにファイルに保存 |
| `/share` | この会話をどこでも開ける Web ページとして保存し（何も変わっていなければ同じページ）、Done を選ぶまで、開く、Finder（エクスプローラー）で表示する、パスをコピーする。SSH 経由ではページの場所を伝えます |
| `/reconnect` | 新しいブリッジで Live に接続し直す。会話はそのまま（それ以前の変更は Kumi の undo を失う） |

## 即時フレーズ

メッセージが次のフレーズのどれかなら、モデルを呼ばずにその場で Live を変えます。回答には何が変わったかと「instant」が表示され、変更は HISTORY に入り、元に戻せます。今は英語だけです。

| フレーズ | すること |
| --- | --- |
| `tempo 124`、`bpm 124`、`124 bpm` | テンポを設定する |
| `mute drums`、`unmute drums` | トラックをミュートする／ミュートを解除する |
| `solo bass`、`unsolo bass` | トラックをソロにする／ソロを解除する |
| `arm vocals`、`disarm vocals` | トラックを録音待機にする／解除する |
| `loop 9-16`、`loop bars 9 to 16`、`loop off` | 9〜16 小節（両端を含む）をループする、またはループを切る |
| `metronome on`、`metronome off` | メトロノームをオン／オフにする |

- トラックは名前（大文字小文字は問わない）、入力した文字で始まる名前のトラックが一つだけならそのトラック、または位置（`mute track 3`）で指定します。
- それ以上のこと（"mute the drums a bit"、"solo the bass?"）や、Kumi がどのトラックか確かでないものは、書いたとおりモデルに送られます。
- 実行されるのは Kumi が回答していないときだけです。回答中の Enter は、これまでどおり回答への指示になります。
- **REAPER では：** テンポマーカーや拍子マーカーのあるプロジェクトでは、`tempo` と `loop` はモデルに送られます（テンポがどのマーカーのことか、1 小節の長さがどれだけかは場所によるためです）。`loop 9-16` はリピートもオンにします。
- **Renoise では：** `loop 9-16` は、その小節を含むシーケンスのスロットをループします。パターンの途中で始まる、または終わる小節はモデルに送られます。`arm` は断られます。Renoise は、エディットモードがオンのときに選択中のトラックのパターンへ録音するためです。テンポは 32〜999 BPM です。
- `~/.kumi/settings.json` の `"instantPhrases": false` で無効になります。

## キー

**入力と送信**

| キー | 動作 |
| --- | --- |
| Enter | 送信。Kumi の作業中は、進行中のステップの後にメッセージを読む。`@` で何かを指したメッセージは、答えが終わるまで待つ |
| Tab（Kumi の作業中） | 答えが終わった後に送る。メッセージは入力欄の上で待つ |
| Alt-↑ | 最後の待機中のメッセージを入力欄に戻す |
| Ctrl-J, Alt-Enter, Shift-Enter | 改行（Shift-Enter は、それを報告するターミナルで） |
| ↑ と ↓ | 入力欄の行を移動し、その先は以前に送ったものをたどる（`/new` や再起動をまたいで保持。秘密情報は除く） |
| Ctrl-A / Ctrl-E, Home / End | 行の先頭 / 末尾 |
| Alt-← / Alt-→, Ctrl-← / Ctrl-→, Alt-B / Alt-F | 一単語左 / 右 |
| Ctrl-W, Alt-Backspace, Ctrl-Backspace | カーソルの前の単語を切り取る |
| Ctrl-K / Ctrl-U | 行の末尾 / 先頭まで切り取る |
| Ctrl-Y | 最後に切り取ったものを戻す（Ctrl-W を 2 回など、続けて切り取った分はまとめて戻る）。直後の Alt-Y で、その前に切り取ったものと入れ替える |
| Ctrl-- (Ctrl-_) | 入力欄で元に戻す。続けて入力・削除した分、貼り付け、切り取り、話した内容をそれぞれ 1 回で戻す。Ctrl-- でターミナルが縮小表示になる環境（Windows Terminal、GNOME Terminal、Konsole）では Ctrl-_（Ctrl-Shift--）を使う |
| Ctrl-R | 送ったメッセージを、入力した言葉で遡って探す。もう一度 Ctrl-R でさらに前のもの、Enter で入力欄に入れ、Esc で下書きに戻る |
| Ctrl-G | 下書きを、VISUAL か EDITOR で指定した自分のエディタで開く（ウインドウで開くエディタは閉じるまで待つ指定が要る：`code --wait`）。保存した内容が入力欄に戻り、Ctrl-- で元に戻せる |
| Ctrl-S | 下書きを添付ファイルごと脇に置く。入力欄が空のときの Ctrl-S で戻す（入力欄に文字があれば入れ替わる） |
| Ctrl-T | 入力の代わりに話す：もう一度押すと止まり、押したまま話すこともできる。話した内容はカーソル位置に入る。Enter で止めてすぐ送り、Esc で破棄する |
| Ctrl-V | クリップボードの画像（スクリーンショットなど）を次のメッセージに添える。ウインドウにドラッグしたファイルも同じように添えられる |
| `@` | トラック、デバイス、インストゥルメント、自分のサウンド・パレット・テクニックを正確に指す。`@` の後に打つと候補が出て、Tab か Enter で選んだものが入る（`@Drums`）。Kumi にはまさにそれが伝わる。Backspace でまるごと消え、↑ と Ctrl-G では言葉として戻るので、もう一度指し直す |
| 長い貼り付け | 10 行または 1,000 文字を超える貼り付けは `[pasted 41 lines]` のような 1 つのチップになる。Backspace でまるごと消え、Kumi には全文が届き、会話にはチップと最初の行の冒頭が出る。Kumi の作業中に待たせたメッセージ、Alt-↑ で戻したもの、停止後に戻ったもの、↑ や Ctrl-R で呼び戻したものもチップのまま。1 つのメッセージは 256 KB まで：それより長いと入力欄の下にそう出て、Enter を押しても欄に残る。履歴ファイルには長いメッセージの最初の 4,096 文字が `…` 付きで残る。Kumi の起動後に送ったものは ↑ で全文が戻る |
| 空の入力欄で Backspace | 最後に添えたファイルを取り消す |
| 空の入力欄で `?` | `/help` と同じく、キーとコマンドを開く。ほかの場所では `?` が入力される。メッセージを `?` で始めるには、先にスペースを入力するか、貼り付ける |

**停止と移動**

| キー | 動作 |
| --- | --- |
| Esc | `/` か `@` のメニューを閉じる。メニューがなければ Kumi の答えを止める（終わったステップは残り、待機中のメッセージは入力欄に戻る）。それもなければ、ピン留めしたデバイスを外す |
| Esc Esc | Kumi が何もしていないとき、空の入力欄で（ピン留めがなければ）：あなたの依頼を新しい順に、それぞれの変更の数とともに表示します。一つ選ぶと、`/takeback` と同じように、その依頼とその後の依頼をすべて取り消せます（その前に、Kumi が元に戻せない変更を示します。それらはそのまま残ります）。または、その依頼の前からコピーで続けることもでき、DAW と元の会話はそのまま残ります |
| Ctrl-C | Kumi の答えを止める。Kumi が何もしていないときは入力欄を空にし（↑ か Ctrl-- で文字が戻る）、入力欄が空なら終了する |
| Ctrl-B | 答えの中の、Live を使わない時間のかかるステップ（ビデオ、ページ、マニュアル、ライブラリー）をジョブとしてバックグラウンドに移す。答えはそのまま続く。tmux では Ctrl-B を 2 回押す |
| Ctrl-D | Kumi が何もしておらず入力欄が空のときに終了する |
| Page Up / Page Down、マウスホイール | 会話をスクロールする（タブの上ではホイールでタブをスクロール）。新しいテキストが届いても位置はそのまま。上にスクロールしている間は、読んでいる回答のリクエストが一番上の行に残り（クリックでそこへ戻る）、一番下の行に下に届いた件数が出る |
| Ctrl-Home / Ctrl-End | 会話の先頭へ / 最新に戻る |
| Ctrl-O | 会話の詳細：各リクエスト、各ステップに渡したものと返ってきたもの（完全なエクスポートと同じ内容で、ステップは 12 行まで）、各回答（この Kumi の実行中に返したものは、回答したモデル、開始時刻、コストも）、進行中のターン。その中では `/` で検索（Enter で検索を残し、Esc で取り消す）、`n` と `N` で一致箇所を移動、`{` と `}` でリクエストからリクエストへ移動、`[` でキーを押すまでターミナルのスクロールバックに出力、`v` でエディタ（`VISUAL` または `EDITOR`）で開き、`q`、Esc、Ctrl-O で閉じる |
| Ctrl-L | 画面を再描画する |

**Live のペイン**

| キー | 動作 |
| --- | --- |
| Ctrl-\\ | 100 列未満ではドロワーを開閉する。全幅では右のペインをしまう（会話がウィンドウ全体を使い、入力欄の下の行に戻し方が表示される）か、元に戻す。24 行未満では 2 行の帯について同じ |
| Tab（Kumi が何もしていないとき） | FOCUS のデバイスツリーに、Live の選択位置から入る：↑↓ で移動、Enter でその行を指し示す、Esc か Tab で入力に戻る |
| Shift-Tab | タブに入る（もう一度押すと次のタブ）：↑↓ と Page Up/Down で移動。変更の行では Enter、→、Space でその図を開き、Enter か ← で閉じる。図を開いている間は `u` で取り消す。保存したものの行では Enter で forget。JOBS の行では Enter でジョブを開き、`x` で止める。Esc か Tab で戻る |
| マウス | 行末の **undo** や **forget**、変更の文字（図が開く）やジョブの文字（ジョブが開く）、タブの名前をクリックする。ツリーのデバイスをクリックすると、それを指し示す。ピンをクリックするとピン留めを外す。テキストをドラッグすると、離したときにコピーされる。ダブルクリックで単語、トリプルクリックで行をコピーする（Kumi が折り返した行はひと続きでコピーされる）。ドラッグ中は表示が止まり、ヒントの場所に「Copied」がしばらく出る。その間の Ctrl-C は Kumi を止めたり終了したりせず、もう一度コピーする。Kumi が何もしていないときの Esc は、その一行を消すだけ。settings.json に `"copyOnSelect": false` を書くと、選択はそのまま残り、Ctrl-C または右クリックでコピー、Esc で選択を解除する。Shift を押しながらドラッグするとターミナル自身の選択を使う（iTerm2 では Option）。Kumi のコピーがクリップボードに届かないとき（SSH 越しでターミナルが許可していないときなど）に使う |

**パネル**（`/model`、`/effort`、`/login`、`/memory` など）：↑↓ で移動、Enter で選択、Esc で閉じます。`/model`、`/memory`、`/resume`、`/recipes` では、入力すると一覧を絞り込めます。`/model` では ctrl+f でフォールバックを設定します。`/resume` では Tab で This Set と All Sets を切り替え、ctrl+f で選んだ会話の名前の変更、ピン留め、削除、ID のコピーができます。会話が別の Set のものなら、Kumi は尋ねます：その Set を Live で開く（おすすめ）、ここでコピーとして続ける、キャンセル（Esc）。**Your answer**（番号付きの選択肢で質問して終わる答え）：番号を押して Enter で答えます。Kumi のおすすめの選択肢には印が付き、最初から選ばれています。誰もいないとき（`/goal`、`/loop`、マッチングの実行中だったとき、または Kumi のウィンドウが 2 分間ほかのウィンドウの後ろにあったとき）は、カウントダウンの後に Kumi がその選択肢を選びます（「Taking 2 (recommended) in 60 s · any key cancels」）。キーの入力欄ではキーを貼り付けて Enter を押します。Kumi はプロバイダーでキーを確認し、プロバイダーに接続できないときは確認せずに保存します。ChatGPT のサインインパネルでは `c` でリンク（またはコード）をコピーし、`d` でブラウザの代わりにコードでサインインし、`b` でブラウザに戻ります。`/btw` パネルでは ↑↓、Page Up/Down、マウスホイールでスクロール、←→ で以前の答えをたどり、`c` でコピー、Esc、Enter、Space で閉じます。ジョブの詳細では ↑↓ とホイールでスクロール、`x` で止め、`r` でもう一度実行し、`c` でレポートをコピー、Esc で閉じます。ヘルプでは ↑↓、Page Up/Down、Home、End、ホイールでスクロールし、Esc、Enter、`?` で閉じます。文字を入力したり貼り付けたりしても閉じ、入力した内容は入力欄に入ります。`"mouse": "off"` のときは、ホイールではどれもスクロールしません。

**自分のキー。** `~/.kumi/keys.json` で、Kumi のアクションに別のキーを割り当てられます（`KUMI_KEYS_FILE` でファイルの場所を変えられます）。

```json
{ "composer.undo": ["ctrl+z"], "app.background": ["ctrl+b", "f5"], "pane.toggle": [] }
```

- アクションごとのリストが、そのアクションのキーに置き換わります。空のリストではキーがなくなります。キーは `ctrl`、`alt`（または `option`）、`shift` と名前で書きます：`enter`、`tab`、`esc`、`backspace`、`delete`、`insert`、`up` または `↑`（ほかの矢印も同じ）、`home`、`end`、`pageup`、`pagedown`、`space`、`f1`〜`f12`、または一文字（`ctrl+-`、`ctrl++`）。スペースで区切った二つのキー（`esc esc`）は、続けて押します。最初のキーは、入力欄でほかに何も受け取らないときだけ組の始まりになり、二つ目は半秒以内に押します。組が使えるのは入力欄だけです。
- 同じキーを複数のアクションが使うときは、keys.json のものが先に、次に Kumi 自身のものが、これまでの順に試されます。
- 文字を入力する場所（入力欄、一覧、`/` と `@` のメニュー）では、一文字をキーにはできません。入力中の検索やフィルター（会話の詳細、地図）だけのアクションにもできません。そこでは文字として入力されます。空の入力欄での `?` はいつもヘルプを開き、`app.help` にキーを加えることもできます（`f1`）。

- ヘルプ（`/help`、`?`）、入力欄の下、パネル、地図、セットアップのヒント、Kumi のお知らせは、keys.json のとおりのキーを示します。

## プレーンモード

`KUMI_UI=plain`、またはパイプを通した入力や出力では、代わりに一行ずつのプレーンなインターフェースになり、スクリーンリーダーやログに向いています。フルスクリーンのアプリのコマンドがテキストで使え、`/help` がこのセッションで使えるものを一覧にします。

- `/btw <question>` は横から答え、`/goal` と `/loop` はフルスクリーンのアプリと同じように動きます。
- `/jobs`、`/slots`、`/music` は一覧を表示します。音楽を変えるのはフルスクリーンのアプリで行います。
- `/model [provider/model]`、`/effort [level|default]`、`/logout <provider>` は、フルスクリーンのアプリではパネルを開きますが、ここでは言葉で指定します。
- `/export [md|html|json]` と `/share` はどちらもファイルを保存し、場所を伝えます。
- `/pin <id>`、`/unpin <id>`、`/forget <id>` で `/memory` のメモを残したり忘れさせたりします。
- `/voice`、`/map`、`/palette`、`/copy`、`/recipe`、`/takeback` はフルスクリーンのアプリだけにあり、プレーンモードではそう伝えます。
- `/resume` はこの Set の会話、次にほかの Set の会話に番号を付けます。別の Set の会話についての Kumi の質問には 1、2、3 で答えます（答えを待つ間もコマンドは使え、ほかの言葉にはもう一度質問します）。
- バックグラウンドジョブが始まったときと終わったときは知らせ、あなたの依頼に必要なジョブは Kumi が何もしていないときに続きを進めます。
- サインインはシェルから `kumi login` で行います。Ctrl-C は答えを止め、Kumi が何もしていないときは終了します。

## Kumi から離れているとき

- **ターミナルのステータス：** Kumi は OSC 7501 でしていることを伝えます（NOW の言葉と実行の進み具合を添えた作業中、選択やサインインの待ち、完了、失敗）。対応しているターミナルはタブやサイドバーに表示します。Windows Terminal、ConEmu、Ghostty には OSC 9;4 の進捗も送ります。どちらも Kumi の終了時に消えます。
- **Kumi のウィンドウがほかのウィンドウの後ろにある間**、Kumi は 15 秒以上かかった答えを終えたとき、選択やサインインが必要なとき、プランの上限を待つとき、エラーで止まったとき、`/goal`、`/loop`、マッチングの実行が終わったときに知らせます：
  - デスクトップ通知：ターミナル自身の通知（Ghostty、WezTerm、foot は OSC 777、iTerm2 は OSC 9、kitty は OSC 99）、それ以外は macOS の通知（Terminal.app など）、Linux では `notify-send`、Windows Terminal ではベル（タスクバーが点滅します）。
  - Live（または Renoise）のステータスバーに一行（「Kumi · done · the bass is darker」）。ダイアログは出さず、HISTORY にも入れません。REAPER には Kumi が書き込めるステータスバーがありません。
  - 10 秒に一度まで（待っている最新のものがそのときに届きます）。Live が録音している間は録音が止まるまで届けず、あなたが戻ってきたら何も届けません。
  - 前面にあるかどうかを伝えないターミナルでは、Mac で、知らせることがあるときだけ、どのアプリが前面にあるかを Kumi がシステムに尋ねます。
  - 通知が表示されないときは、システム設定 › 通知で、使っているターミナル（macOS 自身の通知ならスクリプトエディタ）の通知を許可してください。
- **コンピューターはスリープしません**：Kumi が作業している間（答え、`/goal`、プランの上限待ち）。ディスプレイはスリープしてもかまいません。
- **設定**（`~/.kumi/settings.json`）：`"notifications": "off"`、`"liveStatusBar": false`、`"keepAwake": false`、`"answerAfter"`（Kumi がおすすめの答えを選ぶまでの秒数。`0` は選ばない）、`"theme"`（既定の `system` はターミナルの背景に合わせて明るい配色か暗い配色になり、配色の変化を知らせるターミナルではそれに合わせて切り替わる。`dark` は Kumi 本来の配色、`light` は明るいターミナル向け、`colorblind` は赤緑の色覚の違いでも見分けやすい色）、`"fullRepaint": true`（何かが変わるたびに、Kumi がウィンドウのすべてのセルを書き直す。変わった部分だけの描画が乱れるターミナル向け。Windows Terminal では既定でオンで、`false` でオフになる）。

## ターミナル

Kumi はターミナルが表示できる色数を検出します。`KUMI_COLOR`（`truecolor`、`256`、`16`、`none`）で上書きでき、`NO_COLOR` にも従います。ターミナルの記号が表示されないおそれのある環境（古い Windows コンソール、Linux コンソール）では、Kumi はアイコンの代わりに 2 文字のバッジを使います。`KUMI_ICONS=glyphs` または `badges` で選べます。変更の図は、kitty と Ghostty（24 ビットカラーで、tmux の外）では画像で、それ以外では点字とハーフブロックで、記号が表示されないおそれのある環境では文字で表示されます。`KUMI_PICTURES=cells` で文字セルに固定できます。Kumi は起動時にターミナルの種類を問い合わせます（その答えで、SSH 越しでも画像、通知、リンクが使えます）。`KUMI_PROBE=off` で問い合わせません。Windows では Windows Terminal をおすすめします。Kumi の答えの中の Web とメールのリンクは、iTerm2、Ghostty、WezTerm、kitty、Windows Terminal、VS Code のターミナル（tmux の外）ではクリックで開けます（Cmd か Ctrl を押しながらのターミナルもあります）。そこでは、文字が別のアドレスに見える場合を除いて、アドレスが文字の後に続きません。それ以外のターミナルでは続きます。ドラッグでは文字だけがコピーされます。`/copy` と `/export` はアドレスも残します。kitty キーボードプロトコルに対応していないターミナルでは、改行に Ctrl-J か Alt-Enter を使います。tmux の中では、`set -g allow-passthrough on` で Kumi のステータスと通知が通り、フォーカスの報告には `set -g focus-events on` が必要です。SSH 越しでは、`set -g set-clipboard on` で Kumi のコピーがクリップボードに届きます。対応しているターミナルは、押していた Ctrl-T を離したことを伝えます。それ以外では、キーのリピートが止まったところで Kumi は聴くのをやめます。

終了するときは、お別れの前に会話をターミナルのスクロールバックに出力します。あなたの依頼、Kumi の答え、ひと続きのステップごとに一行で、秘密は `/export` と同じように取り除きます（長い会話は最後の 200 KB）。settings.json の `"transcriptOnQuit": false` でこれを止められます。`"mouse": "off"` にすると、マウスはターミナル（または tmux）に任されます。ターミナル自身の選択とコピーが使え、Page Up と Page Down でスクロールし、その間ホイールが ↑ や ↓ を送ることはありません。Kumi のクリック、ドラッグでのコピー、地図でのマウス操作はそのあいだ使えません。

## 設計メモ

アプリを開発する人向けです（`crates/kumi/src/tui/`）。

**原則。** Kumi はウィンドウ全体を受け持ち、すべてのセルを自分で描くので、ペインはそれぞれ独立にスクロールし、位置がずれません。枠線は使わず、領域は背景の濃淡で分けます。色には必ず意味があります。記号より言葉を優先し、ステップはツール名ではなく音楽の言葉として読めるようにします（"looked at Bass and Drums"）。動きは、何かが起きている、または変わっていることを示すためだけに使います。ペインはビューです：ランタイムが描くものをデータとして記述するので、別のフロントエンドでも同じものを描けます。

**パレット**（`style.rs`）。グレーは `#0e0f12`（地）から `#f4f6f8`（最も明るい色）まで、アクセントは一つでミント `#86e3b5`、そして Live 自身のトラックカラー（とても暗いものは表示用に明るくします）。警告 `#e7b45f`、エラー `#ee8479`、拍のライト `#ffe14d`。Kumi が保存するものは種類ごとに色があります：メモ `#8cc8ff`、テクニック `#c7a6ff`、レシピ `#f2a6c4`、教訓 `#e7c88f`。回答のコードは、フェンスが示す言語（JavaScript と TypeScript、gen~、Lua、Python、REAPER の EEL）で色分けします：キーワード `#7aa2f7`、文字列 `#b8d47e`、数値 `#e48ee0`、コメントは淡い色、残りはコードの帯の上の明るい色です。三つのテーマで描きます（`theme`）：dark は上のとおり。light は明るいターミナルのために作った配色で、温かみのある白 `#f7f7f4` に暗い文字、アクセントは深いミント `#14764e`、警告は琥珀色 `#925b0d`、淡すぎて読めないトラックカラーは濃くし、コードの色も濃くします（キーワード `#3a4fb8`、文字列 `#4a6a10`、数値 `#9c2f9a`）。colorblind は dark の色を赤緑の色覚の違いでも見分けやすい色にしたもので、アクセントはスカイブルー `#56b4e9`、警告はオレンジ `#e69f00`、エラーは朱色 `#d7650b`、コードの数値はピンク `#f0a8d8` です。どのテーマでも色の意味は変わらず、文字は 4.5:1 以上のコントラストで読めます。`system` では、Kumi は起動するときにターミナルが知らせる背景から明るい配色か暗い配色を選び、配色が暗く、または明るく変わったら知らせるようターミナルに頼みます（モード 2031 に対応したターミナルが知らせます）。

**基盤**。UI フレームワークを使わず、ターミナルの基本機能から組み立てています：

1. ターミナル I/O（`tty.rs`、`probe.rs`）：raw モード、代替スクリーン、bracketed paste、SGR マウス、フォーカスイベント、使える場合は kitty キーボードプロトコル。終了時、クラッシュ時、シグナル受信時にはターミナルを元に戻します。画面の開始時に、ターミナルの種類と色を一度だけ問い合わせ、待つのは最大 0.25 秒です。その答えで、環境変数にターミナル名が届かない SSH 越しでも、画像、通知、色数を選びます。
2. 入力（`keys.rs`）：修飾キー付きのキー（xterm と CSI u）、貼り付け、マウス、複数回の読み取りに分かれて届くシーケンス、そして短いタイムアウトで判定する単独の Esc。kitty プロトコルでは、押し続けているキーのリピートと、キーを離したことがそれぞれイベントになります。
3. スクリーンとレンダラー（`screen.rs`、`render.rs`）：セルのグリッドです。各フレームを前のフレームと比較し、変わったセルだけを同期更新の中で書き込みます。色は 24 ビットから 256 色、16 色、色なしへと段階的にフォールバックします。
4. テキスト（`width.rs`、`wrap.rs`）：書記素の幅（全角の CJK 文字と絵文字は 2 セル）、折り返し、切り詰め。
5. フレーム（`scheduler.rs`）：再描画はまとめて行い、アニメーションのクロックは何かが動いているときだけ動きます。

`app.rs` がレイアウトを描いて入力を処理し、`editor.rs` が入力欄、`transcript.rs` が会話、`tree.rs` がデバイスツリー、`tabs.rs` がタブを担当します。テストはレンダラーの出力を小さなターミナルインタープリターで再生し、意図したフレームを正確に再現できなければなりません。

**まだできていないこと：** ロケーターと新しいトラックを NOW で図にすること。ルーティングのファンイン図やサイドチェイン図。とても長いクリップの概観の帯。多くのトラックにまたがる変更を、展開できる一つの HISTORY 項目にすること。ある変更に依存する変更の取り消しを提案すること。項目に "undone in Live" と印を付けること。macOS のアクセシビリティ機能を通した FOCUS（正確なコントロール、クリップのタブ、Browser の項目）。
