# Ableton Live の安全性

[English](../en/LIVE_SAFETY.md) · [简体中文](../zh-CN/LIVE_SAFETY.md) · 日本語

ブリッジが Live の Set を読み取り、変更するときに保証すること、保証しないことをまとめます。ブリッジとは、`crates/ableton-mcp-server` にある MCP サーバーと、Live の中で動くその Remote Script のことです。ブリッジを操作するのは Kumi ですが、どの MCP クライアントからも操作できます（[ユーザーガイド](USER_GUIDE.md)）。大事な Set にクライアントを向ける前に、このページを読んでください。

## 信頼の境界

- `--config` がないと、ブリッジは利用不可アダプター（unavailable adapter）を使い、Live を読み取ることも変更することもありません。クライアントが何を送っても、別のアダプターを選ぶことはできません。
- 設定があるとき、ブリッジはループバック（`127.0.0.1` または `::1`）経由でだけ Live に接続し、すべてのリクエストに 32 文字以上のオーナー専用シークレットで署名します。ブリッジはあなたのユーザーアカウントを信頼します。あなたとして動くプログラムはそのシークレットを読んで Live を操作できますが、ネットワーク上のほかのものにはできません。
- クライアントが見て呼び出せるツールは、デプロイメントポリシーが決めます。ポリシーは `read-only`、`edit-no-audio`、`performance`、`full`（デフォルト）のいずれかで、`ABLETON_MCP_TOOL_ALLOW` と `ABLETON_MCP_TOOL_DENY` で絞り込めます。ブリッジは適用、取り消し、緊急停止を含むすべての呼び出しでこれを確認します。`live_run_python` を含むのは `full` だけで、`ABLETON_MCP_TOOL_DENY=live_run_python` でオフにできます。プロファイルについては[ユーザーガイド](USER_GUIDE.md)を参照してください。
- Kumi はブリッジを `full` で起動し、Kumi が使うツールだけをちょうど並べた許可リストを渡します。プレビューと適用を実行し、その確認を手元に持っておくのは Kumi 自身のコードで、モデルは変更を名前で頼みます。モデルは Live の中で Python を実行することもできます（[Live 内の Python](#live-内の-python) を参照）。

## 変更が Live に届くまで

ほとんどの変更は、プレビューしてから適用します。

1. `*_preview` ツールは最新の状態を読み取り、リクエストを確認し、何が変わるかを示すトランザクションを返します。何も変更せず、10 分で期限が切れます。
2. `*_apply` ツールは、トランザクション ID、その確認（ほとんどのツールでは文字どおりの `apply`。シーンのオーディション、クリップの起動、オーディオキャプチャでは予測できないトークン）、冪等キーを受け取ります。
3. ブリッジは変更を 1 つのリクエストとして Remote Script に送ります。Remote Script は Live のメインスレッドで、変更が持っているフェンス（変更が名指すものの同一性と、その置き場所。デバイスならそのトラックと兄弟デバイス、クリップならそのスロットとシーン）を確認してから適用し、結果を冪等キーのもとに記録します。そのあとブリッジが結果を読み戻します。

`live_change` はプレビューと適用を 1 回の呼び出しで行います。ただし、プレビューを見てから決める変更ではそうしません。オーディション、クリップの起動、キャプチャ、録音、リアルタイムのアーム、Live のダイアログがそれにあたります。

ミキサー、チェーン、ルーティング、クリップ、シーン、トラック、ソングの設定、チューニング、ビュー、名前の変更、パラメータとデバイスの編集、Simpler のサンプル、Browser からのロード、データ、削除では、プレビューが変更の依存するもののダイジェストも取得します。ダイジェストに含まれるのは、変更が名指す行、ソングのトランスポートの状態、そしてパラメータ、ミキサー、名前の変更以外では Set のトラックとシーンの構造です。適用はこのダイジェストを持っていき、どれかが違っていれば Remote Script は「Live state changed since the preview」で拒否します。ダイジェストが対象とするのはトランザクションの最初のステップだけで、有効なのは 10 分間です。再生中のものに依存する変更（トランスポート、起動、キャプチャ、録音）はダイジェストを持ちません。プレビューと適用のあいだにも再生が進むからです。

変更の終わり方：

- **拒否され、何も変わらなかった。** 「nothing changed」で終わる拒否は、Live で何かが実行される前に行われたものです。理由に書かれていることを直して、もう一度プレビューしてください。
- **適用された。** 同じ冪等キーで再試行すると、もう一度適用するのではなく、記録された結果を返します。Remote Script は動いているあいだこの結果を保持し、明示的に再接続すると消えます。
- **不確定。** タイムアウト、応答の喪失、読み戻しの失敗があると、変更は不確定のままになります。新しいプレビューや新しいキーで再試行しないでください。同じ Live セッションがつながっているあいだに同じ適用を同じキーで再試行すれば、何が起きたかが返ってきます。または Live を確認して手で復旧します（[復旧](RECOVERY.md)）。同じキーでの再試行が拒否された場合、わかるのはその再試行が実行されなかったことだけなので、変更は不確定のままです。

参照は 1 つの Live セッション（エポック）に属します。Live が再起動したりブリッジが再接続したりすると、それまでの参照、トランザクション、取り消しは使えなくなります。

すべての変更が従うそのほかのルール：

- **値はパラメータに合わせる。** パラメータの範囲を超えた値は近いほうの端に、段階のあるパラメータで段と段のあいだの値はいちばん近い段になります。オフになっているデバイスのノブや、Live がオートメーションしないパラメータも設定できます。拒否されるのは、Live がグレーアウトしているパラメータだけです。リアルタイムのプレーンはもっと厳格です（[リアルタイム制御](REALTIME_CONTROL.md)を参照）。
- **名前は重複してよい。** トラックやシーンは同じ名前を持てます。変更はオブジェクトを名前ではなく同一性で見つけます。
- **読み取りは短く。** ディスカバリーのページやスナップショットのウィンドウは、Live のスレッドで約 30 ms 作業すると止まり、残りのためのカーソルを返します。そのため、Set がどれだけ大きくても、Live の画面をふさぐ読み取りはありません。

## 取り消し

- `live_undo` は、同じ Live セッションの中で、適用済みのトランザクションを 1 つ取り消します。
- 取り消しは中身ではなくオブジェクトについていきます。変更で作られたトラック、シーン、リターン、複製、デバイス、クリップは、そのあと名前が変わったり、クリップやデバイスが入ったりしていても削除されます。パラメータ、フェーダー、テンポは、そのあとどう動いていても変更前の値に戻ります。参照が今は別のオブジェクトを指しているとき、またはオブジェクトがなくなっているときは、取り消しは拒否されます。
- 例外が 2 つあり、こちらは中身についていきます。`live_midi_clip_apply` で作られた Session の MIDI クリップは、名前、長さ、ノートが変更直後のままのときだけ削除されます。Kumi の Live 拡張機能を通じて書き込まれたアレンジメントの MIDI クリップは、ノート、名前、範囲のどれかが変わると残ります。消すべきなら、そのクリップは自分で削除してください。
- Live に触れる前に確認で拒否された取り消しは、変更を適用済みのまま残し、次の取り消しがもう一度確認します。
- 削除と一瞬で終わる操作（[トランザクションモデルの外側](#トランザクションモデルの外側)にあるもの、ラック、Looper、一部のビューの操作）にはトランザクションの取り消しがなく、`live_undo` はそう伝えます。削除は Live 自身の Cmd-Z で取り消せます。削除ツール（`live_clip_delete_*`、`live_scene_delete_*`、`live_track_delete_*`、`live_locator_delete_*`、`live_device_delete_*`）は、オブジェクトとその置き場所を同一性でフェンスするので、代わりに別のものを削除することはありません。
- MIDI クリップ、バッチ、デバイス状態のトランザクションは、それぞれ最大 512 件の記録を保持します。それを超えると、いちばん古い適用済みのものから取り消しができなくなります。

プランは Live 自身の取り消しで 1 ステップにできます。`live_undo_step_begin` でステップを開き、`live_undo_step_end` で閉じると、そのあいだに Remote Script が変えたものすべてが Cmd-Z 一回で戻ります。開いたステップは Remote Script のもので、それを開いた接続が閉じたとき、時間切れのとき、再接続時、終了時に閉じます。開いているあいだに Live で自分で行った編集は、それだけで別のステップになります。Live 拡張機能を通じた変更はこのステップにまとめられません。`live_song_undo` と `live_song_redo` は Live 自身の取り消しとやり直しを押すもので、Live で行ったことのためのものです。トランザクションの取り消しではありません。

## トランザクションモデルの外側

これらのツールにはトランザクションの取り消しがありません。許可する前に、それぞれが何をするかを把握してください。

| ツール | すること | 確認されること、終わり方 |
| --- | --- | --- |
| `live_run_python` | Live の中で Python を実行する（下記） | 事前の確認はなし。Live の取り消し 1 ステップ |
| `live_transport_action_preview/apply` | 開始、続きから再生、選択範囲の再生、スクラブ、タップテンポ、ナッジ、ジャンプ、Session 録音のトリガーなど | Set とその再生状態でフェンス。`trigger-session-record` は、下記の録音の確認なしに Session 録音を始めます。 |
| `live_scene_fire_preview/apply` | Live で選択中のシーンを起動するのと同じように、シーンを 1 つ起動する | シーン、シーンのリスト、トリガー済みかどうか、トランスポートが再生中かどうかでフェンス。空のシーンは拒否 |
| `live_fire_button_preview/apply` | クリップ、スロット、シーンの起動ボタンを押す、または離す | 離すまで、接続が閉じるまで、または 30 秒間押したまま |
| `live_browser_preview` | Browser のアイテムのプレビューを再生する | その `previewId` を渡した `live_browser_preview_stop` で止まる |
| `live_message` | Live のステータスバーまたはダイアログにメッセージを表示する | Set の中は何も変えない |
| `live_song_undo`、`live_song_redo` | Live 自身の取り消しとやり直し | Live の履歴にあるもの次第 |

### Live 内の Python

`live_run_python` は、型付きのツールでカバーされないことのために、Live のメインスレッドで Python を実行します。スクリプトの実行中、Live は待ちます。

- 引数：`code`（最大 64 KiB）、`mode`（デフォルトの `exec` はコードが `result` に代入したものを返し、`eval` は式の値を返します）、`timeoutMs`（1–30,000、デフォルト 5,000）、省略可能な `ref`。
- コードから使える名前：`Live`、`song`、`app`、`obj`（`ref` が指すオブジェクト）、`bridge`（Remote Script のオブジェクトマッパー。内部もすべて含みます）。
- 戻り値は `{ok, result, stdout, error}` です。結果の中の Live オブジェクトは `{ref, type, name}` として返り、その ref はほかのツールでも使えます。エラーにはその型、メッセージ、トレースバックが付きます。
- 実行はそれぞれ Live の取り消し 1 ステップ（「Kumi: Python」）になるか、すでに開いているステップに加わるので、Live の Cmd-Z で取り消せます。
- プレビュー、ダイジェスト、冪等キー、トランザクションの取り消し、HISTORY の項目はありません。タイムアウトや応答の喪失のあとは、スクリプトが何をしたかわかりません。Set を読み直してください。
- タイムアウトは Python のコードを中断します。Live への時間のかかる呼び出しは、それが戻ったときにだけ確認されます。
- スクリプトは、再生、録音、削除を含め、Live の Python API でできることは何でもできます。クライアントに持たせるべきでないときは、デプロイメントポリシーでこのツールを拒否してください。

Kumi はこれを `run_python` としてモデルに提供し、実行のたびに Live への参照をすべて忘れます。

## 音が出る操作と録音

トランスポートの操作、シーンの起動、起動ボタンは上の表にあります。出力の安全性の証拠（`outputSafety`）は、シーンのオーディションを除くすべてのツールで省略できます。クライアントが渡さないときは、ブリッジが自分で用意します。ブリッジにはスピーカーの音が聞こえないので、モニターの音量は安全なレベルにしておいてください。

| 操作 | ツール | 実行前に確認されること | 止め方 |
| --- | --- | --- | --- |
| クリップの起動 | `live_clip_launch_preview/apply` | プレビュー時のトラック、シーン、スロット、クリップの同一性。Live でスロットを押したときと同じように、再生中や録音中のものがあっても起動します。 | `live_clip_launch_stop` がクリップのトラックを止めます。ただし、そのクリップがトラックで唯一の再生対象であるあいだだけ |
| シーンのオーディション | `live_session_audition_preview/apply/stop` | Set の正確な名前。トランスポートが止まっていて、録音中・再生中のものがなく、アームされたトラックや入力をモニターしているトラックがなく、起動クオンタイズが None でないこと。呼び出し側の出力の安全性の証拠。Live のスレッドで Set、シーン、再生のリビジョン、すべての対象をもう一度確認します。 | `live_session_audition_stop`。自分の対象だけを止めます |
| 録音 | `live_recording_preview/apply` | アームされた録音先トラック（`destinationTrackRef`）と、一緒に録音する最大 1,024 のアームされたトラック（`alsoTrackRefs`）。ほかのトラックがアームされていてもかまいません。Live はアームされたすべてのトラックに録音します。Session と Arrangement の録音状態と録音先の同一性は、Live のスレッドでもう一度確認されます。 | アクション `stop` でプレビューして適用する、または緊急停止 |
| オーディオキャプチャ | `live_audio_capture_*` | [オーディオインテリジェンス](AUDIO_INTELLIGENCE.md#live-からのキャプチャ)を参照 | Live 内の 10 秒のウォッチドッグと、専用の緊急停止 |
| リアルタイム | `live_realtime_*` | [リアルタイム制御](REALTIME_CONTROL.md)を参照 | `live_realtime_disarm` |

`live_session_emergency_stop` は、Session のクリップ、トランスポート、Session Record、Arrangement Record を一度に止めます。アクティブな対象と録音モード（`stopped`、`session`、`arrangement`、`both`）を最新の再生のディスカバリーから受け取り、それ以降に Live の状態が変わっていれば拒否します。どのトランザクションにも属さないので、ホストが再起動したあとでも使えます。

読み取り専用のツールが再生や録音を始めることはありません。

## Live に渡すファイル

ツールがオーディオファイルを読み込むとき（オーディオのインポート、プロジェクトのインポート、Simpler、ドラムパッド、サンプルのロード）、ブリッジは検証したファイルを読み取り専用で管理フォルダーにコピーし、Live にはそのコピーだけを渡します。管理フォルダーは、macOS と Linux では `~/.config/ableton-mcp/import-staging`、Windows では `%APPDATA%\ableton-mcp\import-staging`、または `ABLETON_MCP_IMPORT_STAGING_DIR` で指定した絶対パスです。フォルダーはオーナー専用です。確認とロードのあいだにファイルをすり替えることはできません。

Live はインポートしたオーディオをその場所から再生するので、適用が成功したあとは、Set のファイルを集約するかクリップを削除するまで、このコピーがクリップや Simpler のサンプルになります。ブリッジがコピーを削除するのは、それを何も使っていないとき（適用の失敗や拒否、期限切れまたは確定済みのトランザクション、クリップがなくなったあとの取り消し）だけで、成功時や終了時には削除しません。古いコピーは、それを使うクリップがなくなってから手で削除してください。

## ブリッジと Remote Script

Remote Script へのリクエストはすべて HMAC で署名され、1 つの Remote Script セッションと 1 つの接続に結び付けられ、厳密に増えていくシーケンスと期限を持ちます。ソケットを読むのは Live のメインスレッドで、表示のティックごとに少しずつ、すべてのリクエストを自分で実行するので、別のスレッドから Live に触れるものはありません。Windows では、オーナー専用とは、あなた 1 人だけのエントリを持つアクセスリストのことです。インストール時に頼めば、Remote Script は小さな診断ファイルを書き出せます。詳しくは `remote-script/README.md` にあります：[Remote Script の README](../../remote-script/README.md)。

## 実際の Live で確認したこと

テスト、シミュレーター、fake-Live マッパーが確認するのはブリッジの契約であって、Live の動作ではありません。実際の Live での証拠は `docs/evidence` にあり、各ファイルに日付、Live のバージョン、ブリッジのバージョンが記され、[実装状況](IMPLEMENTATION_STATUS.md)に一覧があります。最新の実行は macOS 上の Live 12.4.15 ベータです。2026 年 7 月のフェーズファイル（Live 12.4.5b8、ブリッジ 0.1.0）は現在のブリッジより前のものです。Windows の Live での実行は記録されていません。

Live の表示とブリッジの報告が食い違うときは、クライアントを止め、証拠を残し、何かが再生中なら緊急停止を使い、バグとして扱ってください。
