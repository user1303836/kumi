# Logic Pro ブリッジ契約（M2、M3、Loop Range プレビュー）

M2 の読み取りメソッドは `ping`、`status`、`focus`、`read`、`snapshot`、`focus_body` の六つです。M3 は `change_preview`、`change_apply`、`change_restore`、`transport_play`、`transport_stop`、`cursor_set`、`undo_step_begin`、`undo_step_end` を追加します。

16種類の変更（トラックの音量・パン・ミュート・ソロ・アーム・名前・追加・削除、マーカーの追加・移動・削除、テンポ、ノートの追加・変更・削除、プラグインのバイパス）と再生・停止・再生位置に対応します。Logic に一括の取り消しブロックはなく、音量・パン・ミュート・ソロ・アーム・テンポ・バイパスは Logic 自身の取り消しに入りません。Kumi の取り消しは値を新しい書き込みで戻し、後から同じ値を変えた場合は拒否します。追加・削除したトラックと削除したマーカー、および元の情報が不完全なマーカー変更は、Logic の取り消し履歴から手動で取り消します。聴く機能、ゴール、スクリプト、一般的な UI 操作、前回からの差分は無効です。

ノートの読み取りは対象リージョンだけを選択した状態で行い、選択を変えません。`status.permission` は未許可時に `accessibility`、通常時は `null`。`busy` は `false` または `modal`・`away`・`loading` です。サンプルレートは最大 64 KiB の通常 XML ファイル `Alternatives/000/MetaData.plist` のみから非同期に読み、シンボリックリンク、バイナリー形式、不明な値は `null` になります。通常起動では MIDI ポートを作らず、明示的な `--mcu` は Logic にコントロールサーフェス設定を残す可能性があります。

完全な表と JSON フィールドは[英語の契約](../en/LOGIC_CONTRACT.md)を参照してください。`accept_logic` の自動変更チェックには、使い捨てプロジェクトを開いた上で `--changes --scratch-confirmed` が必要です。追加したテスト用トラックは、取り消し履歴からの手動操作用に残ります。ほかの取り消しに失敗した場合も編集が残る可能性があります。過去の M2・M3 ラボ記録は、この移植版の新しい実機確認ではありません。

追加したトラック・削除したトラック・削除したマーカーは Kumi では自動的に戻せません。Logic の UI ではオートメーションや閉じたプラグインの状態などを完全には確認できず、取り消しタイトルだけでは変更を特定できません。Logic 自身の「取り消し履歴」で適切なステップを確認し、手動で取り消してください。マーカーの追加・移動も、元の Text 列など必要な情報が見えなかった場合は手動取り消しになります。後から列を表示しても元の値は分かりません。完全な元の行とリストを確認できた場合だけ、値による取り消しが可能です。discard でも不明な情報を無視しません。確認済みの手動対象は HISTORY に Kept として残り、既定の /undo は古い変更へ飛ばず説明を返し、RPC を送りません。不確かな書き込みは不確かなままです。

M4 の最初のプレビューでは、M3 の16種類に loop_range だけを追加します。startBeats と endBeats は四分音符単位で、1拍960ティックに正確に合う値だけを使い、サイクルを有効にします。Custom LCD と完全な Signature List をあらかじめ表示し、単一の N/4（N は1〜16）・/16分割、停止中かつ非録音である必要があります。0,0 はロケーターを保持して無効にします。変更前のオン・オフ、両ロケーター、単一拍子と時間基準を新しく完全に読み、フェンスで確認します。拍子が不明・複数の場合、値や時間基準が変わった場合は書き込みや復元を拒否し、discard でも無視しません。サイクルは Logic 自身の取り消しに入りません。完全な確認済みの値だけを新しい書き込みで戻し、元の証拠がない変更は HISTORY に手動操作の案内を残します。ほかの M4 変更とプロジェクト保存は無効です。これは過去の 6f8f6e9bbc3666159ce68be1ce7466aa30e82670 の Loop Range だけの移植で、新しい実機検証結果ではありません。
