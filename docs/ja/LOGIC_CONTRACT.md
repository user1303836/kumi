# Logic Pro ブリッジ契約（M2、M3）

M2 の読み取りメソッドは `ping`、`status`、`focus`、`read`、`snapshot`、`focus_body` の六つです。M3 は `change_preview`、`change_apply`、`change_restore`、`transport_play`、`transport_stop`、`cursor_set`、`undo_step_begin`、`undo_step_end` を追加します。

16種類の変更（トラックの音量・パン・ミュート・ソロ・アーム・名前・追加・削除、マーカーの追加・移動・削除、テンポ、ノートの追加・変更・削除、プラグインのバイパス）と再生・停止・再生位置に対応します。Logic に一括の取り消しブロックはなく、音量・パン・ミュート・ソロ・アーム・テンポ・バイパスは Logic 自身の取り消しに入りません。Kumi の取り消しは値を新しい書き込みで戻し、後から同じ値を変えた場合は拒否します。削除したトラックとマーカーは、Logic 自身の取り消しを手動で使います。聴く機能、ゴール、スクリプト、一般的な UI 操作、前回からの差分は無効です。

ノートの読み取りは対象リージョンだけを選択した状態で行い、選択を変えません。`status.permission` は未許可時に `accessibility`、通常時は `null`。`busy` は `false` または `modal`・`away`・`loading` です。サンプルレートは最大 64 KiB の通常 XML ファイル `Alternatives/000/MetaData.plist` のみから非同期に読み、シンボリックリンク、バイナリー形式、不明な値は `null` になります。通常起動では MIDI ポートを作らず、明示的な `--mcu` は Logic にコントロールサーフェス設定を残す可能性があります。

完全な表と JSON フィールドは[英語の契約](../en/LOGIC_CONTRACT.md)を参照してください。`accept_logic` の自動変更チェックには、使い捨てプロジェクトを開いた上で `--changes --scratch-confirmed` が必要です。取り消しに失敗すると編集が残る場合があります。過去の M2・M3 ラボ記録は、この移植版の新しい実機確認ではありません。

削除したトラックとマーカーは Kumi では自動復元しません。取り消しのタイトルだけでは Kumi の変更を特定できないため、Logic 自身の取り消しを手動で使います。確認済みの削除は HISTORY に手動取り消しの制限付きで残り、`/undo` は RPC を送りません。不確かな削除は不確かなままです。マーカー・ノート・構造の変更を、タイトルだけから取り消し済みとは判定しません。
