## 版本

[更新日志](../../CHANGELOG.md)中的每个版本都写明了随附的桥接；[桥接版本](KUMI_CHANGES.md#桥接版本)列出了全部桥接版本。版本号本身记在各 crate 的 `Cargo.toml` 文件（Kumi、桥接）、根目录的 `package.json`（Kumi）和 `apps/live-extension/manifest.json`（扩展）中；REAPER 扩展的版本号在 `crates/reaper-kumi/Cargo.toml` 中，Renoise 工具的版本号在 `daws/renoise/com.kumi.Bridge.xrnx/payload/version.lua` 及其 `manifest.xml` 中。哪个 Kumi 附带哪个版本，见[连接 REAPER 或 Renoise](KUMI_GUIDE.md#连接-reaper-或-renoise)。

## 在哪里测试过什么

以下真实 Live 记录来自较早的 TypeScript 发布版本。原生版的 CI 和迁移测试不能替代新的真实 Live 验收。

- **每个拉取请求：** 原生 Rust 构建和测试、Remote Script 和 Live 扩展的测试、六个目标平台的发行包，以及安装和迁移测试；见 [CI](TESTING.md#ci)。
- **macOS 上的真实 Live**（Apple 芯片，Live 12.4.15 beta）：Kumi 做出的每一类修改，且每一项都通过 Kumi 撤销（在桥接 1.0.62 和 1.0.63 上 65 项全部通过，分别在 19 条和 200 条轨道的工程中），播放、并轨（bounce）、聆听和观看，通过 Kumi 扩展进行的离线渲染和右键菜单，以及 Willington 编辑。
- **Windows 上的真实 Live**（Windows 10，Live 12.4.15 beta，Kumi 1.6.0 配合桥接 1.0.71）：把桥接安装到移动过的 User Library、Remote Script 加载，以及 Kumi 连接。这部分目前还没有记录文件。
- **macOS 上的 REAPER 和 Renoise**（REAPER 7.82 评估版、便携版；Renoise 3.5.4；2026 年 10 月 20 日）：每项修改通过 Kumi 应用、通过 Kumi 撤销，再用 DAW 自己的撤销和重做，大型工程（REAPER 200 条轨道和 2,000 个对象，Renoise 64 条轨道和 100 个模式），以及聆听。
  - REAPER（提交 `c80eb1e7`）：当时 141 类中 140 类通过，一项已知限制。`drum_kit`、`scratch_keep` 和 `metronome_switch` 是之后加入的，未运行。
  - Renoise（提交 `78faa00f`）：132 个用例中 121 个通过，11 项已知限制。`instrument_kit` 和 `scratch_keep` 是之后加入的，未运行。
  - 这些限制列在[已知限制](KUMI_CHANGES.md#已知限制)中。这些目前还没有记录文件。Windows 和 Linux 上的 REAPER 与 Renoise 尚未测试。
- **macOS 上的真实 Logic Pro**（Apple 芯片，Logic Pro 12.3.1）：考察 macOS 能让 Kumi 用哪些途径读取和修改 Logic 的实验，每个通道一个可行或不可行的结论（M0）；以及运行在 Logic 旁边的桥接通过它的辅助功能辅助程序接入 Logic，并应答 `ping` 和 `status`，由 `kumi --daw logic bridge` 安装，能被 doctor 找到，并由 Kumi 的主机从会话中启动（M1）。M2，观察：桥接对真实 Logic 的读取记录在 `crates/daw-mcp-server/tests/vectors/logic-reads.json` 中（各行、各引用、焦点以及 FOCUS 的各项内容），主机重放这些记录，运行时读取它们，重新打开一段保存的对话所属的工程，并判断 Logic 是否正在录音；`crates/kumi/examples/accept_logic.rs` 则是为关口（gate）在真实 Logic 上进行的、需要主动运行的验收。M3，修改与撤销：桥接在真实的 Logic 上做出十六类修改（轨道头的推子、声像、静音、独奏和录音准备，Inspector（检查器）中的名称，在所选轨道下方添加轨道以及删除轨道，创建、移动和删除标记，速度，以 Event List（事件列表）中的行表示的片段（region）音符，插件的旁通），每项都会回读，并会按名称回报制作人自己做的撤销；Kumi 的修改集正好声明了这些（`logic_changes.rs`），模拟的 Logic 在录下的工程上按它们的格式应答，主机的日志会把桥接未能确认的应用或撤销保持为不确定，且绝不发送第二次，Logic 上的 HISTORY 通过 `undone_in_daw` 跟进 Cmd-Z，验收运行的 M3 检查则是一个计划（推子、重命名、添加并静音一条轨道，每项都通过 Kumi 撤销），以及一次用 Cmd-Z 撤回的重命名。Logic 不为推子、声像、静音、独奏、录音准备、速度或旁通保留撤销步骤，所以这些按数值恢复；删除的轨道只有在那一步仍在最上面时，才能通过 Logic 自己的撤销恢复。这台 Mac 上的 M3 关口记录在 `docs/evidence/logic-m3-gate-2026-10-19.md` 中。M4，第一批：Kumi 的修改集声明了桥接在真实 Logic 上做出的、M3 之外的修改类别，概念相同时沿用 REAPER 的工具名称，措辞则始终用 Logic 的：`key_command`（兜底手段，按命令的英文名称或 ID 指定；Logic 不为其保留撤销步骤的命令没有 HISTORY 行，而且只有 Logic 自己的撤销能撤回一条快捷键命令），Tracks area（轨道区域）中的片段沿所在轨道移动、按整拍调整大小和分割（返回右半部分的引用）、设为循环、重命名和删除，`notes_quantize`，循环区域（cycle）的范围（`loop_range`，不是 Logic 撤销中的一步），Tempo List 和 Signature List（速度列表和拍号列表；`tempo_marker_set`、`tempo_marker_delete`、`signature_set`），一次写入许多音符，方式是 Kumi 写出一个 MIDI 文件，由 Logic 导入到指定轨道下方的一条新轨道上（`midi_import`），以及创建和拼合 Track Stack（轨道堆栈）；还有动作 `save_project`（即主机的 `project_save`：保存，或另存为一个尚不存在的 `.logicx`；没有 HISTORY 行）。移动轨道和给轨道上色会被拒绝，并说明原因：轨道头无法从外部拖动（没有快捷键命令能重排轨道，轨道头除了它的菜单之外不提供任何操作），而 Color palette 的色块对辅助功能来说只是一个个光秃秃的位置，轨道头又不显示颜色，所以颜色永远无法回读。除 `notes_quantize` 之外，模拟的 Logic 在录下的工程上有状态地应答其中每一种，与桥接录下的场景的应答一致（它们的格式、Logic 的 Edit 菜单为每一步给出的标题，以及纪元（epoch）在桥接的纪元变化之处随之变化）；主机的测试和协议的基准文件（golden file）覆盖了它们，运行时的测试把它们记入 HISTORY 再撤出（没有 HISTORY 行的保存、有行和没有行的快捷键命令、通过 Logic 自己的撤销撤回的分割和导入、循环区域、一次速度修改、一次 Logic 应答为不确定的撤销），验收运行也加入了 M4 的检查（`--files <dir>` 指定另存为所放的文件夹；MIDI 导入只要它的片段覆盖了这些音符就算通过，因为 Logic 的 Event List 只列出它屏幕上的那些行）。这台 Mac 上的 M4 关口记录在 `docs/evidence/logic-m4-gate-2026-10-21.md` 中：此前六次运行每次都发现了需要修复的地方，之后所有检查都通过了。M4，第二批：Kumi 的修改集声明了把插件放到通道条上和从中移除（`fx_add`、`fx_delete`），在插件窗口的 Controls View（控制视图）中设置它们的参数（`fx_param`、`fx_params`），用窗口的按钮逐个切换它们的设置（`fx_preset`），从 Library（资源库）载入音色（patch，`patch_load`），发送（`send_add`，对于没有任何东西接收的总线，它会让 Logic 建一条辅助轨（aux）；还有 `send_remove`、`send_volume`），Smart Controls（智能控制；`smart_control_set`），以及通过 Track Automation Event List（轨道自动化事件列表）编辑的自动化（`automation_add`、`automation_change`、`automation_delete`），概念相同时沿用 REAPER 的工具名称；并轨和导出则作为动作（`bounce`、`export_tracks`：主机中同名的工具，写出文件，没有 HISTORY 行，由主机为它们写出的内容加上标题）；读取也新增了插件的参数（`param`）、轨道的 Smart Controls（`smart`）和自动化（`automation`）。Stereo Out（立体声输出）在桥接中是 `<epoch>:output:1`，没有哪个读取会列出它：Kumi 在每次观察中都会指明它（`outputs`），并在纪元变化时保留它的名称，所以它的插件以它为父对象来读取，Gain 也能放到它上面。每次请求中 Logic 的工具就是 REAPER 的那八个（其中包括 `fx_add` 和 `fx_param`；分割和导入是 `make_changes` 中的步骤）。这些修改类别依照桥接的第二批，并已对照其格式和录下的场景检查过（每个场景通过模拟的 Logic 重放时，应答都与 Logic 当时一样，只有导出的长度和制作人自己按 Cmd-Z 恢复的内容例外）。模拟的 Logic 在录下的工程上保存了每个通道条的插件（连同它们在 Controls View 中的行和设置；Channel EQ、Gain 和 Keys 的 Piano 都与场景读到的一样）、发送、音色和 Smart Controls，Stereo Out 的插件和 Logic 建立的辅助轨，以及每条轨道的自动化；它有状态地做出所有这些类别的修改（以及旁通），像桥接一样拒绝 `fx-move` 和 `send-mode`，并把并轨和导出的音频文件写到要求的位置；它也按录下的场景读到的方式为轨道和标记命名（带名称的轨道是先创建、再重命名的；新轨道以它的通道条命名；标记按它在 Marker List（标记列表）中的位置命名，长度为 0 拍）。配置插件的说明文字各 DAW 各有一套：Live 的和以前一样，说要在设备中配置参数；Logic 的则说插件窗口的 Controls View，Kumi 会自己打开它。Logic 的指令带有它的术语和做法（片段、Stereo Out 和 Logic 建立的辅助轨、Track Stack、它自己的撤销不保留哪些步骤、量化作为一个参数、导入自带的轨道、各个列表、作用于所选内容的快捷键命令）。验收运行加入了第二批的检查：在 Stereo Out 上放一个 Gain，设置并回读它的增益；从轨道 1 到一条新总线的发送；载入一个音色；在磁盘上找到第 1 至 5 小节的并轨文件；每项都撤销或移除。这台 Mac 上第二批的关口记录在 `docs/evidence/logic-m4b-gate-2026-10-21.md` 中，所有检查在第二次运行时都通过了。M5，聆听：Kumi 能听到 Logic Pro。主机提供 Logic 的 `hear`（播放一段，同时桥接的辅助程序截取 Logic 在 Stereo Out 之后的输出，剪裁到这一段，存入 Kumi 指定文件夹中的一个 WAV 文件）、`audition`（为每个候选做一遍这样的处理，候选是单独独奏的一条轨道或整个混音）和 `render`（离线并轨一段，为此独奏一条轨道），每项都以按 Logic 播放时的速度计算的这一段长度加上余量为限；音频以文件形式传递，从不以采样值传递。Logic 的集成为共享的集成提供了一个聆听钩子（`OwnDaw::listening`），其中的 `Renderer`（`integrations/logic_listening.rs`）应答各个聆听工具（judge、tune、sound、form、groove、audition、render）以及 listen 工具的 `hear`：单独聆听一条轨道时，为它单独做一遍处理并将它独奏；试听时制作人听到第一个候选，其余候选时 Logic 保持无声；判定的一轮会在这次运行的轨道或 Stereo Out 上把电平拉回（用它上面最后一个开启的 Adaptive Limiter 或 Limiter，没有就用最后一个 Gain，再没有就用 Kumi 加在末尾的 Gain），每次设置都通过 Controls View 进行，作为 HISTORY 中的一项修改，可由 Kumi 的撤销撤回；渲染的说明会指出其中包含 Stereo Out 的插件。Logic 的能力中加入了 `hear` 和 `audition`，它的说法会说明它是如何被聆听的，以及判定的一轮在哪里调整电平。listen 工具和后备集成会说明 Kumi 在一个已连接的 DAW 中做不到什么（“Kumi can't pursue a goal in Logic Pro yet.”），而不再说它没有连接。模拟的 Logic 会合成它播放的声音（每条轨道是一个各自的音，经过它的推子、声像和电平类插件，再经过 Stereo Out 的插件，所以在那里调节的 Gain 能被听到），并按契约的聆听一节的格式（其中的文件名、字段、说明和拒绝）应答这三个方法。验收运行加入了 M5 的检查：聆听第 1 至 5 小节（文件的长度和响度），一轮把增益放在 Stereo Out 上的判定（添加一个 Gain，设置、回读、撤销），试听轨道 1 和 2，在磁盘上找到第 1 至 5 小节的渲染文件，以及结束时工程与之前一样。这台 Mac 上的 M5 关口记录在 `docs/evidence/logic-m5-gate-2026-10-21.md` 中，所有检查在第一次运行时就都通过了。M6，在 Kumi 中用上桥接新的修改类别和读取：修改集声明了 `metronome_set`（control bar（控制条）上的 Metronome Click，不是 Logic 撤销中的一步，所以它那一行会说明由 Kumi 的撤销撤回）和 `sample_load`（把一个音频文件导入到一条音频轨道上，再转换成它下方一条新的 Sampler 轨道；Logic 会把文件复制到工程的包中，在这一步仍在最上面时，Logic 自己的撤销能撤回这次载入，两步都撤回）。在请 Logic 载入之前，Kumi 会先在这台电脑上找到采样的文件，就像它为 Live 找采样文件一样（完整路径，或 `~` 下的路径，指向 Logic 能导入的音频文件），不存在的文件则用它自己的话拒绝。主机会转发 Logic 的批量读取（带 `rows` 和 `limit` 的 `snapshot`）和它的 `recent` 读取；模型的读取会列出 Logic 最近打开过的工程。模拟的 Logic 像桥接的场景那样做出这两类修改，记住节拍声的状态，并应答工程行的 `middleC`、速度行的 Tempo List、最近的工程以及批量读取。Logic 的固定短语（“tempo 124”、“mute drums”、“loop 9-16”、“metronome off”）和 Live 的一样，不调用模型就会执行：每一个都是 Logic 自己的一种修改（以整数 BPM 设置的 `tempo_set`，轨道头的静音、独奏或录音准备，用于循环区域的 `loop_range`，`metronome_set`），通过 `make_changes` 作用于重新查看时读到的工程，轨道按名称指定，或按它在制作人自己的轨道中的位置计数（绝不算辅助轨、输出或 Stereo Out）；每一项都会进入 HISTORY，并带有 Kumi 的撤销。超过 Logic 上限 990 BPM 的速度会交给模型。中央 C 跟随 Logic 的“Display Middle C As”设置，工程行会说明它（`middleC`，3 或 4）：会话按那个八度为音符命名（listen 工具给出的声音音高、`find_sounds` 中的音名词语、FOCUS 中的键区），这个设置取自打开的工程，而不是 Logic 的默认值。配方的保存说明只在有 `watch_me` 的 DAW 中提到它，Logic 的配方步骤示例使用它自己的工具（对之前一个 `fx_add` 插入的插件使用 `fx_param`）。`kumi export` 从对话所在的位置取得 DAW 的说法（Logic 工程的导出会说 Logic Pro 和 project，与会话自己的导出一样），导出、`kumi import` 和预算中列出的制作人请求，都能认出以任一已注册 DAW 的方式包装的循环或目标请求，所以用 REAPER、Renoise 或 Logic Pro 的说法包装的多行请求会算作制作人的，而不会被当作 Kumi 的而略去。Logic 的素材库是它自己的：会话的素材库和 `kumi library` 的素材库会学习 Logic 的内容文件夹（先是 `~/Music/Audio Music Apps` 下制作人自己的，再是 `/Library/Application Support/Logic` 下 Logic 自带的）、Apple Loops、Splice 的文件夹和指定的文件夹，从不学习 Live 的；在那里 `.caf` 算作声音；音色（作为一个整体计入的包）、通道条或插件设置、Sampler 乐器和 Audio Unit 的预设都算作预设（Logic 也提供 `find_presets`，类型为乐器或插件设置）；`.logicx` 包算作工程，按名称计入（Kumi 不读取它的内部：`my_sets` 按文件列出它，没有可供筛选的速度或调，制作人的习惯也仍然只从 Live 的 Set 中学习）；素材库的工具用 Logic 的说法说明这些（`find_sounds` 按引用把一个声音与某个音频片段的声音相比，并提到 `sample_load`）。Logic 的工程会在 `~/Music/Logic`，以及存放它最近打开过的工程的文件夹中查找；这些工程由集成在连接后从桥接的 File > Open Recent 读取，素材库会保存下来，供下次运行使用：桥接只知道当前打开的那一个，以及 Spotlight 在 `~/Music` 之外找到的那些最近工程的位置（macOS 不让桥接访问那个文件夹），所以其他的要等打开之后才会学到。REAPER 和 Renoise 沿用 Live 的布局，并加上它们自己的素材库。在 Logic 上，judge 和 groove 说的是 region 及其引用，Live 上的则说 clip；groove 会提到 Logic 的音符修改，并用 Logic 的说法说明它在那里还读不到片段的音符；关于缺失能力的指引和 `note_gap` 只提 Kumi 自己的工具，因为 Logic 没有 Kumi 能用上的脚本。Logic 中插件参数的修改在 HISTORY 中的绘制方式和 Live 的一样：先立即显示它改动的数值（按 Logic 显示的样子；Logic 设成了别的值时，附上所要求的值），然后对 Channel EQ 和 Compressor 显示修改前后的曲线（Channel EQ 的八个频段；Compressor 的阈值、比率、拐点和增益补偿），曲线取自修改稳定之后对插件 Controls View 的一次读取。这次读取会在 Logic 中短暂打开插件的窗口，就像修改插件时一样。
- **Logic Pro 的手册（M7）：** `logic_manual` 依据 Apple 的 Logic Pro User Guide for Mac 作答，就像 `live_manual` 依据 Live 的手册作答一样，两者共用每本手册都要做的部分（`integrations/shared/manual.rs`：保存的副本过 45 天重新读取、词干和 BM25、段落）。指南的欢迎页（`support.apple.com/guide/logicpro/welcome/mac`）列出了完整的目录，约两千个主题，分为若干部分和章节；每个主题是单独的一页（`…/guide/logicpro/<its title's slug>-<id>/mac`），加上 `?displayMode=headless` 就能不带周围的网站来读取，主题中的任务或小标题由包含其标题的 `div` 的 ID 来定位。读取每个主题需要两千次请求，所以 Kumi 只读一次目录，并在回答第一次需要某个主题时才读取它（标题和位置与问题最匹配的六个），把两者都保存在素材库文件夹中（`logic-pro-guide.json`），并用指南为主题起的标题来引用它（“Logic Pro User Guide, Quantize regions”）。问题首先与主题的标题和位置匹配，所以没有哪个标题用到的词（“sidechain”，指南写作“side chain”）可能会漏掉只在正文中提到它的主题；`topic` 按标题或地址完整读取一个主题。解析器和这个工具在一个按 Apple 网站的结构搭建的合成网站上测试（`crates/kumi-runtime/tests/it/logic_manual.rs`）；指南的结构是开发时从 Apple 的十几个页面中读出来的。
- **Logic Pro 的指令包（M7）：** Logic 的每一轮都带有 Kumi 的人设，以及 Live 的指令包所带的通用规则，并针对 Logic 用它的说法写成（`integrations/logic_instructions.txt`：不先询问就做所要求的事、善于想办法且行动迅速、在修改前后聆听、通过搜索匹配声音、学习固定流程和照着视频做、查资料以及向 Apple 的指南询问 Logic 如何工作、什么不可信以及什么是最新的、引用和分页、以工程为目标），然后是 Logic 自己的说法和做法（M4b），以及它的修改集的指令。Live 自己的做法（Live 中的 Python、调律、重采样、Max for Live 设备、Live 的菜单、它的设备容器和启动器、它的音符记法）都略去了。所有选项都打开时，在模拟的 Logic 上的第一次请求为 56,698 字节（其中系统文本 16,398 字节），Live 的为 73,204 字节（25,945 字节）；加入这个指令包之前为 47,656 字节（7,356 字节）。Logic Pro 不在时，对话中的那一行会说明这一点，并指向 Apple 的指南。
- **Logic Pro 的评测（M7）：** `crates/kumi/examples/eval_logic.rs` 在模拟的 Logic 上向配置的模型提出 23 项请求，每项都是单独的一个会话，带有 Logic 的指令包、修改和聆听，Apple 的指南则从包含其主题的测试夹具中读取（从不联网）：十个考查 Logic 术语和做法的知识问题（片段，Stereo Out，Track Stack，Marker List、Tempo List 和 Signature List，作用于所选内容的快捷键命令，Logic 的撤销不保留哪些步骤，Controls View，量化作为片段的参数，导入自带的轨道，Smart Controls），七个针对 Scratch 的修改请求（推子、重命名、标记、速度修改、Stereo Out 上的 Gain、发送、包含几项修改的计划），五个限制（移动轨道或给轨道上色、发送的模式、移动插件、Quick Sampler）和一次聆听。每项检查都是代码：用 Logic 的说法，不用任何 Live 的说法；问题涉及 Logic 的功能时，询问了指南，并引用它给出的某个主题；问题不会引起任何修改；Logic 应用的修改和 HISTORY 的行；限制被拒绝并说明原因；混音被听过。它的试运行（对预先写好的回答执行每项检查）在 CI 中运行（`crates/kumi/tests/eval_logic_dry.rs`）；它还没有用模型运行过。

## 已知限制

- Live 的 API 无法保存或导出工程、冻结、创建编组轨道或编辑编曲视图中的自动化；见 [Live 的 API 不提供的功能](CAPABILITY_MATRIX.md#live-的-api-不提供的功能)。
- 有些修改无法通过 Kumi 撤销，只能用 Live 自己的撤销；见 [Live 安全](LIVE_SAFETY.md)。
- 在 Windows 上，Kumi 的扩展尚未测试，并且从 1.6.0 或更早版本运行 `kumi update` 可能因 tar 错误而失败；见 [Windows](SUPPORT_MATRIX.md#windows)。
- 到目前为止的真实 Live 测试都在 Live 12.4.15 beta 上进行，主要是在 Apple 芯片的 Mac 上。Live 12.0 至 12.3、Intel Mac 和屏幕阅读器都未经测试。
- Willington 编辑在 `/willington` 开启之前一直关闭，并且需要 Willington 有绑定的 Live 构建版本：macOS ARM64 上的 Live 12.4.15b4 和 b5（机架链区域仅限 b5），以及 Windows x64 上的 Live 12.4.15b5。在 Windows 上，这些绑定已通过 Live 中的 Python 测试，但还没有通过 Kumi 自己的编辑测试；见 [Willington](WILLINGTON_INTEGRATION.md)。
- Kumi 和桥接都没有签名；见[发布与分发](DISTRIBUTION_POLICY.md)。
- Logic Pro 是在 Stereo Out 之后被聆听的（进程音频分接听到的是 Logic 的全部输出）：单独聆听一条轨道靠的是独奏它，所以声音会经过 Stereo Out 的插件，而且除了中性的 Gain 之外，遮蔽不会透过其中任何插件来测；每个候选都是单独的一遍实时处理。Kumi 还不能在 Logic 中让目标的渲染装置保持打开，不能凭耳朵调节插件的旋钮（tune 不读取 Logic 的任何旋钮），也不能跟上运行期间被重命名的轨道；也不能把片段的音频文件当作文件来听，因为 Logic 只显示它的名称（改为在片段所在的小节上聆听它的轨道）。一次聆听会把 Logic 的节拍器关掉再打开（它的节拍声用来为捕获定时），而这是 Logic 随工程保存的设置，所以聆听之后，即使工程里什么都没变，它也会显示为已编辑；Kumi 聆听过之后会说明这一点。
- 对 Logic Pro 的支持不能为标记命名或重命名，因为标记的名称单元格不是文本框；不能移动轨道或给轨道上色，因为轨道头无法从外部拖动，而 Color palette 的色块只是光秃秃的位置，没有哪个轨道头能把颜色回读出来；不能移动插件（Logic 靠拖动来移动它）或设置发送的模式（这是 Logic 自己画出的一个记号，外部任何东西都读不到）；桥接对每一项都会拒绝并说明原因。Kumi 声明了桥接在真实 Logic 上做出的修改类别，包括 M4 两批的和 M6 的。Logic 没有撤销块，也不为推子、声像、静音、独奏、录音准备、速度、旁通或循环区域保留撤销步骤，插件的参数或设置（它们是插件窗口自己撤销中的步骤）、Smart Control、发送电平或节拍器也没有，所以 Kumi 按数值恢复这些；删除的轨道或片段、分割、导入、拼合的 Track Stack 和载入的音色，只有在那一步仍在最上面时，才能通过 Logic 自己的撤销复原（删除的插件连同其设置一起复原，建立的发送连同 Logic 为它建的辅助轨一起撤回），载入的采样也是这样，连同它的 Sampler 轨道和两个片段一起撤回，而文件的副本会留在工程的包中。快捷键命令做的事，只有 Logic 自己的撤销能撤回。采样只能放进 Logic 的 Sampler：Quick Sampler 要把采样拖到它的窗口上才能载入。片段只能在时间上沿所在轨道移动；它的边缘、分割点和导入的位置都落在整拍上，导入会生成一条自己的轨道。速度只接受整数 BPM。保存不保留版本（那是 REAPER 的功能）。Logic Pro 11 和 Intel Mac 不在范围之内。见 [Logic 契约](LOGIC_CONTRACT.md)。
- Logic Pro 不保留任何 Kumi 能放进工程内部的 ID，所以 Kumi 按路径识别 Logic 工程（桥接的 ID 是路径的哈希）：移动过或以其他名称保存的工程，对于追上离开期间的变化和记忆来说都是一个新工程。追上离开期间的变化和 `watch_me` 比较的是 Kumi 通过桥接读取的快照：轨道按名称和顺序匹配（位置和类型不变而被重命名的轨道会报告为已重命名），片段按所在轨道和起点匹配，插件按在通道条上的顺序匹配，标记按位置匹配，无法区分的则说明为不明确。它们还不比较音符或插件设置。如果读取时 Logic 还没有绘制某条轨道的 Mixer（调音台）通道条（在比 Mixer 视图更宽的工程中），这条轨道的插件和路由就不参与比较，而不会报告为已移除。Stereo Out 的插件是工程本身的条目（某个插件被添加、移除、旁通或重新打开），在两个快照都读到它们之后才比较。桥接能一次读取所列类别的所有行时（带 `rows` 的 `snapshot`），快照就是对工程的那一次查看，它的 Mixer 和 List Editors（列表编辑器）各显示一次（按 M6 桥接的测量，在 Scratch 上为 2.7 s，而分页读取为 4.5 s）；较旧的桥接则和以前一样，一次读取一页。对 Logic 的 Project Templates 文件夹中的工程，从不追上离开期间的变化。
